# 新时代 YSM 模型设计（bb_* 工具）

> 用语义工具在后台 Blockbench 里安全地建模/贴图/动画，并用无头渲染自检。
> 本技能的数字来自 **169 个解密后的现代 YSM 工程**（151,155 方块 / 24,800 骨骼）实测，
> 不是经验之谈。详细拆解见 `docs/20`、`docs/21`、`docs/21a/b/c`。

## 0-A. 谁来调用（**强制**）

**主代理不要直接调用任何 `bb_*` 工具。** 一律委派：

```
用户请求 → 主代理判定任务类型 → 用 assets/delegation-brief.md 拉起子智能体
        → 子智能体先 promote（补全任务书）→ 执行 → 回报产物与证据
主代理只做汇总与验收，不碰 bb_*
```

理由：渲染图 200–900 token/张会污染主会话；主会话容易跳过搜图/写 spec 直接改方块；
建模动辄几十次写操作需要独立上下文；事故无法隔离。

例外：只读的 `bb_session_status` 可以主代理做。协议见 `docs/17`。

## 0. 铁律

- **不猜结构**：先 `bb_scene(scope:"summary"/"bones"/"cube")` 看真实层级；不要凭空编 bone 名。
- **小步修改**：一次 `bb_apply_model_patch` 只做一类事；大改前 `bb_checkpoint`。
- **每次可见改动后必须看图**：写操作会自动附 `front + iso_fr` 拼图；不够就 `bb_look`/`bb_orbit`。
- **不要空转**：连续多次 `no_visible_change` 就停下检查或回滚，不要盲目叠加。
- **导出前必校验**：`bb_validate` → `bb_save_project` → `bb_export_ysm`。

## 1. 开工流程（顺序不能反）

### 1.1 官方基准（必做第一步）

`bb_ref_canon({character})` 一次拿三样：**外观文字描述**（已裁到外观相关段落）、
**外文名/罗马音**（booru 只认罗马音）、**官方图对照表**。

这份基准用来校验后面所有候选图。实测教训：一次验收里 15 张候选混进了**另一个角色**，
靠人肉才排除。有基准能一眼剔除。

### 1.2 大面积搜索（搜索很便宜，别省）

`bb_ref_search({character, depth:"deep", romaji:<name_variants>})`

deep 展开 24 条中/日/英查询词 × Bing 三语区 × 3 页分页 + 360 分页 + 萌娘 + yande.re，
实测候选量比 fast 放大一个数量级（96 → 902）。单源失败会在 `sources` 报状态，**不要把失败当成功**。

### 1.3 下载成对照表

`bb_ref_collect()` —— 下载 + 精确/感知去重 + 拼成一张带编号对照表。
**必须真的看**：哪些是同一角色、什么角度、有没有设定集页。对照 canon 剔除错图。
缺背面是常态：**继续做，合理推测，最后明确告诉用户**。

### 1.4 写 spec

`bb_spec_save({spec})` 把结论固化成结构化规格（部件/骨骼/方块预算/用色/参考索引/gaps）。
校验会挡住明显会做砸的方案（方块数、头部占比、贴图尺寸、缺背面却未记 gaps）。
返回**构建计划**：`order` + `bones`（父级与预算）+ `texture.regions`。
换会话用 `bb_spec_load()` 恢复。

### 1.5 开项目

`bb_session_start({mode:"new_ysm", name, resolution:[512,512]})` 新建
（`resolution` 会真正改写贴图尺寸，**不要用默认 128**）；
已有包用 `bb_project_open({pack_dir})`（**相对 `models/<项目名>/`，不是仓库根**）。

## 2. 现代基线（先判定自己在哪一档）

### 2.1 三个时代，差一个数量级

| 时代 | 方块 | 旋转占比 | 薄片(<0.5) | 判定 |
|---|---|---|---|---|
| 女仆模组 | ~92 | **0%** | 0% | 过时 |
| 女仆移植 YSM | 412 | 75% | 少 | **过时** |
| **现代 YSM** | **742**（中位） | **85%** | **26–44%** | 目标 |

**参考分布**：现代 YSM 中位 742 块 / 85% 带旋转 / 26% 薄片。
但这些是**统计结果，不是及格线**——一个 400 块的 Q 版模型也可以做得很好。
真正要避免的是"整体粗糙但某处突然超精细"这种**画风割裂**。

### 2.2 设计方法：从总到分（**本节是全技能最重要的部分**）

**不要先想方块。先想这个角色应该给人什么感觉，再决定怎么拆。**

任何模型都按这四层顺序做，**上一层没定下来不要动下一层**：

```
第 1 层  风格档位   —— 定体素尺度与精细度，全模型贯彻
第 2 层  剪影比例   —— 整体轮廓、头身比、体积分布
第 3 层  部件形态   —— 每个部件长什么样、曲线走向
第 4 层  方块实现   —— 才动手拼方块
```

#### 第 1 层：风格档位

选**一个**档位并全程贯彻，这是"画风统一"的根。实测全语料的方块特征尺度中位 **1.38**：

| 档位 | 体素尺度 | 参考总块数 | 适合 |
|---|---|---|---|
| **粗犷/远看** | 2.0+ | 100–400 | Q 版、小比例，靠剪影取胜 |
| **标准** | 1.3–1.6 | 400–900 | 主流，近距离看也不散 |
| **精细** | 1.0–1.2 | 900–2500 | 特写/展示用 |
| **分层精细** | 混合（特例） | 2500+ | 表演级：身体大块 + 面部/特效微雕，**层次分明才成立** |

**关键判断**：一旦定了尺度，**所有部件都按这个尺度出块**。
不要在 1.4 单位的画风里塞 0.2 单位的瞳孔——那会让局部突然"换了个画风"。
反过来，要做"分层精细"档，就得**每一层都自洽**（身体用大块、面部件用小块、特效再更小），
而不是只有眼睛细、其他地方粗。

#### 第 2 层：剪影与比例

- **先画剪影**：这个角色远看是什么形状？肩宽/腰线/裙摆展开度/头发轮廓
- 比例参考（语料中位）：头身比 **4.87**（原画通常是 6.5–7，模型故意做大头）、
  腰/胯 0.657、胯/胸 1.361（**梨形**）
- **剪影决定成败**：把模型拉到拇指大小看，还认得出角色吗？认不出就说明剪影没做好

#### 第 3 层：部件形态

对每个部件先回答：**这块是什么形状？曲面往哪走？**

- 脸：圆脸/鹅蛋/尖下巴？颧骨突不突？
- 头发：发流从哪开始、往哪落？外轮廓是蓬松还是贴头？
- 身体：胸腰胯的起伏关系
- 服装：垂坠感、展开度、层数

**这一步只在纸上/心里决定形态，不碰方块。**

#### 第 4 层：方块实现

形态定了，再问"**这个形态用几个方块、多大、怎么摆**能表达出来"。
同样是"圆脸颊"，可以用 3 个斜置大块，也可以用 20 个小块——**取决于档位，不取决于标准**。

#### 一致性自检（做完必看）

- [ ] 把模型缩到很小看剪影，还认得出吗？
- [ ] **全身方块尺度是否协调**？有没有某个部位明显比别处精细或粗糙
- [ ] **眼睛是不是全场最精细的地方**？如果是，要么整体都提升到这个精度，
      要么把眼睛降到和其余部分一致——**这是最容易出错的点**
- [ ] 配色是否落在同一套色板（主色 4–6 个 × 2–3 级明度）
- [ ] 正面/侧面/背面看起来是不是同一个角色

## 3. 部件做法（形态优先）

### 3.1 脸与五官

**先决定这张脸的性格，再决定怎么拼。**
但有一条比性格更优先：**脸的"大小"和"形状"是设计出来的，不是头骨决定的。**

#### 3.1.1 头别做大，脸别露太多（最容易翻车的两点）

实测 93 个模型：

| 指标 | 中位 | 做得最精致的那些 |
|---|---|---|
| **脸被头发遮挡比例** | **41%**（p25 25% / p75 51%） | **62–67%** |
| 头宽 | 7.0（默认骨架尺寸） | 好模型偏 **6.0** |

> 翻车典型：头用默认 7×7×7、头发只盖头顶、脸整块裸露 → 一张又大又平的方脸。
> **正确做法：头宽压到 6.0，再用头发把脸框到只剩 35–60% 可见。**

#### 3.1.2 怎么"框"脸（按顺序做，效果好于雕方块）

1. **刘海下压**：盖住额头到**眉上沿**，分成 8–12 撮错落，中央最低点压到眼上沿附近
2. **侧发内收**：两侧各盖进 **1–1.5 单位**，把脸的方角吃掉，露出的是窄长脸
3. **鬓发贴颊**：耳朵位置各留一撮，进一步收窄
4. 剩下露出的部分（通常 4–5 单位宽 × 3–4 单位高）才是"脸"

#### 3.1.3 脸型修形（想要更精致才做）

三种做法，按投入递增：

| 法 | 做法 | 效果 |
|---|---|---|
| **贴图法**（最省） | 脸贴图画颊部阴影、下巴收暗、鼻影 | 60% 的情况够用 |
| **窄脸板** | 脸板本身做 5.5–6 宽，下巴单独一块窄板斜置 | 轮廓明显变秀气 |
| **劈头法** | 把头切成左右**镜像斜片**（下巴收窄/脸颊外扩），镜像配对率要高 | 最精致，`hi3_elysia`、`changchun`、`bronya` 都用 |

#### 3.1.4 五官

- **眼睛**：精细度**必须服从整体档位**。标准档给 4 层、每层 1–2 单位深；
  精细档才做瞳孔/高光分层。**眼睛不该成为全场唯一的超精细点**
- **不要把眼睛做成微雕**：0.2 厚的瞳孔放在 1.4 尺度的模型里就是画风割裂
- **眉毛比眼睛略凸**，用来压住眼神
- **鼻子基本不做几何**（168 个模型里 0 个建鼻），交给贴图
- **嘴**：纯贴图，或 0.1 厚的一小组几何；不要微雕

#### 3.1.5 两种脸型路线（都成立）

| 做法 | 特征 | 代表 |
|---|---|---|
| **单块脸 + 贴图 + 靠头发框** | 脸是 6–7 宽的方块，五官大部分画在贴图上，靠刘海/侧发收形 | 多数模型 |
| **分面雕脸** | 把整个头切成镜像斜片，做出下巴收窄/脸颊外扩的弧面 | `hi3_elysia`、`changchun`、`bronya` |

### 3.2 头发

**先定发流（从哪出发、往哪落、怎么分束），再定每束怎么切。**

- **发片是最基础的单位**：语料里厚度高度集中在 **1.00**——这是最稳的"发片厚度"
- 但是否用 1.00 取决于档位：标准档用 1.0–1.5，精细档可到 0.5
- **发束按段挂骨骼**（`Hair1 → Hair2 → Hair3`），末段收尖
- **刘海**：决定脸部露出多少。中央那撮的最低点通常压在**眼睛上沿**附近
- **分缝**：98% 的模型没有几何分缝，中分/侧分画在贴图上
- **发饰单独成骨并挂在发束上**，这样会跟着甩
- 头发通常是第二大件，占比与"角色辨识度"直接相关——不要省

### 3.3 身体

**先定体态（梨形/比例/姿态），再定每个部位的曲面，最后才是方块。**

- **胸**：不是"必须做几块"，而是"这个体态需要多大起伏"。做的时候用一圈斜置小块
  拼出球冠感，峰值偏下，上缘压低
- **腰**：收腰靠躯干方块**旋转**做出八边形截面，不需要加骨骼分段；
  也可以靠胯宽对比让人"读"出细腰
- **腿**：环切（一圈板绕 Y 排布）比一根方柱自然；大腿→膝收、小腿肚再鼓
- **肩**：平肩即可，A-pose 略外展；斜肩很少做
- **颈**：一般不做，头直接坐躯干上
- **手**：每只 2 块就够；分指只有 5% 的模型做，除非角色特写需要

### 3.4 服装

**先定这块布怎么垂、怎么展，再定用什么拓扑。**

裙子 5 种拓扑（**圆环分层已淘汰，全语料只有 0.35%**）：

| 型 | 做法 | 适合 |
|---|---|---|
| A 平面薄片围合 | 大薄片围成筒 | 挺括的短裙 |
| B 竖条帘幕 | 竖向长条成排 | 长裙/垂坠感 |
| C 微块马赛克 | 小方块堆 | 蓬松/毛绒 |
| D 花瓣羽片环 | 细长羽片环形排 | 花瓣状/多褶 |
| E 单骨大裙 | 全塞一根骨 | 简单/省资源 |

- **荷叶边/褶皱靠相邻块交替角度**，不要单独建 hem/frill 骨
- **同一层深色必须拉开明度**（≥4 级），否则分层糊成一片
- 上衣直接雕进 `UpBody`，胸前可单独一根 `Breast` 骨
- 袖子挂在 `Arm`/`ForeArm`，不需要独立袖根骨
- 披风/飘带靠**薄 + 长链**，不是靠块多

### 3.5 配饰与特效

- 配饰是"角色特点"的高浓度区：把预算花在**能被一眼认出的那几件**上
- 特效层（`ysmGlow` 发光、拖尾、光晕）是"震撼感"来源，但**不能替代本体质量**
- 普通角色特效占比 2% 左右即可；要演出级才堆到 30%+


### 3.6 官方原画对照：强调 vs 省略

**必须强调**：头发体量（占画面 30–40%）、眼睛大小与瞳色、胸腰胯对比、色块对比、腰部配饰群
**降级到贴图**：蕾丝花纹、刺绣、半透明、细绑带、布料褶皱、头发高光
**配色**：主色 **4–6 个** × 每个 **2–3 级明度** + 1 级高光；金/宝石高饱和小块 <5% 面积放视觉焦点

## 4. 贴图

**上色五条**（官方群课程，详见 playbook §7）：
1. **明度**：朝上更亮、朝下更暗；南北较亮、东西较暗
2. **饱和度**：亮部更低、暗部更高；阴影饱和度较低
3. **天光**：阳光亮黄 + 大气蓝 → 亮面偏暖、暗面偏冷、阴影偏冷
4. **AO**：阳角亮、阴角暗
5. **闭塞阴影**：物体根部/缝隙最深，越远越浅

- 尺寸：**512 起步**，精细模型 1024。128 只是模板遗留。
- 有效指标：**texel/块**（中位 99，p90 358）比"贴图尺寸 vs 块数"更能判断贴图够不够
- 纹理色阶：主干部位 **2–3 级明度**；深色叠层 **≥4 级**
- 局部查看 `bb_texture_read({format:"palette"})`；放大核对 `bb_render_texture({scale:12})`
- 涂色 `bb_texture_patch`；整图导入用 `bb_texture_import_png`（先用 PIL 生成设计稿更高效）
- UV：`add_cube` 支持三种写法——省略（自动避让）/ `{mode:"box",offset,size}`（会真正拉伸采样区）/
  `{mode:"faces",faces,sizes}`（逐面精确，做眼/饰必须用这个）
  > `Cube` 上**没有** `uv_size` accessor，box 模式尺寸只能逐面写 `faces[f].uv_size`
- PBR：`bb_texture_pbr` 生成 `_n`/`_s`，需要光影支持

## 5. 自检

**编辑即看**：写操作成功后自动附 `front + iso_fr` 拼图，改完直接看。
更多角度用 `bb_look`（比 `bb_render_views` 省 token）；转台查穿模用 `bb_orbit({steps:8})`；
动画采样用 `bb_anim_check`。

- `review.verdict`：`visible_change` / `visible_change_clipped` / `no_visible_change` /
  `empty_render`。连续 3 次 no-visible-change 触发 no-progress → 先 `bb_restore` 或换策略。
- `edge_touch=true` 说明被裁切，用 `focus` 或调机位。
- 背景透明，不要用"背景色没变"判断失败。
- 规则判定不是 VLM：造型/配色/意图仍要自己看图判断。

**验收清单**（**先看整体，再看细节**）：

整体（这几条最重要）
- [ ] 缩到拇指大小看剪影，还认得出这个角色
- [ ] 正面/侧面/背面看是同一个角色、同一套画风
- [ ] **全身方块尺度协调**，没有某处特别精细或特别粗糙
- [ ] **眼睛不是全场唯一最精细的地方**（如果它是，说明画风割裂）
- [ ] **头没有过大**：头宽压到 6 左右（默认骨架是 7，直接用会显脸大）
- [ ] **脸没有露太多**：头发遮挡 40–65%，可见脸只剩 35–60%
- [ ] **脸型有处理**：刘海压眉 + 侧发贴颊，不是一块裸方板
- [ ] 主色 4–6 个、每个 2–3 级明度，深色分层靠明度拉开
- [ ] 角色特点（发型轮廓/标志性服装/瞳色/配饰）一眼可见

技术
- [ ] `bb_validate` 0 error
- [ ] `bb_orbit` 8 角度无穿模、无漏缝
- [ ] 至少 1 个自定义动画
- [ ] 导出 zip + 渲染图

## 6. 动画

- 列表 `bb_animation_list`；新建 `bb_animation_create({name:"animation.main.xxx", length, loop})`
- 关键帧 `bb_animation_patch({ops:[{op:"set_keyframes", animation, bone, channel:"rotation"|"position"|"scale", keys:[{time,value}]}]})`
- 一个 patch 内多 op 共享一个 Undo，失败整体回滚
- 绑定控制器 `{op:"bind_controller", animation, controller:"player.pre_main", state}`
- 动画文件保存时"合并回写"：未改条目/顺序保留，只替换语义变化的动画

---

## 7. 保存 / 导出 / 回滚

- `bb_checkpoint({label})` 内嵌贴图当前像素；`bb_revisions` 列表；`bb_restore({revision, confirm:true})`
- `bb_save_project` 写回 pack（模型/动画/控制器/贴图/ysm.json）
- `bb_export_ysm` 先 validate，产物含 `export-manifest.json` + zip
- `bb_batch` 不是事务，失败不自动回滚

## 8. 用户接管

用户说"我来看看" → 提示 `/show`；窗口显示期间写操作返回 `GUI_BUSY`；
用户 `/hide` 后返回 `user_edits` 摘要，先 `bb_scene` 对账 revision 再继续。

## 9. YSM 约束速查

- **骨骼数量没有上限**（默认模板 64 骨是模板自身的数，不是限制；语料 77% >64，最高 1257）
- 真正的限制：**骨骼嵌套 ≤32 层**（2.6.3 起解除）、网格子级 ≤64、纹理子级 ≤32
- 贴图 ≤**4096×4096**；默认模板 128，社区主流 256，精细 512–2048
- 必需定位组：`Head`/`Body`/`RightArm`/`LeftArm`/`RightLeg`/`LeftLeg`；
  建议加 `RightHandLocator`/`LeftHandLocator`（放在对应 `Hand` 组**里面**）
- 改完模型/贴图必须保存，否则导出的是磁盘旧版本

## 10. 常见错误（全部实测踩过）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 用 `update_bone` 传 `scale` | 空操作，渲染不变 | Blockbench 不支持骨骼缩放，用 `update_cube` 改几何 |
| 用 `delete` 简写不核对 | 静默失效 | 传 `refs:[{kind,id}]`，并检查返回的 `changed[]` 非空 |
| 按骨骼 bbox 大面积涂色 | 误伤别家 UV 岛 | 先 `bb_scene(scope:"uv")` 看 `unsafe_bboxes` |
| `add_cube` box UV 不给 `size` | 采样恒为 1px/单位，贴图糊 | 给 `size`，或改用 `faces+sizes` |
| `animation.create` 后不保存 | 游戏里没动作 | 确认 `bb_save_project` 写了 animation 文件 |
| 会话已连接时重复 `session_start` | 复用旧项目，改动丢失 | 先 `bb_project_close` |
| 用世界坐标反推语料造型 | 完全错误的结论 | 语料 rotation 不能无条件重放，按尺寸+名字分析 |
| **按右手定则推导方块 Z 轴滚转** | **裙板/披风朝反方向翻，做出"漏斗裙"** | **Blockbench 里 cube 的 Z 滚转旋向与右手公式相反**：要 A 字外扩应写 `rotation:[0,0,-pitch]`。任何"绕枢轴倾斜"的方块必须先在真实渲染里试一次，不能只靠推导 |
| 用 PowerShell `Set-Content -NoNewline` 写生成脚本 | 中文/换行被破坏，脚本写坏 | 用 `write`/`edit` 工具写代码文件 |
