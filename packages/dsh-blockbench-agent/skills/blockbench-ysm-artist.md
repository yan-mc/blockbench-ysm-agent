## 0. 谁执行 + 十条流水线

### 0-A. 强制委派

**主代理不要直接调用任何会改模型/看渲染的 `bb_*` 工具。** 一律：

```
用户请求 → 主代理判定任务类型 → 按 assets/delegation-brief.md 拉子智能体
        → 子智能体 promote（补全任务书、输出计划）→ 执行 → 回报产物与证据
主代理只做任务书、验收（bb_scene / 读产物图）与汇总
```

理由：渲染图会污染主会话 token；主会话容易跳过参考/spec 直接改方块；长任务需要独立上下文；事故可隔离。
例外：只读的 `bb_session_status` 可由主代理直接调用。

### 0-B. 标准流水线（顺序不能反，每步有验收门）

| # | 阶段 | 必做 | 验收门 |
|---|---|---|---|
| 1 | **官方基准** | `bb_ref_canon` 拿外观描述 + 罗马音 + 官方图 | 能一句话说出角色辨识特征 |
| 2 | **深搜对照** | `bb_ref_search(depth:"deep")` → `bb_ref_collect` | **逐格真看**，错角色/错皮肤全部剔除并记录理由 |
| 3 | **立绘拆分** | `bb_seg_probe` → **T3 有 key 优先（三视图/拆解板），否则 T2 有则用、没有则 T1 必做**（见 §2.4） | 有部件清单 + 占比数字，或写明拆分/降级原因 |
| 4 | **写 spec** | `bb_spec_save`（references/palette/parts/budget/gaps） | 预算按档位反推；缺背面必须进 gaps |
| 5 | **开项目** | `bb_session_start(new_ysm, resolution:[512,512])` | 已清空示例模型；rest rotation 已处理；texture_width 真为 512 |
| 6 | **定档位/剪影/比例** | 先算数，再动方块（§3） | 头身比/肩宽/胯宽算式对得上 |
| 7 | **建模** | 按 spec 的 `plan.order`，小步 patch，每次可见改动看图 | `bb_scene` 数字正确 |
| 8 | **贴图** | 先查 `bb_scene(scope:"uv")` 的 `unsafe_bboxes` | 无大面积误伤 |
| 9 | **逐部件自检** | 按 §6 的 8 组清单逐组 `isolate`（**强制**） | 每组有渲染图与判定 |
| 10 | **出厂** | `bb_validate` → `bb_save_project` → `bb_export_ysm` → 成品渲染 | 0 error + 4 视角图 + zip |

## 1. 铁律（每条都真实返工过）

0. **开工前置（不满足就别建模）**：模型**正面朝北、对称轴落在世界轴线**（否则镜像/对称全废）；
   尺寸小数落在 `.25/.5/.75`；避免**混素**（16x 项目 1 格=1px，32x 项目 0.5 格=1px，方块不要小于 1px 对应尺寸）；
   共面/近共面必处理 **inflate**（`+0.01~+0.005` 防 z-fighting，`−0.01` 内收防穿模，**不要用大幅 inflate 当圆角**）。详见 playbook §0/§3。
1. **不要凭记忆/凭文字描述建模**：先看图、先拆图、先写 spec；配色必须从参考图像素确认。
2. **先算再做**：头身比、肩宽/头宽、裙纵深先写算式；算不通就报告冲突，不要硬改到"指标对但造型错"。
3. **块数服从档位，不为指标凑块**：903 块曾被判"画风割裂"，484 块反而成立（v6→v7 教训）。
4. **一个模型只有一套体素尺度**：特征尺度 1.3–1.6 是主流；局部突然精细 = 画风割裂。
5. **`isolate` 是默认检查手段，不是可选项**：v1–v8 没用 isolate，导致"脸只露 1/4、角被头发埋死、手臂被躯干吞"都晚一轮才发现。
6. **任何"绕枢轴倾斜"先在真实渲染里试一次旋向**：Blockbench 方块 Z 轴滚转与右手定则**相反**，A 字外扩写 `rotation[2] = -pitch`（前 6 版漏斗裙的根因）。
7. **写操作必须回读验证**：`delete`/`set_uv`/`animation.create` 都出过"返回 ok 但没生效"；`delete` 要核对 `changed[]` 里的删除条数（简写现在合法，但**结果仍要核对**）。
8. **`update_cube` 改带 rotation 的块必须同时给 `pivot`**：不给会绕旧枢轴，偏移可达 1 单位。
9. **注意坐标空间**：`main.json` 与 `.bbmodel` 的 x 是镜像的；按 uuid 批量改块一律用 `.bbmodel` 坐标，改完逐块校验 mismatch=0。
10. **`closeup` 单独渲染**：与其他视图同批会污染整批取景；需要真特写优先 `isolate`+`zoom`（`focus.padding` 只改对焦点/边缘留白，不改变缩放倍数）。
11. **导出顺序固定**：`bb_validate` → `bb_save_project` → `bb_export_ysm`；不 save 就 export 导出的是磁盘旧版。
12. **写脚本用 `write`/`edit` 工具**：PowerShell `Set-Content -NoNewline` 会毁中文/换行。
13. **美术判断亲自看图**：脚本只做统计；造型/配色/神态必须逐张渲染人工判读，且**每个建模轮至少一次**把官方立绘与当前渲染并排看（否则颜色/比例越修越偏）。
14. **禁止"模板换色"冒充建模**：交付前自查——骨架是否仍是模板？方块是否只是示例模型/旧模型的复制？UV 是否只是重映射？**每个部件都必须能说清"从哪张参考图推出来的"**（v0 的祥子就是模板换色，被用户当场否定）。
15. **眼睛/头发/角不要照抄旧结论**：先按 §2.7 打开 2–5 个参考模型、渲染+读方块，确认当前作品的层序/定位/轴向后才动手；旧版 skill 里"角绕 Z 轴 258°""眼白 2.0×1.36×1.00"等已被 2026-11-08 实测推翻。
16. **参考板必须按原图像素独立裁切、逐张目检**：T3/设定板常把 front/side/back + 头部 + 服装细节排在同一张图；按比例估算会把邻视图/邻部件裁进来（祥子 v5 真实事故：front 混进 side、side 混进 back、back 混进头部细节）。规则见 §2.8。
17. **大曲面用斜置薄板拼，不要用方块堆/只绕 Y 的竖条**：参考工程 85.4% 方块带旋转、裙类 93.3% 带旋转，且大量是 X/Z 倾斜 + 三轴旋转的薄板；只做 Y 轴旋转的"竖片环"仍是圆筒。做法见 §3.6。

## 2. 参考阶段（决定像不像的上限）

### 2.1 官方基准（第一步）

`bb_ref_canon({character})` 一次拿：**外观文字描述**、**外文名/罗马音**、**官方图对照表**。
实测教训：15 张候选里混进过**另一个角色**（把"鹿島神"当成目标），靠"逐格看图+官方基准"才排除。
**若百科只覆盖基础人设、找不到指定皮肤，必须换关键词再搜，并在 spec.gaps 记录。**

### 2.2 深搜

`bb_ref_search({character, depth:"deep", romaji:<name_variants>})`
- deep = 24 条中/日/英查询 × 多语区 × 多页 + 萌娘 + booru；实测候选量 902–1062（fast 仅 96 量级）。
- 单源失败要在 `sources` 里报状态，**不要把失败当成功**；外部图站 403/404 是常态，用萌娘原图/本地兜底。
- 参考图是越多越好：**token 不值钱，看图花的时间是最值的。**

### 2.3 对照表逐格判读

`bb_ref_collect()` 下载 → 精确/感知去重 → 编号对照表。**必须逐格写判读**并写进 `spec.references.images`：

| 字段 | 内容 |
|---|---|
| index | 对照表编号 |
| 角度/类型 | 正面/侧面/背面/坐姿/设定集/同人 |
| 可信度 | 官方立绘 > 设定集 > 动画截图 > 同人 > AI 图 |
| 判读 | 该图贡献了什么（发色/瞳色/服装结构/角形/配饰） |

缺背面是常态：**继续做，按对称推断，最后明确告诉用户**（进 spec.gaps）。

**对照表必须给用户看一遍再继续**（尤其是要喂 T3/T2 之前）：让用户按编号挑出"角度正确、可信"的几张（正面/侧面/背面/细节），再把选中文件喂给分层工具；不要把整批候选原样喂进去，也不要自己替用户决定。

### 2.4 立绘拆分（**强制步骤**：T3 有 key 优先，T2/T1 兜底）

拆分给两样东西：**部件清单**（做逐部件检查的 checklist）+ **2D 面积/占位数字**（校准比例）。
它**不是可跳过项**；确实做不了，必须在报告写"为什么没做 + 缺什么条件"（非 N 卡/无 ComfyUI/无 API key/预算不足），**不许静默省略**。

**分级与优先级（2026-11-08 起）**：

| 级别 | 能力 | 需要 | 什么时候用 |
|---|---|---|---|
| **T3** | **Nano Banana Pro（Gemini 3 Pro Image）云端**：1–14 张多角度参考图 → **严格三视图** / **全景式深度拆解板**（三视图+服装分层+表情+材质+道具+箭头） | **付费 Gemini API key**（`nanoBanana.apiKey` 或 `GEMINI_API_KEY`；约 $0.134/张 2K、$0.24/张 4K） | 有 key 且官方立绘带动作/背景/遮挡复杂、缺背面；**产物是"假设"，必须人工复核** |
| **T2** | See-through 本地：23–29 语义层 + 深度序 + 遮挡补全 | NVIDIA GPU + ComfyUI（本机已装） | 精修档默认；对**可见部分**最可靠 |
| **T1** | SAM2 本地轻量分割：部件掩膜 + 面积/bbox | CPU + 59MB | 标准档必做；快速清单/比例校准 |
| **T0** | 零依赖：模型直接看立绘 | — | 草稿/应急 |

**分档规则**：
- 粗犷/草稿档：T0 可接受，但报告要写"启用 T0 的原因"；
- **标准/正式档：T1 必做**（成本仅 5–15 秒 + 59MB 模型，性价比最高）；若 T3 已配置，建议先 `bb_seg_t3(mode:"turnaround")` 拿一张干净三视图（可选）；
- **精修/分层精细档：T1 必做 + T2 已装必做 + 有 T3 则先跑 T3 出"三视图/拆解假设"**（用户原话：有 T2 用 T2，没有 T2 用 T1；T3 有 key 优先）。

**先探测**：`bb_seg_probe()` → 看 T3/T2/T1/T0 哪级可用、磁盘/GPU/ComfyUI 状态、`recommendedTier`。
`recommendedTier` 已按 **T3 > T2 > T1 > T0** 排序：T3 没配置 key 时自动落到 T2；T3 只检查配置，不发请求、不耗额度。

**T3（Nano Banana Pro，云端）——复杂立绘/缺背面时用（需要付费 API key）**
1. **先筛选参考图**：`bb_ref_search` → `bb_ref_collect` 得到带编号对照表；**必须把对照表给用户看**，让用户按编号挑选"角度正确/可信"的几张（正面/侧面/背面/细节各取所需），再把选中路径传给 `bb_seg_t3.references`（或放进一个目录用 `reference_dir`）；不要自己替用户决定。
2. 先 `bb_seg_t3({mode:"turnaround", references:[...], dry_run:true})`：看提示词与成本，不花钱（dry_run 不需要 key）；
3. 去掉 dry_run 真跑：`mode:"turnaround"` 出**严格正/侧/背三视图 + 头部/上半身/下半身/手/脚单独图 + 服装单品拆解**（建模主用）；`mode:"breakdown"` 出**全展开部件拆解板**（把每件服装/配饰平铺分开，只拆参考图里存在的部件）；`mode:"custom"` 定向修改；
4. 参考图建议 4–6 张同角色多角度；`image_size:"2K"` 性价比最好，4K 只给需要放大看纹理的拆解板；
5. **所有生成结果都是推断**：逐张复核身份/左右镜像/配色/纹样/背面自洽性；推定项写进 `spec.gaps`；**不得当官方设定或精确尺寸依据**；
6. 生成图可交给 `bb_seg_run`（T2）继续分层：T3 出假设，T2 出可见证据；
7. 服务商：官方 Gemini 用 `nanoBananaProvider:"official"`；**中国大陆/香港不直连官方时用 APIYI**：`nanoBananaProvider:"apiyi"` + `nanoBananaApiKey`（自动 baseUrl `https://api.apiyi.com/v1beta` + Bearer 鉴权，请求体与官方一致）；其他中转站用 `custom` + `baseUrl/auth/bodyStyle`；价格以服务商账单为准；
8. 无 key / 限流 / 内容拦截 → 返回 `T3_NOT_CONFIGURED`/`T3_QUOTA`/`T3_NO_IMAGE`，**降级 T2** 并在报告写原因。

**T2（See-through，完整分层）——精修/需要遮挡补全/需要头部拆分时用**
1. `bb_seg_install({confirm:true})`：装 ComfyUI（~7GB，可后台作业）；
2. 按返回的 `startCommand` 起 ComfyUI（8188），等 `/system_stats` 200；
3. `bb_seg_run({file, resolution:832})`：首次下权重约 12.5GB/约 20 分钟，之后约 1–3 分钟；
4. 得到 **body 13 + head 11 原始 24 层 → 实际输出通常 29 个语义层**（层名以返回的 `layers.json` 为准：
   back hair / bottomwear / handwear-l/r / headwear / face / front hair / legwear / footwear / neckwear / topwear / objects 等）+ 深度序 + 遮挡补全；
5. **逐层与模型对照**，这就是最可靠的"每个部件像不像"依据，同时用于 spec 的 gaps 检查。
   - 注意：`bb_seg_run` **不产 PSD**（前端按钮/ag-psd 才能生成）；`objects` 层是背景道具，不建模；裁切层图直接看形状，不要拿绝对 bbox 当模型坐标。

**T1（SAM2.1 轻量分割）——默认必做的兜底**
- `bb_seg_lite({file:"<一张全身立绘>", grid:24, max_parts:24})`：首次自动下载 **59MB** 模型 + 装 onnxruntime，CPU 约 12–39 秒/张；
- 返回部件清单（bbox/面积/质心/主色）+ 覆盖图；**看图后**把部件按语义归类（头/发/角/躯干/臂/裙/腿/靴/配饰）；
- 用途：① 校准 2D 比例（如"腿+靴占图高 35%""角占图宽 47%"）；② 生成逐部件检查清单（§6）。

**T1 的已知局限（必须知道，别盲信）**
- 掩膜会重叠（"整个人"和"零件"一起输出）；只给可见区域，**背面/遮挡处无信息**；
- 稠密插画（暗色人物 + 暗色大件道具 + 亮背景）会**把钢琴/沙发/底座当主体**，人物的裙/手套/腿/靴/胸饰 0 个切出（2026-11-07 实测）；
- 因此：**拆分结果不可用时，改人工读裁切图（crop_head/face/body/legs）+ 全图对照，并把"拆分不可用"写进报告**；严禁跳过而不说。

**降级顺序**：**T3（有 key）→ T2 → T1 → 人工裁切判读 → 纯文字描述**（最差，仅当无图时）。
T3 失败/无 key 不丢人，但**必须在报告写"T3 降级原因"**；不许假装跑过 T3。

### 2.5 spec

`bb_spec_save({spec})` 固化：`character` / `references.images` / `palette` / `parts` / `budget` / `gaps` / `notes`。
校验会挡住明显会做砸的方案（方块数、头部占比、贴图尺寸、缺背面未记 gaps）。
**`budget.cubes` 要按档位反推**，不要拍脑袋（实测有轮次计划 370、实交 188）。
拿到 `plan.order` 后按顺序建。换会话用 `bb_spec_load()` 恢复。

### 2.6 开项目（两个必踩的坑）

`bb_session_start({mode:"new_ysm", name, pack_dir:"pack", resolution:[512,512]})`
（`resolution` 会真正改写贴图尺寸；**不要用默认 128**，128 下脸只有 7×7 像素）。
已有包用 `bb_project_open({pack_dir})`（**相对 workspace，即 `models/<项目名>/`**）。

- ⚠️ **`new_ysm` 带出的是完整示例模型**（70 bones / 172 cubes / 303 animations），不是空骨架。
  先 `bb_checkpoint` 落盘 `.bbmodel` → 读 cube UUID → 一次 `delete` 清空（骨骼保留），再开始建。
- ⚠️ **模板骨骼带非零 rest rotation**（Ribbon / FrontSkirt / BackSkirt / Collar / SideSkirt / LeftArm / RightArm / Breast 等）。
  按世界坐标 `add_cube` 会被带偏（出现过"蝴蝶结被甩出体外成浮空黑块"）。先 `bb_scene(scope:"bones")` 读 rotation：
  清零，或直接按局部坐标计算。
- 开完确认 `bb_scene` 的 `textures` 尺寸 = 你传的 resolution；不对就改 `main.json`/`arm.json` 的 `description.texture_width/height` 后重开（旧版 bug）。

### 2.7 参考模型实证判读（眼睛/头发/角必做，2026-11-08 新增）

**为什么**：眼睛/头发/角这三件靠"看统计数字"永远做不对——统计只能告诉你中位数，不能告诉你"这层为什么凸、那个小片遮住了什么"。必须**亲自打开参考模型，把渲染图和方块数据一一对应**。

**做法（主代理自己或子代理执行，约 15–30 分钟/批）**：
1. 从 `material/refmodels/ysm_decoded/<模型>/` 选 3–5 个同风格参考；写最小 YSM 包（`ysm.json` + `models/main.json` + `textures/main.png`），`bb_project_open` 打开；
2. 渲染 **2400² front/iso/back**（`bb_render_views`），再裁头部/眼睛/角（PIL 裁切放大 2–5×）；
3. 读对应骨骼的 cube 数据（origin/size/rotation/相对脸面的 z 深度），**把渲染图上看到的每一层与方块对应**：哪块是眼白、哪块是虹膜、哪块是眼线、哪块凸出多少、哪块凹进去；
4. 多模型互相对照，提炼"层序 + 尺寸 + 深度 + 定位"；写进 `docs/23` 或任务报告；
5. **不要把参考模型渲染图随仓库分发**（第三方版权，放 `models/<项目>/artifacts/refstudy/`，gitignored）。

**判据示例（2026-11-08 实测）**：
- 眼睛：眼白板 2.0–2.2×1.3–1.8×0.30，仅凸 0.02–0.07；上眼线凸 0.3–0.7；现代模板眼中心 ±1.76（内缘间距 20–24% 脸宽）；
- 头发：底发帽 20–80 块小板 + 附属束各自成组，不是 2 块大板；
- 角：参考甘雨 z 跨度 7.7（−4.7~+3.0）→ 绕左右轴 X 的椭圆螺旋，不是正面平面里的 C 形。

## 3. 设计方法：从总到分（本手册最重要的一节）

**不要先想方块。先想这个角色该给人什么感觉，再决定怎么拆。**

```
第 1 层 风格档位 —— 体素尺度，全模型贯彻
第 2 层 剪影比例 —— 整体轮廓、头身比、体积分布
第 3 层 部件形态 —— 每个部件长什么样、曲线往哪走
第 4 层 方块实现 —— 才动手拼方块
```

### 3.1 第 1 层：档位

| 档位 | 特征尺度 | 参考总块数 | 适合 |
|---|---|---|---|
| 粗犷/远看 | 2.0+ | 100–400 | Q 版、小比例，靠剪影取胜 |
| **标准（主流）** | **1.3–1.6** | **400–900** | 主流现代 YSM |
| 精细 | 1.0–1.2 | 900–2500 | 特写/展示 |
| 分层精细 | 混合 | 2500+ | 身体大块 + 面部/特效微雕，每层都要自洽 |

**判据**：缩到拇指大小看剪影；全身方块尺度要协调。
**反例**：1.5 单位档硬堆到 903 块 → 碎条化（v6 被推翻）；同档 484 块成立（v7）。

### 3.2 第 2 层：剪影与比例（先算后改）

**⚠️ "头身比"有三种口径，不能混用**（这是多轮返工的根源）：

| 口径 | 定义 | 语料值 | 用途 |
|---|---|---|---|
| **A 头方块口径** | 总高 / 头骨方块高 | **7.31**（p25 6.54 / p75 9.88） | 建模对齐用；报告里优先用这个 |
| B 视觉头口径 | 总高 / （下巴→发顶，含发/角） | **4.87**（p25 4.49 / p75 5.29） | 只用于"看起来几头身"的审美判断 |
| C 头高占比 | 头方块高 / 总高 | 0.198 | 与 A 等价换算 |

> 实测教训：用 B 当目标去改 A 会陷入"物理不可能"——总高 45 时 4.87 要求头高 9.24，而头压到 6.7 后又变竖长条。
> **做法**：模型报告同时给 A/B 两个数；冲突时优先保"头不竖长条、剪影好看"。

| 指标 | 语料中位 | 好模型区间 | 备注 |
|---|---|---|---|
| 肩宽 / 头宽 | **1.01** | 0.96–1.25 | 做宽立刻显壮；**改它要先缩躯干，再把手臂 pivot 移回体侧**，不要单靠内移手臂 |
| 胯宽 / 头宽 | 骨枢轴比约 **0.70** | — | ⚠️ 这是**枢轴**比，不是剪影比。**剪影上胯应 ≥胸×1.2（靠裙/胯布撑开）**，语料是梨形（86% 模型胯>胸），不要做成肩宽胯窄的倒三角 |
| 躯干长 / 头高 | 1.77 | 1.48–1.95 | 头枢轴→体枢轴 |
| 臂长 / 头高 | 1.49 | 1.06–1.67 | 肩→肘 |
| 腰 / 胯 | 0.657 | — | 梨形 |
| 胯 / 胸 | 1.361 | — | 梨形 |
| **头宽** | 7.0（模板） | 实战推荐 **6.0–6.2**（3 个精细模型 + v8/v9/v11 实测；语料中位仍是 7.0，7 会显脸大） | 按角色需要选择，不要当绝对标准 |
| **脸被头发遮挡** | 41% | **62–67% 好** | 口径 = **脸平面可见面积占比**（头正面投影被头发盖住的比例）；要用 isolate 正视图实测，不要数方块 |
| **眼中心 / 双眼内缘间距** | ±1.76 / 1.43–1.5 | ±1.7–1.8 / 1.4–1.6 | 脸宽 6–7 时；内缘间距 ≈20–24% 脸宽（旧派 ±2.12 / 41% 偏宽）；详见 §4.2 |
| 头发占方块 | 17.5% | 结构与辨识度直接相关 | 第二大件，别省 |

### 3.3 第 3 层：部件形态

对每个部件先回答：**这块是什么形状？曲面往哪走？**

- 脸：圆/鹅蛋/尖下巴？颧骨突不突？
- 头发：发流从哪开始、往哪落？外轮廓蓬松还是贴头？
- 身体：胸腰胯的起伏关系
- 服装：垂坠感、展开度、层数
- **角/兽耳等辨识件**：先定"最外点/最高点在哪"，再拼几何

### 3.4 第 4 层：方块实现

形态定了，再问"**这个形态用几个方块、多大、怎么摆**"。
同一个"圆脸颊"可以用 3 个斜置大块，也可以用 20 个小块——**取决于档位，不取决于标准**。

### 3.5 一致性自检（做完必看）

- [ ] 缩到拇指大小看剪影，还认得出吗？
- [ ] 全身方块尺度是否协调？有没有某处明显比别处精细/粗糙
- [ ] **眼睛是不是全场唯一最精细的地方**？是就说明画风割裂（v6/v7 测试过：眼睛过细与整体不搭）
- [ ] 正/侧/背是不是同一个角色、同一套色板
- [ ] 配色：主色 4–6 个 × 每色 2–3 级明度

### 3.6 曲面：斜置薄板拼面（不是方块堆叠；2026-11-08 新增）

**参考实测（160 个可解析解密工程，138,400 方块）**

| 指标 | 数值 |
|---|---|
| 全部方块中带旋转 | **118,180 / 138,400 = 85.4%** |
| 裙/衣摆类方块中带旋转 | **8,647 / 9,263 = 93.3%** |
| 旋转裙板中位尺寸 | **1.20 × 1.81 × 1.00** |
| 旋转裙板 min 边 ≤0.5 / ≤0.7 | 46.3% / 54.4% |
| 旋转裙板最大转角中位（p25/p75） | **32.25°**（15° / 68°） |
| 2 轴 / 3 轴同时旋转的裙板 | 6,335 / **5,275** |

代表工程：
- `hi3_elysia`：`ClothHipLeftInnerSkirt` **126/126** 块全旋转，其中 **121 块三轴**；`ClothHipFrontLeftPlane` 12/12 三轴。
- `yujin`：`Skirt_Left3` **121/121** 旋转（围绕 X 的 2.5–17.5° 为主，36 块三轴）；`Skirt_Left2` 128 块中 124 旋转。
- `bronya_reason4.2`：`outskirt` **85/85** 全旋转、全部三轴，最大角中位 **62.2°**；`fskirt` 53/53、51 块三轴。
- `ak_virtuosa`：`coat_L/R` 系列薄板厚 **0.15**，绕 Y 约 56° 做斜披。

**参考模型结构分析 SOP（做裙/衣摆/发梢前先做）**
1. 读 `material/refmodels/ysm_decoded/<模型>/models/main.json` 或 `main.json` 的 `bones[].cubes[]`；
2. 按骨名筛 `skirt|dress|hem|frill|ruffle|coat|cape|train`，统计每骨 cube 数、`rotation` 非零比例、`size` 三围、X/Y/Z 各轴角度、三轴组合数；
3. 若参考裙板 90%+ 带旋转且大量 X/Z/三轴 → 照 §3.6 斜置薄板；若你自己模型的裙板只有 Y 轴旋转 → 就是"圆筒"反例，必须重做；
4. 把统计数字和代表块（size/rotation/origin）写进任务报告，作为"为什么这样摆"的证据，而不是凭感觉。

**反例（祥子 v5 实测）**：裙 165 块中 164 块带旋转，但 **全部只绕 Y**（X/Z 中位 0、三轴 0），板尺寸 2.25×1.12×0.5。旋转率看似很高，实际是"竖片环/圆筒"，不是斜面拼曲面——这就是"方块堆叠感"的来源。
**正例（v6.2 落地，2026-11-08）**：同一裙 165 块 → **182 块三轴斜置薄板**（非零旋转 100%、三轴 100%、板厚中位 0.34、五裙骨保留），外加 32 片低 tilt 内层黑壳 + 30 片蓝壳堵缝；全身/侧/背看到连续层叠斜面，无漏光。
> 教训：v6.1 曾把裙加到 262 片（三轴 96.2%）但特写仍漏光/散刺；v6.2 减到 182 片，靠**内层连续壳 + 切向重叠 1.24–1.38** 解决，不是无限加板。斜置薄板解决"圆筒感"，内壳/重叠解决"漏光"。

**做法（裙摆/披风/衣摆/长刘海通用）**
1. **分层**：2–4 圈；每圈 **16–28 片**薄板，片数越多越圆；总块数按档位控制在 60–180（精细裙可 200+）。
2. **薄板尺寸**：切向长 = `2πr/N × 1.10`（相邻片重叠 10%）；法向厚 **0.15–0.5**；高度 0.8–2.0（内层矮、外层高）。
3. **旋转**：`rotation=[tilt_x, yaw, tilt_z]`，其中 `yaw=i×360/N+相位偏移`；`tilt` 绕切向轴倾斜 **内圈 5–15°、中圈 15–25°、下摆 25–40°**；允许三轴组合。**只绕 Y 的竖片不算曲面**。
4. **位置**：半径逐圈 +0.6–1.5；y 逐圈下降 1.5–3；相位偏移 12–90°；相邻圈上下叠压 10–25%；外层下摆半径最大。
5. **颜色**：同圈同色、按高度明度分档；斜板受光自然产生明暗，不要把每片画成渐变。
6. **验证**：先只做 12 片小样，render front/side/45°/isolate 看是不是"斜面片"；确认后按 N 复制。重点看侧视/45° 轮廓有没有"阶梯/竖条/圆筒"。

**Euler 注意**：Blockbench 欧拉序是 XYZ（R=Rx·Ry·Rz）；斜板方向要按 `ry=asin(tx), rx=atan2(−ty,tz)` 解；先渲染 1 片标定，再批量。
> **2026-11-08 v6.1 实测反馈**：按 XYZ 设计的三轴裙板在引擎里出现板缝；射线遮挡测试提示引擎可能按 **ZYX** 组合（尚未最终定论）。**不要假定欧拉序**：先用 1 片 `[10,20,30]` 三轴板渲染 front/side/45°，把实际投影与 XYZ/ZYX 两种组合比对，确认后再批量；板缝可用"透明背景 alpha 洞 + 射线遮挡"定位。
**同类**：角/发梢/披风/裙撑/荷叶边都用薄板；厚方块只用于身体/鞋底/配重件。

## 4. 部件做法（带实测数字）

### 4.1 头与脸

**头别做大、脸别露太多**（最容易翻车的两点）：

| 项 | 数值 |
|---|---|
| 头宽 | 6.0–6.2（可选精细做法；默认骨架 7，语料中位 7.0） |
| 头高:头宽 | 接近 1:1（6.2×9.1 会成"竖长条"，压到 6.2×6.7） |
| 脸被头发遮挡 | 62–67% 好；可见脸 33–38% |
| 脸 UV 分辨率 | 128 贴图 → 脸仅 7×7px；**512 → 64×64**；1024 → ~136×166。新项目 **512 起步** |
| 脸 UV 标定 | 脸 UV 的 u/v 可能旋转，画五官前先画"十"字标定 |

**框脸顺序（效果优于雕方块）**：
1. 刘海下压到**眉上沿/眼上沿**，8–15 撮错落，中央最低点压在眼上沿附近；
2. 两侧侧发各盖进 **1–1.5 单位**，吃掉脸方角；
3. 鬓发贴颊，再收窄一档；
4. 剩下露出的 4–5 × 3–4 单位才是"脸"。

**脸型修形三法（按投入递增）**：
| 法 | 做法 | 效果 |
|---|---|---|
| 贴图法 | 颊部阴影/下巴收暗/鼻影画在贴图上 | 多数情况够用 |
| 窄脸板 | 脸板 5.5–6 宽，下巴单独窄板斜置 | 轮廓明显秀气 |
| 劈头法 | 头切左右镜像斜片（下巴收窄/脸颊外扩） | 最精致，`hi3_elysia`/`changchun`/`bronya` 都用 |

> 实测：只做"窄+后退下颌"时，45° 侧看脸颊仍是直角；要真弧面必须斜片。

### 4.2 眼睛：平板眼白 + 小方块叠层 + 四角小片勾勒（2026-11-08 重写）

> 被用户纠正 4 次。2026-11-08 逐个打开 doggo / zhe_2 / ak_kaltsis / yujin / 甘雨 / 镜流 等参考模型（渲染 2400² + 读方块数据）后重写本节；完整证据见 `docs/23` §1/§6。
> **核心**：眼睛不是"一块多边形"。眼白 = 一块大而平的板（几乎贴脸）；虹膜/瞳孔 = 2–34 个小片叠；眼型靠 **上眼线弧 + 外眼角翼 + 四角小片** 把方形四角切掉。真正凸出的只有上眼线（0.3–0.7），眼白只凸 0.02–0.07。

**参考实测（2026-11-08；脸宽 6–7）**

| 部件 | 尺寸/块数 | 相对脸面 z |
|---|---|---|
| 眼白板 | 2.0–2.2 × 1.3–1.8 × 0.30–0.36 | **凸 0.02–0.07（几乎贴脸）** |
| 虹膜/瞳孔 | 2–34 片，0.1–1.3，厚 0.03–0.4 | 凸 0.03–0.15 |
| 上眼线 | 2–12 片 0.7–1.15×0.34×0.68，rot Z −40°…+40° | **凸 0.3–0.36** |
| 外眼角 | 0.4–0.7×0.5–0.86，3D 旋转 | **凸 0.6–0.7（最凸）** |
| 下眼睑/眼影 | 0.14–0.38×0.25×0.16 | **凹 0.15（在脸内）** |
| 眉毛 | 2–9 片 0.5–1.6×0.16×0.29，逐段递减旋转 | 凸 0.15–0.72 |

**定位**
- 眼中心 x = **±1.76**（脸宽 6–7，约半脸宽 50–53%）；**双眼内缘间距 1.43–1.5 ≈ 20–24% 脸宽**；旧派 doggo ±2.12（41%）偏宽，不要照抄。
- 眼高 1.3–1.8（脸高 20–26%）；眼中心 y = 脸底 + 0.30×脸高；宽>高（1.2–1.4:1）。
- 眼/眉骨骼 pivot 在眼中心；移动眼睛时**同步移 pivot**（动画只引用旋转，pivot 平移安全）。

**构造（从后到前，标准档每眼 16–22 块；高精参考可达 34 片虹膜，标准档不跟）**
1. 眼白板（大、平、贴脸；奶白/浅灰）——不要用菱形板当眼白（"金宝石"错误）
2. 虹膜外环（主色，约眼白 75–85%）→ 内环（深色）→ 竖瞳（居中，宽约虹膜 1/3）→ 高光 1–2 小片
3. 上眼线 2–3 片（深色，前凸 0.3–0.36，外段可到 0.6–0.7；压住眼白上缘 10–20%）
4. 外眼角深色翼（rot Z ≈ −30°，斜上外伸 0.2–0.3）
5. 内眼角小点 0.2–0.3
6. 下睑暗片（薄、可凹回脸内 0.1–0.15）
7. **四角勾勒小片 2–3 片/角**（肤色/眼线色；0.18–0.4；rot ±10–35°；z 放在"眼白与虹膜之间"或"虹膜前"）——**沿眼弧排列、相邻片旋转差 10–20°、重叠 0.03–0.05**，把方角切成弧形/多边形；**放在虹膜后面只能遮眼白、看不出切角**（v4 实测）；眼角片用**脸皮同色格心**（不要用发色行）
8. 眉 2–3 片递减旋转（深灰紫）
9. 可选：上下睑肤色压边 0.12–0.18 薄条

**常见错误（全部实测被否决）**
- ❌ 眼白做成 45° 菱形板、整片凸出 0.3–0.6 → "金宝石眼"
- ❌ 虹膜占满眼白 → 金板；应留 0.2–0.3 白边
- ❌ 眼中心 ±2.3 以上 → 眼距过宽（现代模板 ±1.76）
- ❌ 四角片只做 1 块大直角 → 补丁感；放虹膜后面 → 无效
- ❌ 眼角片用发色 swatch 行 → 被改色污染成紫块；眼睛颜色独立行/格
- ❌ 只靠几何做"纯方眼"；没有上眼线/四角小片
- ❌ 眼睛做成全场唯一超精细处（画风割裂）；标准档 16–22 块/眼足够

**贴图**：每块一个 2–4px 纯色 swatch；眼睛用**独立一行/格**（白/金/深金/深棕/高光白/深灰紫眉），不要和发色/肤色行混用；改发色后 isolate 单眼核对一遍。

### 4.3 头发：底发帽 + 附属束分层（2026-11-08 重写）

**结构（参考实测）**：必须是"一层底发帽 + 上面各种附属物"，不是几块大板。

- **底发帽**：覆盖头顶/后脑/两侧，20–80 块小板（每块 1–4 宽 × 0.5–2 高 × 0.5–1 厚），紧贴头（离头面 0.05–0.15）；可用 0.5–0.8 薄板。
- **附属组各自成骨/链**：刘海、侧发、后长发、双马尾/辫子、发髻、发饰；下缘互相叠压 1–3 单位。
- 参考：甘雨 `hair`37 + `HairFront`13 + `LongHair3`42 + 发髻 10 + 侧发 5；镜流 `hair`80 基础发 + 多级子束；狗哥 `Hair`27 + `front_h1`14 + `LongHair`28 + `S2`60。
- ❌ 2 块 8×8 大平板当顶盖（45°/背面必露头皮、像盖子；祥子 v3 前的根因）。

**细则**
- 厚度：标准档发束恒 1.00（22,013 块里 49.2% 在 1.00±0.05）；粗档 1.2–2.1、细档 0.38–0.66；同一模型只用一档。底发帽可用 0.5–0.8 薄板。
- 等粗长条 + 多块串联（每段 5–12° 渐变弯曲，长直发可 2–5°）；每束 6–16 段，相邻段重叠 0.2–0.3。
- **后发**：≥4 束 × 6–10 段，长度差 1.5–5.5，束间 x/z 错开 0.2–1.4，垂到腰/臀；内层加 6–10 块填充防漏。
- **刘海**：2 层——后层 6–8 宽板压额头；前层 **8–12 缕**（宽 0.9–1.5）中央分缝、每缕 3–5 段折角 5–12°、发梢收尖 30–50%；**发丝最低点不得落在眼区前**（|x|<3 且 y<36 的区域；实测刘海挡眼一整轮，v3.2 修复）。
- **侧发**：每侧 2 组 × 3 块垂到胸；**双马尾/辫子**独立骨，从耳后 y≈36 垂到 y≈20，层间前后错开 0.6–1。
- 发色：每块纯色、按高度分档（约 7 档），不要每块各自渐变；同高度同色。
- 发饰单独成骨挂在发束上；分缝 98% 靠贴图。
- **检查**：front/back/left/iso + isolate 头发（角隐藏）；重点查头顶/耳后/颈后露皮、束间缝隙。

**全覆盖 + 平滑发缕（2026-11-08 v7 实测，必须按此修）**
- 底发帽必须有**实心内填充/穹顶**，不能只做单层薄壳：v7g 用薄片圈层顶视出现中心孔+白块；v7h 改实心叠层 + 逐面 UV（2×2，发色 swatch）后顶视透孔 0。
- 顶部用**同心水平叠瓦/实心层**（4–6 层，重叠 20–30%），不要放射风车薄片；顶视剪影要连续圆穹。
- 刘海：8–12 缕 ×3–5 段，宽 0.9–1.5、厚 0.45–0.7；禁止"针刺竖条"（v7d 96 块针状被推翻）。
- 后发：7–9 缕 ×6–9 段；侧发每侧 2–3 缕 ×5–7 段；每段沿曲线，**相邻段旋转差 5–15°、重叠 0.2–0.3、中心连续**；不要横向/纵向错位台阶。
- 顶视/侧视/背视都要 render isolate 验证无头皮；新增 `HairCap` 骨时保留原 303 动画引用（新骨不被引用即可）。
- 判定：顶视 0 背景孔、侧/背无露皮；发缕段间旋转差报告、重叠报告必须写进任务报告。

### 4.4 角 / 兽耳（辨识件）

**先判读旋转轴，再决定几何。** 2026-11-08 实测教训：

- ❌ 只绕 Z 轴（方块 `rotation=[0,0,±θ]`）→ 正面是 C 形、45° 看是一排竖片，z 跨度 <1（祥子 v2 的错法）。
- ✅ 正确：角是**绕左右轴 X 的螺旋**，同时沿 ±X 向外扩展（像弹簧）；参考甘雨角 x 2.7–6.4、y 45.6–49.1、**z −4.7~+3.0（跨 7.7）**，每块 pivot 落在两个螺旋中心上。

**参数化螺旋（祥子 v3 实测可行；每侧 1 骨，parent=Head，pivot=角根）**

```
P(t) = P0 + A·L·t + (0, ry·cosθ, rz·sinθ)
右角：P0=(1.55,41.10,-0.20)，A=normalize(+1,-0.02,0.06)，L=4.60
θ(t)=150° + 470°·t（≈1.3 圈）；ry=2.45→1.05，rz=2.05→0.85
26 段近立方块（尺寸 1.45→0.62 等比），rotation 全 0（只靠位置排螺旋，避开欧拉序）
每 3 段 1.12× 棱纹块；末 2 段收尖；t≈0.9 金环×2；根部深色环+金环
左角镜像（x 取反）
```

**判定**：90° 侧视应看到**完整椭圆黑圈**（不是竖片）；z 跨度 ≥2.5。正面外点/顶点要超出头发包围盒 ≥0.5（否则角被埋，v1 教训）。
- 若追求更锐利角尖：可改 16–18 段薄带 + 显式解 roll，但**必须先做小样旋转标定渲染**（薄带对欧拉约定极敏感，按 ZYX 推导会变"齿轮辐条"）。
- 角体量参考：占图宽可达 47%，把顶部轮廓拉高 5.5 单位。

### 4.5 身体

- **胸**：不是"必须几块"，是"这个体态需要多大起伏"；一圈斜置小块拼球冠，峰值偏下、上缘压低；胸前可单独一根 `Breast` 骨。
- **腰**：靠躯干方块旋转做出八边形截面 + 胯宽对比，不需要额外骨骼分段。
- **腿**：环切（3–4 环 × 6–9 板绕 Y 45°）比方柱自然；大腿→膝收→小腿肚再鼓；膝最细 ≈26% 身高；腿占身高 ≥50%。
- **肩**：平肩即可，A-pose 略外展（|rotZ| 18°）；斜肩基本不做。
- **颈**：98% 不做几何（头直接坐躯干）。
- **手**：每只 2 块就够（分指只有 5%）；袖口与手要有明度/形状台阶，避免"手腕糊成一块"。

### 4.6 服装（裙子是重灾区）

**先定布怎么垂、怎么展，再定拓扑；曲面实现按 §3.6（斜置薄板），不要只做 Y 轴竖片环/方块堆。**

裙子 5 种拓扑（**同心圆环已淘汰，全语料 0.35%**）：

| 型 | 做法 | 适合 |
|---|---|---|
| A 平面薄片围合 | 大薄片围成筒 | 挺括短裙 |
| B 竖条帘幕 | 竖向长条成排 | 长裙/垂坠 |
| C 微块马赛克 | 小方块堆 | 蓬松/毛绒 |
| D 花瓣羽片环 | 细长羽片环形排 | 花瓣/多褶 |
| E 单骨大裙 | 全塞一根骨 | 省资源 |

- **A 字外扩**：绕枢轴倾斜必须写 `rotation[2] = -pitch`（旋向与右手定则相反），先在渲染里验证一次；否则连续做出"漏斗裙"。
- **裙纵深**：不是越扁越好——实测裙层旋转后 z/x≈1.00（正圆体），**z 从 1.00 加到 1.09–1.14**；扁的是躯干（z×1.25）。
- **斜面截断锥（v7 实测）**：裙不是水平截断的圆锥——前下摆应高于后下摆（示例前 15.4 / 后 12.4，差 ≥2.5u；侧 ≈14.0）；底环随方位连续渐变，不要 4 段台阶；顶环对齐身体中心（示例 x=-0.15）并贴胯（y≈23.6），腰封/内衬必须衔接上身。
- **坐标坑**：`main.json` 的 cube `origin` 是**世界坐标**；生成器写 `origin=pivot−R·loc` 时若 R 被乘两次，会让设计空间裙中心偏移（v6.2 偏 1.87u、白边尖刺），**不要靠硬平移掩盖**；生成后先算设计空间 bbox 中心 vs 身体中心，再渲染验证。
- **层与层次**：每层相位错开 12–90°；下缘正弦扰动 ±0.5–0.9；荷叶边靠相邻块交替角度，不要单独建 hem/frill 骨。**每层 16–28 片斜置薄板（§3.6），薄板厚 0.15–0.5、内圈 tilt 5–15° / 下摆 25–40°；只绕 Y 的竖条环会成圆筒。**
- **重做已有裙**：保留模板的 `Skirt` / `FrontSkirt` / `BackSkirt` / `LeftSkirt` / `RightSkirt` 五骨与父子关系，按扇区/层把薄板分配给对应骨（前中→FrontSkirt，后中→BackSkirt，左右→Left/RightSkirt，中心层→Skirt）；不要新增裙骨，否则 303 动画的引用会丢。
- **衬裙/内衬**：白色衬裙边沿裙摆**整圈露出**才有"重蕾丝"感，只露碎片=没做。
- **拖尾**：薄 + 长链 + 长度落地，不要只 3 块。
- **同层深色必须拉开明度 ≥4 级**，否则分层糊成一片；最暗不要低于 `#1a1a20`。
- 上衣直接雕进 `UpBody`；袖子挂 `Arm`/`ForeArm`；披风靠薄+长链。

### 4.7 配饰与特效

- 配饰是"角色特点"的高浓度区：预算花在**一眼能认出**的那几件（发饰、胸针、腰带、角环）。
- 特效层（`ysmGlow` 发光、拖尾、光晕）是"震撼感"来源，但不能替代本体质量；普通角色特效占比 2% 左右即可。

### 4.8 官方原画：强调 vs 省略

- **必须强调**：头发体量、眼睛大小与瞳色、胸腰胯对比、色块对比、腰部配饰群、辨识件（角/兽耳）。
- **降级到贴图**：蕾丝花纹、刺绣、半透明、细绑带、布料褶皱、头发高光。
- **配色**：主色 4–6 个 × 每色 2–3 级明度 + 高光档；金/宝石等高饱和小块 <5% 面积，放视觉焦点。
- **执行期间要反复回看原图**（尤其是发色/服装配色），否则容易"越修越偏"。

## 5. 贴图与配色

- **尺寸**：新项目开 **512**（现行最低可用；模板默认 128 必须改，否则脸只有 7×7px）；精细/特写 1024。
  语料主流其实是 **256**（社区现状、可作下限参考，不是推荐值）。判断够不够用 **texel/块**（语料中位 99、p90 358），不要只看尺寸。
- **上色五条**（官方群课程，详见 playbook §7）：明度（朝上亮/朝下暗）、饱和度（亮部低/暗部高）、天光（亮面暖/暗面冷）、AO（阳角亮/阴角暗）、闭塞阴影（根部/缝隙最深）。
- **色阶**：主干部位 2–3 级明度；深色叠层 ≥4 级。
- **纯色分档 > 每块渐变**：连续几何（发/裙/褶皱）用"同高度同色"的纯色分档，避免一条条闪。
- UV 三种写法：省略（自动避让）/ `{mode:"box",offset,size}` / `{mode:"faces",faces,sizes}`（逐面精确，眼睛/饰件必须用）。
  box UV 的 `size` 决定采样面积（4×4 指纯色 swatch 即纯色）；`bb_get_element` 不回显 size，以渲染为准。
- 大面积涂色前先 `bb_scene(scope:"uv")` 看 `unsafe_bboxes`；按骨骼 bbox 涂色会误伤别家 UV（实测误伤 36 个面）。
- 局部检查 `bb_texture_read({format:"palette"})`；放大核对 `bb_render_texture({scale:8~12})`。
- PBR：`bb_texture_pbr` 生成 `_n`/`_s`，需要光影支持（下界渲染不显示）。

## 6. 逐部件检查（**强制**，本手册的执行核心）

`isolate` 只渲染指定骨骼子树并自动对焦；其余隐藏，token 更省、细节更清楚。

```
bb_look({isolate:"AllHead", zoom:2.5, cell:640,
         cells:[{camera:{azimuth:0,elevation:4}},{camera:{azimuth:45,elevation:12}}]})
bb_look({isolate:"Skirt", zoom:1.6, cells:[{view:"front"},{camera:{azimuth:40,elevation:8}}]})
```

**先做部件索引**：按 §2.8 的 `ref_parts` 表，把每组要检查的骨/组映射到 T3 拆解板上的零件编号与裁切图；每组 `isolate` 后与对应零件图并排看，记录 `part id / 骨 / 角度 / 判定`。不要只对全身图看“像不像”。

**语义注意**：
- `isolate:"Head"` 会**连带子骨骼**（头发、角都在），查"纯面部"要用叶子骨列表；
- `bb_look` 与 `bb_render_views` 的 `isolate` 都接受逗号分隔多部件（2026-11-07 已修复 `render_views` 的逗号拆分）；
- `closeup` 单独渲染；`focus.padding` 只改对焦点/边缘留白，**不改变缩放倍数**；要真特写用 `isolate`+`zoom` 或高分辨率渲染后本地裁图。

### 6.1 八组检查清单（每组至少 2 角度，建议 2 格拼图省预算）

| # | 组 | isolate | 必看看点 |
|---|---|---|---|
| 1 | 头+脸+眼 | `Head` 或眼/脸叶骨，zoom 1.6–2.5 | 可见脸宽度 ≥1/3 头宽；眼神/瞳色；额前无"发箍"横条；两颊无直角 |
| 2 | 前发/侧发 | 刘海/侧发骨，zoom 1.9 | 中央缺口是否过宽；发片是否薄直板；发梢是否锐；侧发是否贴颊 |
| 3 | 后发/双马尾/蝴蝶结 | 后发/马尾/发饰骨，zoom 1.2 | 体量是否第一；顶视/侧视是否**0 露头皮**；是否"整面帘/阶梯块"；段间旋转差 5–12°；末端是否收尖；蝴蝶结是否可见 |
| 4 | 双角 | 角骨，zoom 2.2 | **最外/最前点是否超出头发包围盒 ≥0.5**；扫角/棱纹/角根环；左右对称 |
| 5 | 躯干+胸饰 | `UpperBody`，zoom 1.25 | 领口内衬；胸饰大小；有没有参考里不存在的平板件；腰线 |

**每组记录**：隔离图路径 + 参考依据（对照表编号/拆分部件编号）+ 差异 + 判定（pass/minor/major）。
**频率**：定点小改时 **renders 应多于 edits**（实测 6 写 / 21 渲染）；全身图只看 1–2 次。
**每个 P0 项完成/修复后 `bb_checkpoint`**（命名 `vN-P项` 或 `vN-base/final`）。

### 6.2 整体验收清单（先整体，再细节）

- [ ] 缩到拇指大小：**发色/瞳色/标志服装/辨识件（角等）** 能在剪影里认出
- [ ] 正/侧/背同一角色、同一套画风与色板
- [ ] 全身方块尺度协调，没有局部突然精细
- [ ] 头宽 6.0–6.2；可见脸 33–38%（脸被头发遮挡 62–67%）；脸型有处理（不是裸方板）
- [ ] 主色 4–6 个 × 2–3 级明度；深色分层靠明度拉开
- [ ] `bb_orbit({steps:8})` 无穿模/漏缝
- [ ] `bb_validate` 0 error（仅接受 `TEXTURE_SIZE`、可选 `ViewLocator` 两类 warning）
- [ ] 导出 zip + 4 视角成品渲染（front/back/left/iso_fr，768）

> 不要用"块数够不够/厚度是不是 1.00"当验收标准——那是手段。

**渲染反馈判读**：`review.verdict` 有五个值——`visible_change` / `visible_change_clipped` / `no_visible_change` / `empty_render` / `no_change_expected`。
连续 3 次 `no_visible_change` 触发 no-progress → 先 `bb_restore` 或换策略；`edge_touch=true` 说明被裁切，用 `focus`/调机位；
背景透明，不要用"背景色没变"判断失败；规则判定不是 VLM，造型/配色仍要自己看图。

**交付前反模板检查（必做）**：
- [ ] 骨架不是纯模板骨架（该加的辨识件骨/头发骨都加了）
- [ ] 每个可见部件都能说清"从哪张参考图推出来的"（不是模板复制/旧模型换色）
- [ ] UV 不是简单重映射；贴图有按参考取样/分档的配色过程
- [ ] 有 `bb_checkpoint` 过程记录，不是一把梭

## 7. 动画

- 列表 `bb_animation_list`；新建 `bb_animation_create({name:"animation.main.xxx", length, loop})`；关键帧 `bb_animation_patch`。
- 一个 patch 内多 op 共享一个 Undo；`bind_controller` 绑定控制器。
- 至少做 1 个自定义动画（idle/挥手）验证管线；采样检查用 `bb_anim_check`。
- 保存时动画"合并回写"：未修改条目/顺序保留，只替换语义变化/追加/移除。

## 8. 保存 / 导出 / 回滚

- `bb_checkpoint({label})` 内嵌贴图当前像素；`bb_revisions` 列表；`bb_restore({revision, confirm:true})`（restores 预算极少，主要用于取证）。
- `bb_save_project` 写回 pack；`bb_export_ysm` 强制 validate，产物含 `export-manifest.json` + zip。
- `bb_batch` 不是事务，失败不自动回滚。
- **数量真相源**：`bb_scene(scope:"summary")` 或直接读 `main.json`；`bb_validate.stats` 与 `bb_session_start` 的 summary 都不可靠（后者是 main+arm 合计）。

## 9. YSM 约束与骨架速查

- **骨骼数量无上限**（模板 70 骨只是模板；语料中位 114、最高 1257）。**不要被默认骨架限制**，按造型自由加骨。
- 真限制：骨骼嵌套 ≤32 层（2.6.3 起上限解除，但超 32 层的兼容性未验证）、网格子级 ≤64、纹理子级 ≤32、贴图 ≤4096×4096。
- 必需定位组：`Head`/`Body`/`RightArm`/`LeftArm`/`RightLeg`/`LeftLeg`；建议 `RightHandLocator`/`LeftHandLocator`（放在对应 `Hand` 组**里面**）。
- **标准骨架树（模板）**：`root → AllBody → {DownBody → LeftLeg/LowerLeg/Foot…, UpBody → {LeftArm/RightArm, AllHead → Head, Breast}}`；细节层 `UpperBody`（外套/领子/胸饰）。颈 98% 不做、臀 93% 不建、手每只 2 块。
- **命名**：大写驼峰、`Left*`/`Right*`/`All*`；不可改名组：`Head`（游戏自动加"头部随视角"）、`LeftHand`/`RightHand`（Locator 必须在组内）。
- **交付三件**：`main.json` + `arm.json` + 任一 PNG；文件夹/贴图名只能**小写英文/数字/下划线**。
- **arm.json**：复制主模型 → 把 `LeftArm`/`RightArm` 放根 → 删 `Root` → 旋转归零 → 根下建 `Background` 组。当前工具**没有工程切换接口**，arm 只能沿用模板；**不要谎称重做**。
- **动画槽位**：`walk/run/idle/jump/…` 放 `main.animation.json`；`parallel0–7` 并行且优先级更高；`extra0–7` 放 `extra.animation.json`（轮盘播放）。
- **MoLang 常用**：`ysm.has_helmet ? 1 : 0`（显隐）；`(ysm.head_pitch > 0) ? -ysm.head_pitch : 0`（长发不穿身）；完整变量见 playbook §9。
- 改完模型/贴图必须保存，否则导出的是磁盘旧版本。
- **回报格式**见 `assets/delegation-brief.md`：结果 / 产物绝对路径 / 各阶段实测数字 / 参考判读 / 偏差（诚实列"不像"）/ 未做项与原因 / 发现的问题。

## 10. 工具坑（全部实测）

### 10.1 致命级（会静默产出错模型）

| 坑 | 表现 | 规避 |
|---|---|---|
| `delete` 语法错时静默失效 | 返回 ok，`changed[]` 里没有 delete，旧块还在 | 必须 `refs:[{kind,id}]`，每批核对 `changed` 条数 |
| `update_cube` 不更新 pivot | 带 rotation 的块改 origin/size 后绕旧枢轴，偏移可达 1 单位 | 同时传 `pivot` |
| `main.json` 与 bbmodel x 镜像 | 按 json 坐标改块 → 整批镜像错位 | 用 bbmodel 坐标 + 逐块校验 mismatch=0 |
| cube Z 滚转旋向相反 | 裙板做反成"漏斗裙" | 要外扩写 `rotation[2] = -pitch`，先渲染验证 |
| `resolution` 未生效（旧 bug） | 仍 128，所有 >128 UV 被 Clamp，渲染全错 | 校验 `bb_scene.textures`，必要时手改 `texture_width` |
| box UV 不给 `size`（旧 bug） | 采样恒 1px/单位，贴图糊 | 给 size 或逐面 `faces+sizes` |
| 按名字删同名块只删第一个 | 128 个同名只删 1 个 | 用 uuid 或重复 refs 并核对 changed |
| `update_bone scale` | 空操作/UNSUPPORTED_FIELD | 改几何 |
| `render_views` 按视图名落盘 | 多次 isolate 互相覆盖，只剩最后一张 | 每次渲染后立刻改名归档 |
| `no_visible_change` 假阴性 | 文件已变仍报未变 | 比对 PNG 字节/自己裁图看 |
| `bb_validate.stats` 非真相源 | bones 恒 77、cubes 有偏差 | 用 `bb_scene`/`main.json` |
| save 产生陈旧重复路径 | `models/deepseek-fish/models/deepseek-fish/...` | 忽略，不当真相源 |
| export 用内存 ysm.json 覆盖手改 | `extra_animation_buttons` 被抹 | 改后再 export 或改 `_ysm.json` |
| **参考板裁切未目检** | front 面板混进 side、side 混进 back、back 混进头部/服饰细节；侧/背对照被污染（祥子 v5 R5/R6 返工） | 按 §2.8 原图像素独立裁切 + proof 图 + 每张 read_image 验收；对照拼图不能替代独立裁切 |
| **裙生成器 origin 双乘 rotation** | `origin=pivot−R·loc` 误把 R 乘两次：设计空间裙中心偏 1.87u、白边尖刺/左右扇区反；硬平移 1.7u 反而更歪 | 生成后算设计 bbox 中心 vs 身体；修正为 `pivot−loc`；左右按 x 侧重分骨；渲染验证 |
| **极薄方块的 box-UV 会采样偏移到相邻 swatch 行** | 0.03–0.06 厚的眼角/菱形片渲染成别的颜色（紫块/白块）；显式 `uv`/`uv_size` 也未必救 | 眼睛等极薄块用**独立 swatch 行**；改发色/肤色后 isolate 单眼复核；必要时删掉问题薄片或加厚到 ≥0.08 |
| **重开工程后 cube/bone UUID 会重新生成** | 旧 id 全部失效，`DELETE_PARTIAL`/update 全错 | 用骨名 `update_bone({bone:"<骨名>"})`；删除按重开后的 id；批量改块用"按骨名 + 序号"重建 |
| **`bb_look`/`bb_render_views` 的 isolate 拼图只内联不落盘** | 需要归档证据时找不到文件 | 用 `bb_render_views({views:["front"], size:[2400,2400]})` 单视图落盘，再自己裁头 |

### 10.2 影响观感/效率

| 坑 | 规避 |
|---|---|
| `isolate` 会包含子骨骼；查"纯面部"用叶子骨 | 记住语义；`bb_look`/`bb_render_views` 都支持逗号多部件（已修复） |
| `closeup` 与其他视图同批会污染取景；`focus.padding` 不改缩放 | 单独渲染；要特写用 1200px 渲染 + PIL 裁头 |
| `bb_look` 的 `focus:"Head"` target 可能算高（全是空地） | 用 isolate / 显式 `bb_camera` |
| 大面积按骨骼 bbox 涂色误伤别家 UV | 先 `bb_scene(scope:"uv")`；per-cube UV 岛 |
| 脸 UV 的 u/v 可能旋转 | 先画"十"字标定 |
| 一次 patch 混 delete+add+update | 一次只做一类，delete 单独批并核对 |
| 700+ 块 inline ops 会耗尽 budget | 改「Python 生成 main.json+PNG → close/open」脚本化路线 |
| 外部官方图直链 403/404 是常态 | 萌娘原始 storage / `bb_ref_collect({urls})` 直喂；缺口进 gaps |
| `Set-Content -NoNewline` 写脚本 | 用 `write`/`edit` |
| `bb_batch` 内图片块/回执 | 以最新实现为准；长批拆小 |
| **欧拉序不要假定** | 按 XYZ 推导过角/斜板；v6.1 实测三轴板出现板缝、射线与 ZYX 吻合。批量前用 1 片 `[10,20,30]` 做 front/side/45° 投影标定，再决定 XYZ/ZYX |
| 骨骼 `delete` 会**级联删除子骨骼与方块** | 删角/马尾根骨会一次清掉整条链；补丁里要"先删后建"，且不要重复删已级联的 id |
| **眼睛/头发/角的"旧结论"会互相矛盾** | 旧 skill 的角绕 Z 258°、眼白 2.0×1.36×1.00、总凸出 0.38 已被 2026-11-08 实测推翻 | 按 §2.7 打开参考模型重新判读；以本文件 §4.2/4.3/4.4 与 `docs/23` 为准 |
