# 新时代 YSM 模型设计（bb_* 工具）

> 用语义工具在后台 Blockbench 里安全地建模/贴图/动画，并用无头渲染自检。
> 本技能的数字来自 **169 个解密后的现代 YSM 工程**（151,155 方块 / 24,800 骨骼）实测，
> 不是经验之谈。详细拆解见 `docs/20`、`docs/21`、`docs/21a/b/c`。

## 0-A. 谁来调用（**强制**）

**主代理不要直接调用任何 `bb_*` 工具。** 一律委派：

```
用户请求 → 主代理判定任务类型 → 用 assets/delegation-brief.md 拉起子智能体
        → 子智能体先 promote（补全任务书）→ 执行 → 回报产物与证据
主代理只做汇总与验收，不碰 bb_*
```

理由：渲染图 200–900 token/张会污染主会话；主会话容易跳过搜图/写 spec 直接改方块；
建模动辄几十次写操作需要独立上下文；事故无法隔离。

例外：只读的 `bb_session_status` 可以主代理做。协议见 `docs/17`。

## 0. 铁律

- **不猜结构**：先 `bb_scene(scope:"summary"/"bones"/"cube")` 看真实层级；不要凭空编 bone 名。
- **小步修改**：一次 `bb_apply_model_patch` 只做一类事；大改前 `bb_checkpoint`。
- **每次可见改动后必须看图**：写操作会自动附 `front + iso_fr` 拼图；不够就 `bb_look`/`bb_orbit`。
- **不要空转**：连续多次 `no_visible_change` 就停下检查或回滚，不要盲目叠加。
- **导出前必校验**：`bb_validate` → `bb_save_project` → `bb_export_ysm`。

## 1. 开工流程（顺序不能反）

### 1.1 官方基准（必做第一步）

`bb_ref_canon({character})` 一次拿三样：**外观文字描述**（已裁到外观相关段落）、
**外文名/罗马音**（booru 只认罗马音）、**官方图对照表**。

这份基准用来校验后面所有候选图。实测教训：一次验收里 15 张候选混进了**另一个角色**，
靠人肉才排除。有基准能一眼剔除。

### 1.2 大面积搜索（搜索很便宜，别省）

`bb_ref_search({character, depth:"deep", romaji:<name_variants>})`

deep 展开 24 条中/日/英查询词 × Bing 三语区 × 3 页分页 + 360 分页 + 萌娘 + yande.re，
实测候选量比 fast 放大一个数量级（96 → 902）。单源失败会在 `sources` 报状态，**不要把失败当成功**。

### 1.3 下载成对照表

`bb_ref_collect()` —— 下载 + 精确/感知去重 + 拼成一张带编号对照表。
**必须真的看**：哪些是同一角色、什么角度、有没有设定集页。对照 canon 剔除错图。
缺背面是常态：**继续做，合理推测，最后明确告诉用户**。

### 1.4 写 spec

`bb_spec_save({spec})` 把结论固化成结构化规格（部件/骨骼/方块预算/用色/参考索引/gaps）。
校验会挡住明显会做砸的方案（方块数、头部占比、贴图尺寸、缺背面却未记 gaps）。
返回**构建计划**：`order` + `bones`（父级与预算）+ `texture.regions`。
换会话用 `bb_spec_load()` 恢复。

### 1.5 开项目

`bb_session_start({mode:"new_ysm", name, resolution:[512,512]})` 新建
（`resolution` 会真正改写贴图尺寸，**不要用默认 128**）；
已有包用 `bb_project_open({pack_dir})`（**相对 `models/<项目名>/`，不是仓库根**）。

## 2. 现代基线（先判定自己在哪一档）

### 2.1 三个时代，差一个数量级

| 时代 | 方块 | 旋转占比 | 薄片(<0.5) | 判定 |
|---|---|---|---|---|
| 女仆模组 | ~92 | **0%** | 0% | 过时 |
| 女仆移植 YSM | 412 | 75% | 少 | **过时** |
| **现代 YSM** | **742**（中位） | **85%** | **26–44%** | 目标 |

**判定标准**：方块 <500 / 旋转 <70% / 最薄方块 >0.5 → 都还是旧画法。

### 2.2 四条心法

1. **全模型分面化**：不留大平面。曲面拆成大量小方块，每块带微小角度差，
   靠贴图给每块不同明暗造布褶/皮肤过渡。
2. **薄片堆细节**：头发/蕾丝/花饰/丝带边一律用薄片，数量取胜（最薄可到 0.025）。
3. **同色系拉开明度**：分层叠穿必须 **≥4 级明度**，否则糊成一片。深色不用纯黑，
   用 `#1a1a20 ~ #35353c` 阶梯。
4. **褶皱在方块上**：块级旋转中位 **17°**（p75 41°），全是 2.5 的倍数、双峰 8–16°/45–50°；
   **骨级旋转中位只有 0–7°**——不要让骨头变形，让方块摆角度。

### 2.3 比例（中位，n=122）

| 指标 | 值 | 说明 |
|---|---|---|
| 头身比 | **4.87**（主流 4.5–5.5） | 比原画的 6.5–7 头矮，**故意大投小身** |
| 头高/身高 | 0.198 | |
| 腿长/身高 | 0.514 | 大腿:小腿 = **1:1.6**（膝位偏高） |
| 腰/胯 | **0.657** | 腰明显细 |
| **胯/胸** | **1.361**（86% 胯更宽） | **梨形** |
| **腰/胸** | **1.00** | 腰并不比胸窄——不是沙漏 |

## 3. 部件配方

### 3.1 服装：5 种裙拓扑，没有一种叫「圆环分层」

只看尺寸比例判定，与旋转约定无关：

| 型 | 做法 | 代表 | 块/骨 |
|---|---|---|---|
| **A 平面薄片围合** | 厚 0.25 大薄片围筒 | `hi3_elysia` | 329 / 4 |
| **B 竖条帘幕** | 竖向长条成排 | `rongrong` | 224 / 10 |
| **C 微块马赛克** | ~0.65 见方小块堆 | `yujin` | 776 / 8 |
| **D 花瓣羽片环** | 1.46×0.10×4.30 羽片环形 | `bronya` | 406 / 18 |
| **E 单骨大裙** | 全塞一根骨 | `gs_yy_yg` | 234 / 1 |

**圆环蛋糕裙已死**：严格"环带"（薄 Y≤0.6 且两水平轴都 ≥2.2）全语料只有
**23 块 / 2 个模型 = 0.35%**。裙块形状 = 厚块 39.7% + 竖条 37.6% + 横板 9.1% + 碎片 8.2% + 薄片 5.4%。
**94–99% 带旋转**，三轴均用（语料 **X 39% / Z 38% / Y 17%**）。

- **下摆/荷叶边靠"相邻块交替 ±角度"**（覆盖 76–98%），**不要单独建 hem/frill 骨**
  （95 个裙模型只有 3 个这么做）
- **上衣比裙子更重要**：8553 块 / 123 模型（裙 6592/95）。上衣**不单独建骨**，
  直接雕进 `UpBody`；**胸前单独一根 `Breast`**（51 个模型有非空）
- **袖**：25 模型 / 1006 块，挂点全在 `Arm`/`ForeArm`，**无独立袖根骨**
- **披风**：50 模型 / 2773 块，**中位仅 18 块**，靠**薄 0.70 + 5–7 级长链**

### 3.2 身体：梨形 + 分面化

- **胸**：`Breast` 骨（100 个模型定义）。**99.6% 的胸块带旋转**，角度中位 **48°**（35–69°），
  球半径 **3.56**（残差 19%，"手搓球冠"不是精确半球）。每侧 **12–67 块**。
  前突中位 **1.85**，**峰值在下 1/3**，上缘压低 1–1.5。
  **皮肤厚 1.4–2.0；衣服版 0.25–0.35（差 4–8 倍）**；硬甲 0.8–1.2。
  > 别"按法向精确铺"：实测最薄轴与径向夹角平均 **57°（≈随机）**。
- **腰**：**不收腰靠加骨骼**——躯干链中位只有 2 段，但躯干块旋转占比 **0.974**，
  曲线在一根骨内部用旋转小板做八边形截面。侧板绕 Z ±25°。**只有 36% 真收腰**。
- **腿**：单侧中位 **14 块**。**环切**：大腿 3–4 环 × 6–9 板，板 `2 厚 × 3–4 宽 × 5–7 高`，
  绕 Y 约 45° 等分；小腿 3–7 环，板高 9→6→4 递减。
  **膝最细处 = 26% 身高，膝宽 = 腿最宽 72%**。
- **臀：只 6.5% 建臀骨**。藏缝靠 **裙顶比腿枢轴高 5.9** + **大腿骨上伸 1.55**。
- **肩**：A-pose **|rotZ| 18°**（15–20°）。**斜肩基本不做**——78% 平肩甚至外高。
- **颈：98% 不做**，头直接坐 `UpperChest`。
- **手：每只 2 块**，**分指只有 5%**。不要纠结手指。

### 3.3 头发：发片厚度恒为 **1.00**

**先避三个统计坑**：`ysmGlow*` 是复制出来的自发光层（82/169 模型有）；
3 个模型有**整骨架副本**（`X` 与 `X2`）；`ClothHair*` 是**饰品**不是头发。

| 指标 | p25 | **中位** | p75 | p90 | max |
|---|---|---|---|---|---|
| 结构发方块数 | 80 | **114** | 185 | 231 | 386 |
| 发束骨 | 6 | **12** | 24 | 55 | 107 |
| 发占全模型 | 12% | **17.5%** | 26.7% | 34.9% | 60.5% |

**厚度 = 1.00**：22,013 个发方块里 **49.2% 落在 1.00±0.05**，每个模型中位厚度 p25/p50/p75 **全是 1.00**。
（第二峰 2.0–2.25 占 6.5%，是"正面看板、侧面 2 厚"的大发片。）

- **形状**：1.0 厚 × 1.5–2.0 宽 × 3–4 长，**竖长条**（长轴 y 62% / x 22% / z 16%），**92% 带旋转**，相邻差 3–7°
- **两派骨架**：块状派 59%（一根骨 10–40 块）/ 样条派 20%（≥8 根单块骨连链）。
  链深中位 3 段，每束 **16.2 块**，**61% 收尖**（端点宽 = 根 × 0.59）
- **超 250 块就不值了**（p90=231）——再加给发饰或表情
- **刘海**：18–35 块（中位 25，占发量 21%），厚 1.00，跨度 = 头宽 ×1.34，全旋转。
  **露眼关键**：中央那撮最低点只比眼睛上沿低 **0.11 头高**；眼睛被遮率中位 **11%**。
  **98% 没有几何分缝**——中分/侧分画在贴图上
- **细发丝（<0.5）只占 8.5%**，中位模型一片都没有。薄片主要给**五官**
- **发饰**：51% 模型有，中位 38 块、厚 **0.70**（p25 0.29）。**必须挂发束骨**（会跟着甩）
- **贴图**：头发只占已用贴图面积 **10%**，**实质色阶中位 4 个**，**44% 没有 1px 明度阶梯**

### 3.4 面部：鼻子不做，眼睛是"块"不是"片"

| 指标 | 目标 | 依据 |
|---|---|---|
| **眼高 / 脸高** | **28.6%（= 2/7）** | 105 个模型一致 |
| **眼宽 / 脸宽** | **28.6%** | 双眼中缝约占 40% |
| **眼中心高度**（从脸底算） | **0.30** | p25/p75 都是 0.30 |
| 眼睛层数 | **4 层**（55% 用 4–5 层） | |
| 每层 z 深 | **1.0–2.0（块不是片）** | |
| 总凸出 | **0.38**（中位） | |
| 双眼合计块数 | **26–42** | |
| 面部件方块数 | **≥36**（中位；最丰富 168） | |
| 头尺寸 | 7×7×7 ~ 7×8×7 | 头宽中位 7.0 |

- **眉毛永远比眼睛凸**（0.72 vs 0.11）
- **鼻子：0 / 168 个模型建了几何鼻**。纯贴图，**不要建**
- **嘴**：**54% 用几何**，厚 **0.10**，16 块 / 3 骨，位于脸底往上 6.5% 头高，89% 带旋转
- **脸型修形 26%（43/165）**：不是"削下巴"，是**把头劈成镜像斜片**——
  有旋转的 43 个里 **30 个镜像配对率 ≥0.90**。可抄：`lenna` 头 `[3.45,6.98,7.29]` rot z=±15；
  `changchun` 下巴 3 条斜板 rot z=−65/−27.5/−10；`bronya` 颊片 `[1.4,2.8,0.4]` rot y=∓39.7
- **63% 用单块头 + 贴图 + 大量面部件**；37% 额外用旋转方块塑形。共同点：
  **刘海压到眉线、侧发贴颊、眼睛够大**——把方脸棱角盖掉

### 3.5 配饰与特效层

- **配饰**：蝴蝶结/缎带/宝石/蕾丝用 0.1–0.5 薄片；宝石用高饱和小块 + 高光贴图
- **特效层**：159 个模型里 **66% 有特效类部件**，但占比中位只 **2%**（p75 7%）。
  47% 用 `ysmGlow`，28% 带武器几何，13% 带光晕。
  - 普通角色按 **2–7%** 预留特效位
  - 想做出"震撼"效果才堆到 30%+：`爱莉希雅` 1257 骨里 557 空骨（44%），
    特效方块 **68%**（`ysmGlow`×528、`SwordParticle`×165、`Moon`×109…）
  - 特效元素**每个挂独立骨骼**才能单独动画

### 3.6 官方原画对照：强调 vs 省略

**必须强调**：头发体量（占画面 30–40%）、眼睛大小与瞳色、胸腰胯对比、色块对比、腰部配饰群
**降级到贴图**：蕾丝花纹、刺绣、半透明、细绑带、布料褶皱、头发高光
**配色**：主色 **4–6 个** × 每个 **2–3 级明度** + 1 级高光；金/宝石高饱和小块 <5% 面积放视觉焦点

## 4. 贴图

**上色五条**（官方群课程，详见 playbook §7）：
1. **明度**：朝上更亮、朝下更暗；南北较亮、东西较暗
2. **饱和度**：亮部更低、暗部更高；阴影饱和度较低
3. **天光**：阳光亮黄 + 大气蓝 → 亮面偏暖、暗面偏冷、阴影偏冷
4. **AO**：阳角亮、阴角暗
5. **闭塞阴影**：物体根部/缝隙最深，越远越浅

- 尺寸：**512 起步**，精细模型 1024。128 只是模板遗留。
- 有效指标：**texel/块**（中位 99，p90 358）比"贴图尺寸 vs 块数"更能判断贴图够不够
- 纹理色阶：主干部位 **2–3 级明度**；深色叠层 **≥4 级**
- 局部查看 `bb_texture_read({format:"palette"})`；放大核对 `bb_render_texture({scale:12})`
- 涂色 `bb_texture_patch`；整图导入用 `bb_texture_import_png`（先用 PIL 生成设计稿更高效）
- UV：`add_cube` 支持三种写法——省略（自动避让）/ `{mode:"box",offset,size}`（会真正拉伸采样区）/
  `{mode:"faces",faces,sizes}`（逐面精确，做眼/饰必须用这个）
  > `Cube` 上**没有** `uv_size` accessor，box 模式尺寸只能逐面写 `faces[f].uv_size`
- PBR：`bb_texture_pbr` 生成 `_n`/`_s`，需要光影支持

## 5. 自检

**编辑即看**：写操作成功后自动附 `front + iso_fr` 拼图，改完直接看。
更多角度用 `bb_look`（比 `bb_render_views` 省 token）；转台查穿模用 `bb_orbit({steps:8})`；
动画采样用 `bb_anim_check`。

- `review.verdict`：`visible_change` / `visible_change_clipped` / `no_visible_change` /
  `empty_render`。连续 3 次 no-visible-change 触发 no-progress → 先 `bb_restore` 或换策略。
- `edge_touch=true` 说明被裁切，用 `focus` 或调机位。
- 背景透明，不要用"背景色没变"判断失败。
- 规则判定不是 VLM：造型/配色/意图仍要自己看图判断。

**验收清单**（逐条打勾）：
- [ ] `bb_validate` 0 error
- [ ] 方块数 / 旋转占比 / 薄片占比落在现代区间
- [ ] 眼睛 28.6%/0.30、≥4 层、凸出 ≥0.38
- [ ] 头发厚度接近 1.00、发束数 12±、刘海压到眼上沿
- [ ] 裙/衣用了 5 拓扑之一，不是圆环
- [ ] `bb_orbit` 8 角度无穿模
- [ ] 至少 1 个自定义动画
- [ ] 导出 zip + 渲染图

## 6. 动画

- 列表 `bb_animation_list`；新建 `bb_animation_create({name:"animation.main.xxx", length, loop})`
- 关键帧 `bb_animation_patch({ops:[{op:"set_keyframes", animation, bone, channel:"rotation"|"position"|"scale", keys:[{time,value}]}]})`
- 一个 patch 内多 op 共享一个 Undo，失败整体回滚
- 绑定控制器 `{op:"bind_controller", animation, controller:"player.pre_main", state}`
- 动画文件保存时"合并回写"：未改条目/顺序保留，只替换语义变化的动画

---

## 7. 保存 / 导出 / 回滚

- `bb_checkpoint({label})` 内嵌贴图当前像素；`bb_revisions` 列表；`bb_restore({revision, confirm:true})`
- `bb_save_project` 写回 pack（模型/动画/控制器/贴图/ysm.json）
- `bb_export_ysm` 先 validate，产物含 `export-manifest.json` + zip
- `bb_batch` 不是事务，失败不自动回滚

## 8. 用户接管

用户说"我来看看" → 提示 `/show`；窗口显示期间写操作返回 `GUI_BUSY`；
用户 `/hide` 后返回 `user_edits` 摘要，先 `bb_scene` 对账 revision 再继续。

## 9. YSM 约束速查

- **骨骼数量没有上限**（默认模板 64 骨是模板自身的数，不是限制；语料 77% >64，最高 1257）
- 真正的限制：**骨骼嵌套 ≤32 层**（2.6.3 起解除）、网格子级 ≤64、纹理子级 ≤32
- 贴图 ≤**4096×4096**；默认模板 128，社区主流 256，精细 512–2048
- 必需定位组：`Head`/`Body`/`RightArm`/`LeftArm`/`RightLeg`/`LeftLeg`；
  建议加 `RightHandLocator`/`LeftHandLocator`（放在对应 `Hand` 组**里面**）
- 改完模型/贴图必须保存，否则导出的是磁盘旧版本

## 10. 常见错误（全部实测踩过）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 用 `update_bone` 传 `scale` | 空操作，渲染不变 | Blockbench 不支持骨骼缩放，用 `update_cube` 改几何 |
| 用 `delete` 简写不核对 | 静默失效 | 传 `refs:[{kind,id}]`，并检查返回的 `changed[]` 非空 |
