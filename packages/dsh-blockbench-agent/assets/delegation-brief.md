# 子智能体任务书模板（bb_* 插件专用）

> 用法：主代理收到建模/改模型/贴图/动画/检查/导出这类请求时，**不要直接调用 `bb_*`**。
> 按本模板填好，用它 `spawn_teammate`（context=fresh）或 `subagent` 拉起执行者。
> 执行者第一步必须做「promote」：把本任务书补完并复述成可执行计划，再动手。

---

## 给执行者的开场白（原样保留）

```
你是 Blockbench YSM 建模执行者。你的第一步不是动手，而是**完善任务书**。

先调用 skill 工具加载 `blockbench-ysm-artist`（这是作业手册，必须先读）。
然后按「任务书」补全空缺项，输出一份你认为可执行的计划（目标/角色/服装/部件/预算/验收标准/风险），
再开始调用 bb_* 工具。若任务书里有明显矛盾或信息缺失，先在第一步就指出，不要带着矛盾开工。
```

---

## 任务书字段

| 字段 | 说明 | 留空时的默认行为 |
|---|---|---|
| **任务类型** | 新建模型 / 修改现有模型 / 只做贴图 / 只做动画 / 只做检查 / 导出 | 必须填 |
| **目标对象** | 角色名，或现有 pack 目录名 | 必须填 |
| **服装/形态** | 若角色有多套造型，指定哪一套 | 执行者从未确认 → 必须回问或选参考图里最完整的那套并说明 |
| **参考来源** | 已提供的图 / 要执行者自己搜 | 默认自己搜（`bb_ref_search` + `bb_ref_collect`） |
| **质量档位** | 草稿（快，50–120 方块）/ 正式（150–300）/ 精修（300–600，+T2 分层） | 正式 |
| **必须用到** | 指定要用 T1 / T2 / 动画 / 游戏内验证 | T1 必做，T2 视环境与预算 |
| **验收标准** | 例如「validate 0 error + 4 视角渲染 + 导出 zip」 | validate 0 error + 至少 3 视角 |
| **禁止项** | 例如「不要改骨架名」「不要重画贴图」 | 无 |
| **预算上限** | 时间/写操作数上限 | 无上限但要求阶段性汇报 |

## 主代理填写的模板

```
【任务类型】<新建 | 修改 | 贴图 | 动画 | 检查 | 导出>
【目标对象】<角色名 或 现有 pack 目录>
【服装/形态】<指定，或写"执行者判断并说明理由">
【参考来源】<自己搜 | 已提供：<路径或编号> | 不需要参考>
【质量档位】<草稿 | 正式 | 精修>
【必须用到】<T1 分割 / T2 分层 / 动画 / 游戏内验证 / 无强制>
【验收标准】<validate 0 error + N 视角渲染 + 导出 zip ...>
【禁止项】<...>
【预算上限】<...>
【背景】<用户原话与目的，别删减>
```

## 执行者必须遵守的作业顺序

1. **promote**：补全任务书 → 输出可执行计划 → 指出矛盾/缺失
2. **参考**：`bb_ref_search` → `bb_ref_collect` → **真的看对照表** → 写判读结论（哪些是同一角色、什么角度）
3. **spec**：`bb_spec_save` 写可校验规格（部件/骨骼/方块预算/用色/参考索引/gaps）
4. **建模**：按 `plan.order` 建，小步 patch，每次可见改动后看图
5. **贴图**：先查 `bb_scene(scope="uv")` 确认哪些骨骼的 UV bbox 能安全涂色；不安全就逐面精确涂
6. **自检**：`bb_orbit` 多角度 + `bb_validate`
7. **动画/导出**：按验收标准
8. **回报**：产物绝对路径 + 每阶段实测数字 + 与参考的偏差（诚实列"不像的地方"）+ 未完成项与原因

---

## 回报格式（执行者 → 主代理）

```
【结果】成功 / 部分成功 / 失败
【产物】<绝对路径清单>
【实测】<各阶段耗时与关键数字>
【判读】<从参考图得到的角色特征，注明来自第几张图>
【偏差】<哪里不像，按严重程度排序>
【未做】<没做的项 + 原因（不许写"时间不够"就完事，要写清缺什么条件）>
【发现的问题】<工具 bug / 流程坑 / 数据缺口>
```

## 反面清单（这些做法都是错的）

- ❌ 主代理自己 `bb_apply_model_patch` 改模型，只让子智能体"看看"
- ❌ 子智能体跳过 `bb_ref_collect` 直接按记忆建模
- ❌ 收集了对照表但不看，直接写 spec
- ❌ 用骨骼 bbox 大面积涂色而不检查 `bb_scene(scope="uv")` 的 `unsafe_bboxes`
- ❌ 报告里把"没做"说成"做了"
- ❌ 用 `update_bone scale` 试图改体量（不支持，会报 UNSUPPORTED_FIELD）
- ❌ 用 `delete` 简写后不核对 `changed[]` 是否真的非空
