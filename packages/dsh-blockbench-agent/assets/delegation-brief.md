# 子智能体任务书模板（bb_* 插件专用）

> 用法：主代理收到建模/改模型/贴图/动画/检查/导出这类请求时，**不要直接调用 `bb_*`**。
> 按本模板填好，用它 `spawn_teammate`（context=fresh）或 `subagent` 拉起执行者。
> 执行者第一步必须做「promote」：把本任务书补完并复述成可执行计划，再动手。
> 设计规范在 `skills/blockbench-ysm-artist.md`；统计口径在 `reference/ysm-corpus-rules.md`；
> Blockbench 操作在 `reference/blockbench-ysm-playbook.md`。**执行者开工前必须 read 这三份。**

---

## 给执行者的开场白（原样保留）

```
你是 Blockbench YSM 建模执行者。你的第一步不是动手，而是**完善任务书**。

先调用 skill 工具加载 `blockbench-ysm-artist`（作业手册，必须先读），
再读 `reference/blockbench-ysm-playbook.md`、`reference/ysm-corpus-rules.md`（按需查数字）、
以及本任务书。然后按「任务书」补全空缺项，输出一份你认为可执行的计划
（目标/角色/服装/部件/比例目标/方块预算/贴图尺寸/参考策略/分部件检查计划/验收标准/风险），
再开始调用 bb_* 工具。若任务书里有明显矛盾或信息缺失，先在第一步就指出，不要带着矛盾开工。
```

## 任务书字段

| 字段 | 说明 | 留空时的默认行为 |
|---|---|---|
| **任务类型** | 新建模型 / 修改现有模型 / 只做贴图 / 只做动画 / 只做检查 / 导出 | 必须填 |
| **目标对象** | 角色名，或现有 pack 目录名 | 必须填 |
| **服装/形态** | 若角色有多套造型，指定哪一套 | 执行者从未确认 → 必须回问或选参考图里最完整的那套并说明 |
| **参考来源** | 已提供的图 / 要执行者自己搜 | 默认自己搜（`bb_ref_canon` → `bb_ref_search(depth:"deep")` → `bb_ref_collect`），并**逐格判读** |
| **质量档位** | 粗犷（100–400 块）/ **标准（400–900，默认）** / 精细（900–2500）/ 分层精细（2500+，需 T2） | 标准 |
| **分层要求（T1/T2）** | 标准档：**T1 必做**（`bb_seg_probe` → `bb_seg_lite` → 用部件清单做逐部件检查）；精细档：T1 必做 + 若 `probe` 显示 T2 可装则 T2 必做；粗犷/无环境：可降级，但**必须在报告写原因** | 标准档 T1 必做 |
| **必须用到** | 动画 / 游戏内验证 / 无（分层项固定按上一条执行） | 动画至少 1 个 |
| **验收标准** | 默认：`bb_validate` 0 error + 8 组分部件检查（§6）+ `bb_orbit(8)` + 4 视角 768 成品图 + 导出 zip | 见左 |
| **禁止项** | 例如「不要改骨架名」「不要重画贴图」「禁止模板换色」 | 无 |
| **预算上限** | 写操作/渲染次数上限（session 默认 edits 60 / renders 40 / restores 2） | 无上限但要求阶段性汇报 |


## 执行者必须遵守的作业顺序

1. **promote**：补全任务书 → 输出可执行计划 → 指出矛盾/缺失；先 read 三份配套文档
2. **官方基准**：`bb_ref_canon({character})` —— 拿百科外观描述 + 官方图 + 罗马音；**先看官方图确认角色长什么样**
3. **深搜与对照**：`bb_ref_search({depth:"deep", romaji})` → `bb_ref_collect` → **逐格真看**，
   错角色/错皮肤/AI 图剔除并在 `spec.references.images` 写判读
4. **立绘拆分（T1/T2）**：按【分层要求】执行；T1 部件清单 + 占比数字用于 spec 与逐部件检查；
   拆分不可用时改人工裁切判读，并记录
4b. **参考模型实证（眼睛/头发/角必做）**：按 skill §2.7 打开 2–5 个同风格参考模型（最小 YSM 包）
   → 2400² 渲染 front/iso/back → 读对应骨骼 cube 数据 → 把渲染图上每一层与方块一一对应；
   统计数字不能代替这一步（眼睛层序/眼距/头发底发帽/角旋转轴都必须这样确认）
5. **spec**：`bb_spec_save` 写可校验规格（部件/骨骼/比例目标/方块预算/用色/参考索引/gaps）
6. **开项目**：`bb_session_start(mode:"new_ysm", pack_dir:"pack", resolution:[512,512])`；
   先清空示例模型 cubes、处理模板骨骼 rest rotation（见 skill §2.6）
7. **建模**：按 `plan.order` 建，小步 patch，每次可见改动后看图（`bb_look` isolate/zoom）
8. **贴图**：先 `bb_scene(scope:"uv")` 确认 `unsafe_bboxes`；按"纯色分档/不每块渐变"上色
9. **逐部件检查（强制 Gate）**：按 skill §6 的 8 组 `isolate` 检查，逐组记录差异与判定
10. **整体自检**：`bb_orbit(8)` + 缩略剪影 + 反模板检查（骨架/部件来源/UV 是否只是换色）
11. **出厂**：`bb_validate` → `bb_save_project` → `bb_export_ysm` → 4 视角成品图
12. **回报**：产物绝对路径 + 每阶段实测数字 + 与参考的偏差（诚实列"不像的地方"）+ 未完成项与原因 + 分部件检查表

---

## 回报格式（执行者 → 主代理）

```
【结果】成功 / 部分成功 / 失败
【产物】<绝对路径清单：pack、zip、渲染图、spec>
【实测】<骨骼/方块/贴图/动画数、各阶段耗时、validate 输出摘要、预算消耗>
【判读】<从参考图得到的角色特征，注明来自第几张图（对照表编号）>
【分部件检查】<8 组：部件 | 隔离图路径 | 参考依据 | 差异 | pass/minor/major>
【偏差】<哪里不像，按严重程度排序>
【未做】<没做的项 + 具体原因（不许写"时间不够"就完事）>
【发现的问题】<工具 bug / 流程坑 / 数据缺口>
```

## 反面清单（这些做法都是错的）

- ❌ 主代理自己 `bb_apply_model_patch` 改模型，只让子智能体"看看"
- ❌ 子智能体跳过 `bb_ref_canon`/`bb_ref_collect` 直接按记忆建模
- ❌ 收集了对照表但不看，直接写 spec
- ❌ **跳过立绘拆分（T1）而不在报告说明**
- ❌ 只做全身渲染、不做分部件 isolate 检查（至少 8 组，见 skill §6）
- ❌ 交付"模板换色"：拿现成模型换贴图/改色冒充建模
- ❌ 用骨骼 bbox 大面积涂色而不检查 `bb_scene(scope:"uv")` 的 `unsafe_bboxes`
- ❌ `delete` 之后不核对 `changed[]` 就继续
- ❌ 用 `update_bone scale` 试图改体量（现在会硬报错 `UNSUPPORTED_FIELD`）
- ❌ 每块发片各画一段渐变（会"一条条闪"）
- ❌ 角/兽耳等辨识件不检查"是否超出头发包围盒"就交付
- ❌ 眼睛只做"方板 + 菱形"：眼距 ±2.3、无上眼线/外眼角/四角小片（见 skill §4.2）
- ❌ 角只绕 Z 轴做成正面 C 形（必须绕左右轴 X 的参数化螺旋，见 skill §4.4）
- ❌ 头发用 2 块大平板当顶盖（必须 20–80 小板底发帽 + 附属束，见 skill §4.3）
- ❌ 报告里把"没做"说成"做了"
