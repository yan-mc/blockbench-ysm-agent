# YSM 模型语料实测规则

> 来源：`材料/03-语料/` 共 **181 个真实社区模型**（82 个 YSM 资源包 + 99 个 .bbmodel），
> 提取脚本 `tools/mine_corpus.py` / `tools/mine_deep.py` / `tools/mine_profile.py`，
> 原始数据 `材料/_dataset.json`。
>
> **用途**：给"这个模型该做多大、骨骼怎么起名、贴图开多大"提供**有依据的默认值**，
> 替代凭感觉估。标注 `[实测]` 的是语料统计，标注 `[文档]` 的是 YSM 官方说明。

---

## 0. 先分清"硬约束"和"实测值"（血泪教训）

我曾把"默认模板有 64 根骨骼"误当成"YSM 限制 64 根骨骼"，并据此砍掉了该加的 Locator。
**这类错误比不会建模更贵，因为它会让你主动做错决定。**

| 项 | 结论 | 依据 |
|---|---|---|
| 骨骼**数量**上限 | **无** | `[实测]` 77% 的模型 >64 骨，中位 83，最高 **451** |
| 骨骼**嵌套层数** | ≤ **32** 层（YSM 2.6.3 起解除） | `[文档]` Modrinth 更新日志 "Removed the 32-layer nesting limit" |
| 贴图分辨率 | ≤ **4096×4096**（2.2.2 起） | `[文档]` mcmod 版本说明 |
| 模型包体积 | 1.2.0 起取消 2MB 限制，但仍不建议过大 | `[文档]` 同上 |
| 默认模板骨架 | 64 bones / 172 cubes / 30 空骨（26 Locator） | `[实测]` 本项目 `docs/05` |

**规则**：任何"上限/限制"的说法，先去 `材料/03-语料/` 里找反例。找到反例就是判断错了。

## 1. 标准骨架层级 `[实测]`

人体类模型的高频父子边（括号内为出现率，样本 181）：

```
Root
└─ AllBody                       (44%)
   ├─ UpBody                     (54%)
   │  └─ (躯干骨骼)
   │     ├─ AllHead              (41%) → Head (41%)
   │     │  ├─ Eyelid            (41%) → RightEyelid / LeftEyelid
   │     │  └─ Hair / Face / …
   │     └─ Arm                  (54%)
   │        ├─ RightArm          (54%) → RightForeArm (53%) → RightHand (49%) → RightHandLocator (54%)
   │        └─ LeftArm  (54%) → LeftForeArm (54%) → LeftHand (49%) → LeftHandLocator (54%)
   └─ DownBody                   (54%)
      ├─ LeftLeg  (41%) → LeftLowerLeg (52%) → LeftFoot (47%)
      └─ RightLeg (41%) → RightLowerLeg (52%) → RightFoot (50%)
```

**要点**
- `Root` 是唯一根；`AllBody` 是人体总控；`UpBody`/`DownBody` 分上下半身。
- 手、脚必须有 `*Locator` 作为挂点（见 §4），**不是可选装饰**。
- 模型层级深度中位 **10–11 层**（13% 在 10 层、17% 在 11 层）；超过 20 层的多是兽形/机械。

**命名反例**：`bone`、`bone2`、`bone3`… 是 Blockbench 自动命名，出现率高达 54%。
这不是风格，是**没改名的导入品**。做正式模型时不要沿用——骨骼名会进动画，
改名的模型在二次编辑/动画迁移时明显更好用。

## 2. 方块预算与竖向分布 `[实测]`

样本 **114 个模型 / 44,072 个方块**。

| 指标 | 数值 |
|---|---|
| 方块总数 中位 | **306** （四分位 153 / 503） |
| 骨骼数 中位 | 83 |
| 方块 / 骨骼 | **4.9** |
| 头部区域（Y ≥ 32）方块占比 中位 | **33.2%** |

竖向分段（YSM 人体，脚底 Y=0、头顶约 Y=37）：

| 区段 | Y 范围 | 占比 | 含义 |
|---|---|---|---|
| feet | 0–3 | 4.6% | 鞋/脚 |
| lower_leg | 3–12 | 11.1% | 小腿/袜子 |
| upper_leg | 12–21 | 17.6% | 大腿 |
| hip_waist | 21–25 | 10.9% | 臀/腰/裙摆 |
| torso | 25–32 | 17.0% | 躯干/外套 |
| **neck_head** | **32–40** | **19.8%** | 颈/头/脸/发 |
| **above_head** | **40+** | **18.2%** | 呆毛/头饰/帽/发梢 |
| 越界 | — | 0.8% | 坐骑/道具 |

### 这条数据怎么用

**成品感主要来自头部。** 头部 + 头顶以上 = **38%** 的方块，
而新手常把头部压到 10–15% —— 这就是"看起来像方块人而不是角色"的根本原因。

实操建议：
1. 先按总数 306 起手，头部（含发）预留 **35–40%**，即 **110–120 个方块**。
2. 头发是头部里最值得投入的部分：分出前发/侧发/后发/呆毛四组，
   前发再做 3–5 缕不等长的发片。
3. 裙/披风落在 `hip_waist`+`torso` 区间；披风类模型这一带占比会明显高于 11%。

> 参照：本项目 `sakiko-final` 是 196 方块、头发 24 块（12%），
> 低于语料中位，这是它"细节够但还不够成品"的量化原因。

## 3. 贴图尺寸怎么选 `[实测]`

223 张贴图的边长分布：

| 边长 | 占比 | 适用 |
|---|---|---|
| **512** | **35.0%** | 主流；脸部细节、眼睫毛、小配饰都够 |
| 128 | 21.5% | YSM 默认模板尺寸；只适合极简风格 |
| 256 | 19.3% | 性价比高，中小型角色够用 |
| 64 / 32 | 17.5% | 道具/坐骑/像素风 |
| 1024+ | 2.2% | 高精模型 |

**规则**
- **默认开 512×512**。128 是模板遗留，不是标准答案；本项目曾一直用 128，
  导致眼睛只有 2×2 像素，这是过早妥协。
- 贴图放大后 UV 布局要重排（`bb_apply_model_patch` 的 `set_uv` 支持显式 `uv_size`）。
- 上限 4096²，但超过 1024 对像素模型收益很小，反而拖慢渲染。

## 4. Locator 挂点清单 `[实测]`

| Locator | 出现率 | 用途 |
|---|---|---|
| `RightHandLocator` / `LeftHandLocator` | **62%** | 手持物品/武器，**最应该加** |
| `ElytraLocator` | 7% | 鞘翅 |
| `RifleLocator` / `PistolLocator` | 7% | TAC/永恒枪械 |
| `ViewLocator` | 3% | 视角挂点 |
| `LeftWaistLocator` / `RightWaistLocator` | 1% | 腰间挂件 |
| `BladeLocator` / `SheathLocator` | 1% | 刀/刀鞘 |

只有 `RightHandLocator` / `LeftHandLocator` 是"不做就会后悔"的，
其余按角色需要加。**它们不占方块，只是空骨骼**，成本极低。

## 5. UV 模式 `[实测]`

| 来源 | box UV | per-face UV |
|---|---|---|
| YSM 资源包（bedrock main.json） | 38% | **62%** |
| .bbmodel 工程 | **100%** | 0% |

- 成品包**多数用 per-face**：因为逐面能精确控制贴图区域，便于在有限空间里塞细节。
- Blockbench 工程默认 box UV（`box_uv: true`），导出后可能被转成逐面。
- **切换判据**：需要"贴图局部高亮/眼睛单独定位/不对称贴图"时，改 per-face。

## 6. 建模检查清单（按语料中位反推）

做完一个角色模型，对照自查：

- [ ] 方块总数在 250–500 区间？（中位 306）
- [ ] 头部区域（Y≥32）占 35–40%？
- [ ] 头发分成前/侧/后/呆毛 ≥4 个骨骼组？
- [ ] `Root → AllBody → UpBody/DownBody` 骨架完整？
- [ ] 手/脚有 Locator？
- [ ] 贴图 ≥256，推荐 512？
- [ ] 骨骼名有语义（不是 `bone12`）？
- [ ] 层级深度 < 20？
- [ ] 头部贴图区域够画眼睛（512 贴图下眼睛可占 4–6 像素）？
