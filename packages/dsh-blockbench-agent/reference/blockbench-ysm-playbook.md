# Blockbench / YSM 建模操作规范（工具操作层）

> **职责边界**：本文件只讲 **Blockbench / YSM 的格式、操作与交付**（骨架、命名、填缝、inflate、贴图、arm、MoLang）。
> **造型、流程、设计方法与验收** 见 `skills/blockbench-ysm-artist.md`；**统计数字** 见 `reference/ysm-corpus-rules.md`。
> 来源：官方说明书、官方群思维导图课程、社区教程、169 个现代语料工程实测、2026-11-07 十三轮实战复盘。

---

## 0. 开工前铁律

1. **在世界中心建模**：模型正面朝北，对称轴落在世界轴线上（否则镜像/对称绘画全废）。
2. **尺度用规范值**：长宽高小数位落在 `.25 / .5 / .75`，尽量能被 5 整除。
3. **避免混素**：16x 项目 1 格 = 1 像素；32x 项目 0.5 格 = 1 像素。方块尺寸不要小于"1 像素对应的模型尺寸"，否则贴图必糊。
4. **贴图前**确认没有隐藏/锁定的方块；**导出前**确认没有方块被误关。
5. **有意识地分组**：边建模边分层，别事后补。
6. **`new_ysm` 不是空模板**：会带出完整示例模型（70 bones / 172 cubes / 303 animations），开项目后先清空 cubes 再建模。
7. **模板骨骼带非零 rest rotation**（Ribbon / FrontSkirt / BackSkirt / Collar / SideSkirt / Arms / Breast 等）：
   按世界坐标 `add_cube` 会被带偏，先 `bb_scene(scope:"bones")` 读 rotation 再决定清零或按局部坐标计算。

## 1. 四种模型格式（先选对）

| 格式 | 限制 | 用途 |
|---|---|---|
| **基岩版** | 旋转/尺寸无限制，单项目只能一张贴图 | **YSM 用这个** |
| java | 3×3×3 方块上限；每方块单旋转轴；角度只能 22.5° 倍数 | 原版/模组 |
| 皮肤 | 16x / 32x | 玩家皮肤 |
| 自由模型 | 有网格体时只能用这个，不能转出 | 动画短片 |

YSM 支持：基岩 **1.12.0 模型** + **1.8.0 动画**（geckolib 内核）。

---

## 2. 造型：用"概括"不要用"雕"

三种流派：**概括**（少块数 + 贴图补细节，推荐）、**狠狠雕**（海量小块，新手陷阱）、**体素**。

**块数由档位决定**（详见 skill §3.1）：粗犷 100–400 / 标准 400–900 / 精细 900–2500 / 分层精细 2500+。
> 旧版本文"人物 50–300 块、超 500 要停"是女仆模组时代的数据，已作废；现代语料人物中位 744 块。

**节约块数的手段**：面片、橡皮擦（把方块擦成异形）、拼块。

---

## 3. 边角：填缝 + inflate

棱台转角不处理会"缺一块"。

**方法一（优先）**：化简为两块重叠，用整体旋转代替多处局部旋转，材质交给贴图。避免过多阶梯。

**方法二（大结构才用）**：
1. 复制朝向合适的元素
2. 正对视角旋转，直到外边缘与相邻面平行（`Ctrl+左键` / `Ctrl+Shift+左键` 微调角度）
3. **顶点捕捉（`X` 键）** 到下顶点
4. 夹角另一面同理
5. 小块补边，或大块填完用橡皮擦掉多余贴图
6. **`inflate` 修面重叠：`+0.01 ~ +0.005`**（太大凹凸明显，太小远处仍叠）

**`inflate` 的两种用法**：

| 值 | 用途 |
|---|---|
| `+0.01 ~ +0.005` | 外撑遮接缝、防 z-fighting |
| `−0.01` | 内收，避免相邻方块面重叠穿模 |

> 规则：只要两个面会共面或近乎共面，就动 inflate。
> **不要**用大幅 inflate 当圆角——那会让方块边缘发虚。

*z-fighting = 重面现象：两面叠在一起时软件不知显示哪个，会闪烁出锯齿。*

## 4. 标准骨架与命名

```
Root
└─ AllBody
   ├─ DownBody            ← 本身带方块（臀/裙摆）
   │  ├─ LeftLeg → LeftLowerLeg → LeftFoot → LeftSole/LeftShoe/LeftSock
   │  └─ RightLeg → …
   └─ UpBody              ← 本身带方块
      └─ UpperBody        ← 细节层：外套、领子、胸饰
         └─ AllHead → Head
            ├─ Eyes → Eyelid → Left/RightEyelid → …Base → EyesDot / Pupil
            ├─ Eyebrow → Left/RightEyebrow
            └─ Hair / Face
```

**部件命名后缀**：`Base`（底）、`Dot`（眼白点）、`Sole`（鞋底）、`Shoe`、`Sock`。

**官方命名规范**：
1. 大写驼峰 + 形容词+名称：`LeftArm`、`AllHead`
2. 简洁：用 `All` 不用 `Whole`；用 `Eyes` 不用 `HeadEyes`
3. 无意义分组用"父类+数字"：`Mouth1`、`Mouth2`

**不可改名的特定组**：

| 组名 | 原因 |
|---|---|
| `Head` | 游戏自动加"头部随视角摆动"动画（不想要就改名） |
| `LeftHand` + `LeftHandLocator` | 左手持物定位；**Locator 必须在 `LeftHand` 里面** |
| `RightHand` + `RightHandLocator` | 同上 |

> 模板是 70 骨（不是 64，64 是旧数据）；**骨骼数量没有上限**，按需要自由加骨（语料中位 114、最高 1257）。

## 5. 眼睛：结构事实（做法见 skill §4.2）

现代语料实测（166 个模型）+ 2026-11-08 逐模型核对（zhe_2/kaltsis/yujin/shazhi/甘雨/doggo）：

| 项 | 值 |
|---|---|
| 眼高 / 脸高 | **20–26%**（1.3–1.8 / 脸 6–7；旧值 28.6% 偏高） |
| 眼宽 / 脸宽 | **28–31%**（2.0–2.2 / 脸 6–7） |
| 双眼中缝（内缘间距） | **20–24% 脸宽**（眼中心 ±1.76；旧派 doggo 41% 偏宽） |
| 眼中心高度（从脸底算） | **0.30** |
| 眼白板 | **1 块大平面，2.0–2.2×1.3–1.8×0.30，只凸出脸面 0.02–0.07** |
| 虹膜/瞳孔 | 2–34 个小片叠层，厚 0.03–0.4，凸 0.03–0.15 |
| 上眼线 | 2–12 片细斜板沿弧排，**凸 0.3–0.7（眼睛最凸处）** |
| 下睑/眼影 | 薄片，**凹 0.15（在脸内）** |
| 双眼合计块数 | **26–44**（单眼中位 17、p25 8；标准档 16–22 块也成立） |
| 眉毛 | 2–9 片递减旋转，凸 0.15–0.72 |
| 鼻子 | **0 / 168 个模型建模** —— 纯贴图，不要建 |
| 嘴 | 54% 用几何，厚 **0.10**，16 块 / 3 骨 |

> 做法（平板眼白 + 小片叠层 + 上眼线/外眼角/四角小片切角）见 skill §4.2。**不要**把眼睛画在高清贴图上当主力（82% 眼部方块是纯色）。
> 旧版"4 层、总凸出 0.38、眼白就是 2.0×1.36×1.00"的叙事已作废：0.38 是上眼线口径，眼白本身只凸 0.02–0.07。

## 6. 头发：两条路线

| 路线 | 做法 | 适用 |
|---|---|---|
| **块状派**（59%） | 一根骨 10–40 块，贴图分层 | 多数情况 |
| **样条派**（20%） | ≥8 根单块骨连成链，配 `parallel` 动画 | 要动态摆动 |
| **贴图分层** | 少方块 + 贴图画出层次 | 省资源 |

硬约定与具体做法见 skill §4.3（**底发帽 20–80 小板 + 附属束各自成组**、等粗条带、厚度一档、刘海两层、后发分组、发色分档）。
速记：**发片厚 1.00 是标准档默认**（底发帽可用 0.5–0.8 薄板）；头发占方块 ~17.5–35%、是第二大件；发饰必须挂发束骨。
❌ 两块 8×8 大平板当顶盖 → 45°/背面露头皮（祥子 v3 前的根因）。

## 7. 贴图与色彩（最容易翻车的地方）

### 尺寸
- 新项目 **512**（模板默认 128 必须改）；精细/特写 1024；语料社区主流 256（下限参考）。
- 128 贴图配 400+ 方块会逼近 UV 饱和（实测某模型 96.6%）。
- YSM 上限 4096×4096；**不建议半透明贴图**（会渲染错误）。
- 有效指标：**texel/块**（语料中位 99、p90 358）。

### 混素
16x：1 格 = 1 像素；32x：0.5 格 = 1 像素。方块别小于 1 像素对应的尺寸。

### 明暗五区
亮面 / 灰面 / 暗面 / **明暗交界线**（方体暗部棱线）/ 反光区 / **闭塞阴影**（无光进入的缝隙）。
阴影：距根部近则深且硬，远则浅而软。

### AO
阳角亮、阴角暗。

### 色彩三要素应用
| 要素 | 规则 |
|---|---|
| 明度 | 朝上面更亮、朝下面更暗；朝南北较亮、朝东西较暗 |
| 饱和度 | **亮部更低、暗部更高**；阴影饱和度较低 |
| 色相 | 色环无极相接，不必纠"算蓝还是绿" |

### 天光设定
默认在天光下绘制：阳光亮黄 + 大气蓝 + 地面漫反射 → **亮面偏暖、暗面偏冷、阴影偏冷**。

### 自发光
自发光零件会影响周围：车灯是亮黄，附近颜色应"变亮变黄"。

## 8. YSM 交付物

### 必需三件
`main.json` + `arm.json` + 任意一个 PNG。文件夹/贴图名只能**小写英文、数字、下划线**。

### arm.json 五步
1. 复制主模型文件
2. 把 `LeftArm`、`RightArm` 复制到根目录
3. 删除整个 `Root`
4. 粘贴两个 Arm
5. 把两者的 X/Y/Z 旋转归零（内部分组不动），手臂应垂直向下

根目录下建 `Background` 组 → 第一人称渲染为背景。
> 当前 `bb_*` 工具没有"切换工程 tab"的 API，`arm.json` 只能沿用模板几何；报告里必须如实说明。

### 动画槽位（`main.animation.json`）
`walk` `run` `climbing` `sneaking` `sneak` `swim` `swim_stand` `attacked` `jump`
`fly` `boat` `use_righthand` `use_lefthand` `sleep` `ride` `ride_pig` `sit` `idle`

- **并行动画** `parallel0`–`parallel7`：与主动画独立同时播放，**优先级更高**（同骨骼冲突时覆盖主动画）。放 `main.animation.json`。
- **额外动画** `extra0`–`extra7`：放 `extra.animation.json`，用轮盘（Z 键）播放。

## 9. MoLang 必备片段

**显示/隐藏部件**（缩放归零即隐藏）：
```
ysm.has_helmet ? 1 : 0
```

**长发不穿身**（抬头抵消、低头随头）：
```
(ysm.head_pitch > 0) ? -ysm.head_pitch : 0
```

**常用变量**：`ysm.head_yaw` `ysm.head_pitch` `ysm.has_helmet` `ysm.has_chest_plate`
`ysm.has_leggings` `ysm.has_boots` `ysm.has_mainhand` `ysm.has_offhand`
`ysm.is_close_eyes` `ysm.is_passenger` `ysm.is_sleep` `ysm.is_sneak`
`ysm.armor_value` `ysm.hurt_time`

完整占位符清单见 `docs/10-Blockbench与YSM教程精要.md` §13。

## 10. 渲染与工具选择（实测）

| 需求 | 用哪个 | 注意 |
|---|---|---|
| 单部件、少角度 | `bb_look({isolate, zoom, cells})` | 最省 token；`isolate` 会包含子骨骼 |
| 多角度/高分辨率/成品图 | `bb_render_views({views, size, antialias, isolate, zoom})` | `isolate` 支持逗号多部件（与 `bb_look` 一致）；`closeup` 单独一批 |
| 连续机位/固定视角接力 | `bb_camera` | `focus` 只接受元素名，不能给坐标 |
| 穿模/对称检查 | `bb_orbit({steps:8})` | 450–800 token |
| 动画动作检查 | `bb_anim_check` | 4–16 帧采样 |
| 贴图像素放大 | `bb_render_texture({scale:8~12})` | 也可 `bb_texture_read({format:"palette"})` |

- 渲染后 `bb_render_views` 按视图名落盘，**多次 isolate 会互相覆盖**：每次立刻改名归档。
- `closeup` 与其他视图同批会污染整批取景；`focus.padding` 只改对焦点/留白、不改变缩放；要真特写用 `isolate`+`zoom` 或高分辨率渲染后本地裁图。
- 渲染预算：写操作自动附图也计入 renders；定点小改时 renders 应多于 edits（实测 6 写 / 21 渲染）。
