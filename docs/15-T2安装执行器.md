# 15 · T2 安装执行器

> 目标：让「想用完整分层」的用户**一条命令**装好 ComfyUI + See-through，且中断可续、失败可诊断。
> 状态：已实现；本机实测安装流程见 §5。

---

## 1. 为什么不打包、而要"安装"

| 方案 | 问题 |
|---|---|
| 把 ComfyUI 打进插件 | 插件包 2GB+，GitHub 仓库放不下，别人 clone 会被吓跑 |
| 依赖用户手动装 | 新用户门槛极高：Python 环境、torch 版本、custom_nodes 路径、模型放哪 |
| **内置安装器，运行时下载** | 插件本体仍只有几百 KB；装不装由用户决定 |

所以 T2 走「**安装器 + 运行时下载**」，这与 T1 下载 SAM2 模型、ComfyUI 节点首次运行拉权重是同一条策略线。

---

## 2. 步骤（幂等、可续）

| 步骤 | 产物判据 | 说明 |
|---|---|---|
| `download-comfy` | `ComfyUI_windows_portable_nvidia.7z` 存在且 >1KB | 流式写入 `.part` 再 rename，避免半截文件被当成完整 |
| `extract` | `ComfyUI_windows_portable/` 存在 | 用 Windows 自带 `tar`（bsdtar 支持 7z）；不支持时明确提示手动解压 |
| `verify-comfy` | `ComfyUI/main.py` 存在 | 解压布局不对就立刻失败，不带病往下走 |
| `install-node` | `custom_nodes/ComfyUI-See-through` 存在 | 优先 `git clone --depth 1`；git 不可用则退回 zip 下载 + 解压 + 改名 |
| `install-deps` | 能跑通 pip | 用**便携版自带的 python_embeded**，不需要用户装 Python |
| `first-run` | — | **不在安装时做**：权重由节点首次跑分层时自行从 HF 拉 |

**每步先检查产物再动手** —— 所以中断后重跑会从断点继续，不会重复下载 1.8GB。

---

## 3. 工具接口

```
bb_seg_install({ confirm:false })   # 默认：只返回计划 + 当前安装状态
bb_seg_install({ confirm:true })    # 真装（约 3.8GB 下载 + 解压 + pip）
```

返回体带 `steps[{id, ok, detail}]`，失败时能直接看出卡在哪一步，并保留已完成部分。

装完返回：

```jsonc
{
  "paths": {
    "startCommand": "\"...\\python_embeded\\python.exe\" -s \"...\\ComfyUI\\main.py\" --listen 127.0.0.1 --port 8188",
    "comfyUrl": "http://127.0.0.1:8188"
  }
}
```

**还需要用户做一步**：用 `startCommand` 启动 ComfyUI（保持运行），并把 `comfyUrl` 写进插件配置。
这一步没有自动化，因为长期驻留的后台服务不该由建模插件悄悄拉起。

---

## 4. 为什么超时设成 1 小时

`bb_seg_install` 的 `timeout_ms` 是 `3600000`。原因：1.8GB 下载 + 解压 + 2GB pip
在慢网/机械盘上可能 30 分钟以上。设短了会误判失败。

同时也提供**命令行入口** `test/run-seg-install.mjs`，走同一套 `lib/seginstall.js`，
适合在后台跑（本机实测就是这么跑的，避免长时间占用工具调用）。

## 5. 本机实测（完整跑通）

| 项 | 值 |
|---|---|
| 平台 | Windows x64 / RTX 4080 Laptop 12GB |
| 磁盘余量 | 227GB → 220GB |
| 下载体积 | ComfyUI 便携版 **1959MB**，约 15MB/s |
| 解压 | **125s**，解开后 **4.59GB / 70802 文件** |
| 节点 | `git clone` **4s** |
| pip 依赖 | **39s** |
| **总耗时** | **约 168s**（含续传，不含权重） |
| ComfyUI 版本 | **0.44.0**，PyTorch **2.14.1+cu130** |
| See-through 节点 | **7 个全部加载**（LoadLayerDiffModel / LoadDepthModel / GenerateLayers / GenerateDepth / PostProcess / SavePSD / PartsToLayers） |

安装后 `bb_seg_probe` 状态：

```jsonc
"comfy": { "reachable": true, "comfyVersion": "0.44.0",
           "devices": [{ "name": "cuda:0 NVIDIA GeForce RTX 4080 Laptop GPU", "vramFree": 11600396288 }] },
"tiers": { "t1": { "ok": true, "ready": true }, "t2": { "ok": true } }
```

### 5.1 实测抓到一个真缺陷：下载不支持续传

第一次跑安装时，后台进程被上游管道提前关闭，留下 **1950.8MB 的 `.part`**（比完整少 8.2MB），
`tar -tf` 直接 `Seek error`。

原实现每次中断都要重下 1.9GB。已修：`download()` 支持 **HTTP Range 断点续传**——

- `.part` 存在则读其长度，发 `Range: bytes=N-`
- 服务端回 `206` → 追加写；回 `200` → 从头下
- 收完后校验总长（误差 <1% 才算成功），不完整则**保留 `.part` 供下次续传**

修完重跑：**1.8 秒补完 8MB**，立即通过。

## 6. 边界

- **只覆盖 Windows**：ComfyUI 便携版只发 Windows。Linux/macOS 走手动安装，
  `bb_seg_probe` 会明确说明并判 T2 不可用。
- **不管非 N 卡**：产品决策是"管不了就明说"，探测层已经拦掉。
- **不启动服务**：装完需要用户自己起 ComfyUI；插件不会偷偷拉起常驻进程。
- **不校验 GPU 驱动/torch 版本**：便携版自带匹配好的 torch，省掉这个经典坑。
