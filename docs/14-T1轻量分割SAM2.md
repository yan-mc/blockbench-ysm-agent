# 14 · T1 轻量分割（SAM2 ONNX）

> 目标：不装 GPU 大管线也能把立绘**切成部件**，用于建模后逐部件对照检查。
> 状态：**已实现并实测通过**（真实工具路径，7.6 秒 / 9 部件 / 354 token）。

---

## 1. 为什么不用 Node 原生依赖

原计划是 `onnxruntime-node`，实际评估后否决：

| 方案 | 体积 | 跨平台风险 | 结论 |
|---|---|---|---|
| `onnxruntime-node`（原生模块） | 100–200MB | 高（各家 Node/Electron ABI 不同，装了还可能要重编译） | ❌ |
| `onnxruntime-web`（WASM） | 30–140MB，算子覆盖窄（int8 量化易缺算子） | 中 | ❌ |
| **Python + `onnxruntime`** | **约 15MB** | **低（DSH 自带 Python，最坏情况 pip install）** | ✅ |

所以架构是：**插件 spawn Python 子进程**，用 JSON 通信。
边界清晰、失败不影响宿主、跨平台稳。

## 3. 关键实现细节（踩过的坑）

### 3.1 多点是「同一个物体」的多个正样本

模型签名：`input_points` 形状 `(batch, 1, num_points, 2)`，第二维固定为 1。
输出 `iou_scores` 形状 `(batch, 1, 3)` —— **`num_boxes_or_points` 是 1，不是 N**。

也就是说：一次推理里塞 N 个点，得到的是「把这 N 个点当成同一物体」的**一个**掩膜，
不是 N 个物体。

**正确做法**：沿 **batch 维**放不同点，每个 batch 元素各含 1 个点：

```python
pts = chunk[:, None, None, :]            # (B,1,1,2)
feeds["image_embeddings.k"] = np.repeat(embeds[k], B, axis=0)
```

### 3.2 性能实测（CPU，int8）

| 阶段 | 耗时 |
|---|---|
| 加载 + 预处理 | ~1s |
| vision encoder（1024²） | **0.6s** |
| decoder（144 点 / 9 批） | 6.5s（每点约 19ms） |
| **合计** | **约 8s** |

对小图（255×390）完全够用，不需要 GPU —— 这正是 T1 与 T2 的分界。

### 3.3 过滤：不滤会得到一堆碎块

144 个提示点 → 144 个候选掩膜。不处理的话：
- 有一个覆盖 79% 的「整图」掩膜（背景/整体）
- 大量低置信度（iou 0.1 级）噪声
- 同一物体被多个点重复命中

三步过滤：

| 步骤 | 参数 | 作用 |
|---|---|---|
| 面积区间 | `0.004 ~ 0.72` | 滤掉噪点和"整图"掩膜 |
| IoU 下限 | `>= 0.35` | 滤掉低置信度 |
| 掩膜 NMS | 交集/并集 `> 0.62` 视为重复 | 去掉同一物体的多次命中 |

实测 144 → 24 → 9（NMS 后）。

### 3.4 输出要能"一眼看懂"

第一版高亮图是「背景压暗 + 部件原色」，几乎看不出差别。改成：
**背景压暗到 12%，掩膜区刷成「原色 35% + 固定色相 65%」**，每个部件一个色相。

再加最后一格 **分块图**：所有部件各涂一色。这是最有价值的一格——
一张图就能看出"这个角色被分成了哪几块、各占多大"。

## 5. 边界（必须说清）

- **只给可见区域**：被前发遮住的后发、被袖子遮住的身体，T1 拿不到。
  遮挡补全是 T2（See-through）的职责。
- **没有语义标签**：输出是「区域 0/1/2…」+ 颜色 + 位置，不是「hair/cloth」。
  语义判断交给模型看图（这正是设计意图：不把判断做成黑箱）。
- **对复杂渐变/阴影多的画风**，SAM 会把同一部件切成多块，需要靠 `max_parts` 与 NMS 调。
- **慢一点**：8 秒/张（CPU）。批量处理 20 张要 2-3 分钟。
