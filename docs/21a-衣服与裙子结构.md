### 1.3 方块形状分类器（本文的核心工具）

不依赖任何旋转/变换约定，**只看方块自身尺寸** `[sx,sy,sz]`（取绝对值）：

```
CHIP     最长边 ≤ 0.85                    → 微块/碎屑
STRIP_V  sy 为最长边 且 sy ≥ 1.6·max(sx,sz) → 竖条（竖直薄条）
PLATE_H  sy 为最短边 且 sy ≤ 0.70 且 max(sx,sz) ≥ 1.4 → 水平板（环片/花瓣）
SHEET    最短边 ≤ 0.35 且 中间边 ≥ 1.0 且 最长边 ≥ 1.4 → 薄片
BLOCK    其余                              → 实心块
```

这个分类器的意义：**"竖条 vs 横环"的差别本质就是尺寸比例**，跟作者用什么旋转无关。所以下面的分型是可信的。

关键参数：

| 参数 | 实测 |
|---|---|
| 单块尺寸 | 中位 **2.00 × 3.00 × 0.25**，p95 (4.50, 7.00, 2.04) |

| 大角度翻转 | **904 / 2,640 块有一个 >120° 分量** —— 这是"翻转贴面"（同一片做正反两贴，防止背面剔除） |

0.1–0.2: 189  (10.4%)
0.2–0.35: 1256 (69.4%)   ← 主峰

### 3.3 B 型 · 竖条帘幕（`hsr_herta_1` 186 / `rongrong` 224）

#### B-1 扁平四分（`hsr_herta_1`，186 块 / 4 骨，全部直接挂 `UpBody`）

UpBody ─┬─► Skirt_Front   53 块  pivot [0, 24.1, -2.0]  brot [0, 0, 0]

- 单块中位 **1.32 × 2.71 × 1.14**（前片）/ **0.40 × 5.05 × 1.04**（侧片）—— 侧片明显更薄更长。

- **角度随深度递增**（这是语料里最干净的递增样本）：

上半段 12–16° 基本不变（贴合），**下 40% 突然加速**（29→38°）——这就是"裙摆散开"的数学形态。

#### "四根子骨"不是前/侧/后 —— 是四层壳

这是本文对 21 号文档最重要的一处订正。**变换无关的证据**：四个子骨在原始坐标下的 Z 跨度全部同时覆盖身前和身后：

| 骨 | 块数 | z 跨度 | y 跨度 | 原始坐标下弧长 | 中位半径 |
|---|---|---|---|---|---|
| Skirt_Right | 84 | **-13.78 … +15.13** | -0.46 … 28.42 | 131.5° | 6.23 |
| Skirt_Right1 | 55 | **-10.53 … +16.13** | 5.51 … 27.01 | 134.7° | 6.02 |
| Skirt_Right3 | 121 | **-14.77 … +11.50** | 4.26 … 28.82 | 143.3° | 5.13 |
| Skirt_Right2 | 128 | **-10.11 … +19.65** | 3.71 … 29.11 | 153.3° | 5.14 |

四根骨每一根都横跨 22–30 个单位的 Z（相当于整个身体前后深度），弧长都在 130–153°。**没有任何一根是"前片"或"后片"**；它们是**同一右侧区域、半径 5.1–6.2 的四层同心壳**（外层 6.23 → 内层 5.13），叠出四层衣料。

> 判断依据不依赖旋转约定：只看 origin 的 z 分布即可。若真是前/后片，z 必然分成不重叠的两半。

- **outskirt 的 85 块 100% 是 PLATE_H**，全部 `sy = 0.10`。尺寸清一色 `1.5 × 0.1 × 4.3 ~ 5.7`：一条 1.5 宽、4~6 长的"羽片"。

### 3.7 怎么一眼判定用哪种

拿到一堆裙块，按这个顺序问：

1. **最薄维度 ≤0.15 且两水平轴都 ≥1.5** → D 型（羽片）。再数块数：60–100 块做一圈。
2. **`SHEET` 占比 >50%、厚度锁定在一个常数（如 0.25）** → A 型（薄片围合）。
3. **三轴中位全 ≤0.8** → C 型（微块马赛克）。这时块数要 200+，否则看起来是噪点。
4. **`STRIP_V` >50%、sy ≥ 4** → B 型（竖条帘幕）。这是最"安全"的一型。
5. **只有 1–2 根骨** → E 型。除非你确定不做分层动画，否则别选。

### 7.3 "飘动感"怎么来

三条正交的手段，语料里都在用：

1. **薄**：披风组厚度中位 **0.70**、p25 0.312；最薄的一档（`ruanmei`）中位 0.312、`Cloak` 只有 0.30。

3. **分段变尺寸**：`gi_yae_sakura` 的 `Tail`(1 块 1.00×1.00×5.00) → `Tail2`(1 块 1.10×1.10×5.00) → `Tail3`(20 块 5.45×2.27×2.07) —— 从根部小段逐渐放大到羽状末端。

## 9. 贴图尺寸 vs 服装复杂度

### 9.1 三个事实

1. **声明尺寸普遍偏小**：`texture_width/height` 写 256 的有 108 个模型，但**实际 PNG 比声明大的有 40 个**（例如 `al_agnes_0` 声明 256、实际 1024；`ak_shu` 声明 512、实际 1024）。写模型时**以 PNG 实际尺寸为准**。
2. **88.3% 的方块用逐面 UV**（`uv` 是 `{north:{uv,uv_size}, ...}` 字典），只有 11.7% 用盒式 UV（`uv: [u,v]` 数组）。现代模型几乎都是逐面 UV。`yujin`、`zhe_1/2`、`爱莉希雅` 都是 100% 逐面。
3. **尺寸与块数只是弱相关**：`Pearson(PNG边长, 总块数) = 0.522`。

### 9.2 更有用的指标：texel / 块

`PNG宽 × PNG高 ÷ 总块数`（每个方块平均能分到多少贴图像素）：

| 分位 | min | p10 | p25 | 中位 | p75 | p90 | max |
|---|---|---|---|---|---|---|---|
| texel/块 | 11 | 43 | 66 | **99** | 200 | 358 | 4410 |

| 模型 | PNG | 块数 | texel/块 |
|---|---|---|---|
| `gs_gy_yg` | 256² | 1,674 | **39**（极省） |
| `yujin` | 512² | 2,481 | **106** |
| `hsr_herta_1` | 512² | 1,267 | 207 |
| `bronya` | 1024² | 4,947 | 212 |
| `rongrong` | 512² | 1,074 | 244 |
| `hi3_elysia` | 1280² | 2,640 | **621**（极奢） |
| `爱莉希雅` | 2048² | 2,882 | 1,455 |

**判据**：
- texel/块 < 50 → 每个块只能分到几个像素，**必须靠色块/明度差**而不是细节纹理（`gs_gy_yg`、`ak_virtuosa`）。
- 50–250 → 主流区间，块上能画 1–2 条明暗过渡。
- > 400 → 高保真路线，块上有完整的布料花纹（`elysia` 1280²、`爱莉希雅` 2048²）。

### 9.3 贴图预算建议

| 模型规模 | 建议贴图 | 理由 |
|---|---|---|
| ≤600 块 | 128–256² | 语料里 128 档的中位块数只有 375 |
| 600–1,500 块 | 512² | `yujin`(2481 块) 用 512² 也不糊，因为块小 |
| 1,500–3,000 块 | 512–1024² | `bronya`(4947) 用 1024²；`rongrong`(1074) 用 512² |
| >3,000 块 + 高细节服装 | 1024–2048² | 只有 `elysia`/`爱莉希雅` 这一档 |

**注意**：贴图越大不代表越好看。`gs_gy_yg` 用 256² 做 1,674 块，靠的是**形状本身有信息**（25 根裙骨、竖条帘幕），不靠纹理。

## 10. 与"圆环分层蛋糕裙"的对比：为什么它消失了

### 10.1 先量化"圆环"到底还剩多少

严格定义"环带"：**Y 为最短边且 ≤0.6，且两个水平轴都 ≥2.2**（即一块能横跨 40° 以上的弧）。

全语料 6,592 个裙块的统计：

| 类别 | 块数 | 模型数 |
|---|---|---|
| **环带（两水平轴都 ≥2.2）** | **23** | **2**（`bronya` 20、`gs_yy_yg` 3） |
| 羽片/刀片（一水平轴 ≥2.0） | 493 | 28 |
| 小块水平板 | 320 | — |

**环带只占裙块的 0.35%，且集中在 2 个模型里，没有一个模型是"整个裙子由环带堆成"。**

也就是说：**"圆环分层蛋糕裙"在现代 YSM 语料里基本不存在。** 你把裙子做成一圈圈水平环，就是在做一件语料里 99.6% 的裙块都不采用的结构。

### 10.2 为什么会被淘汰（每条都有数据）

| 维度 | 圆环蛋糕裙 | 现代做法 | 证据 |
|---|---|---|---|
| **轮廓** | 阶梯锥台，一层一个硬折角 | 连续下垂 / 参差边缘 | 裙块形状：BLOCK+STRIP_V 77.3%，环带 0.35% |
| **布料感** | 环是刚性的，转折处是断崖 | 每块独立角度，褶皱连续 | 单块旋转分布双峰 8–16° / 45–50°，没有任何"整齐的一圈同角度" |
| **动画** | 整环一起摆，像台灯罩 | 每根骨/每块可独立 | 裙骨中位 4 根（p90 14，最多 28）；单环结构只需要 1 根 |
| **数量效率** | 100–150 块只能做 3–4 层 | 同样块数能做 100+ 条竖片 | 语料裙块中位 37、p75 78；冠军 300–800 |
| **贴图利用** | 环的顶面/底面几乎看不见，浪费 UV | 竖片正反都能贴 | 88.3% 逐面 UV，薄片可以六面各贴各的 |
| **侧面看** | 一层层的"台阶" | 平滑/碎边 | — |

### 10.3 那 `bronya` 的 85 块薄片算不算"环"？

不算，它是**羽片环（D 型）**，跟蛋糕裙的差别在"片的朝向"：

| | 蛋糕裙的环带 | bronya 的羽片 |
|---|---|---|
| 长轴方向 | **切向**（沿圆周走） | **径向**（从身体往外戳） |
| 典型尺寸 | 8 × 0.15 × 1.2 | **1.5 × 0.10 × 4.3** |
| 一圈需要几块 | 8–16 块拼满一圈 | 每片独立，85 片互相重叠 |
| 旋转 | 0（水平放置） | 三轴，最大角中位 49°、p90 83° |

**判别口诀：长轴沿圆周 = 环；长轴指向体外 = 羽片。** 语料里 493 : 23，羽片完胜。

### 10.4 结论

> "圆环分层蛋糕裙"不是"不好看"，是**信息密度太低**：一圈环带要 8–16 块才围满，同样的块数换成竖片能做出 3–5 倍的轮廓变化；而且环带是水平放置，顶/底面浪费 UV，侧面看必然是台阶。
> 现代语料的作者把同样的块数投到**竖条（37.6%）+ 厚块（39.7%）**上，用角度而不是层数制造体积。

## 12. 反例与坑

| 坑 | 表现 | 数据 | 怎么避 |
|---|---|---|---|
| **把中位数当目标** | 以为"裙骨每根 60–130 块" | 541 根裙骨里只有 38 根（7%）到 40–160 块；中位只有 6 块 | 先按 §2 的"及格/良好/冠军"三档选，不要一上来就 800 块 |
| **只绕 X 轴** | 以为语料都是 X 俯仰 | 语料 X 39.3% / Z 37.7% / Y 17.3%；只有 yujin 是 81.5% 单轴 | 前后摆用 X、左右摆用 Z、羽片用三轴 |
| **给下摆加 0.1 薄片当蕾丝** | 以为这是标准做法 | 8 个代表里只有 2 个下摆 <0.2 厚 | 荷叶边用**交替角**（§5.3），蕾丝用**贴图** |
| **把所有裙块塞进一根骨** | 省事 | 语料只有 `gs_yy_yg` 这么做（234 块 / 1 骨） | 至少 4 根，否则不能分层动画 |
| **角度取整数好看** | 用 5/10/15/30/45 | 语料实际是 **2.5 的倍数**：±2.5、±7.5、±12.5、±17.5…… | 用 2.5 步进 |
| **贴图开大就完事** | 512² 配 200 块 | texel/块中位才 99；`gs_gy_yg` 用 256² 做 1,674 块 | 先看 texel/块（§9.2） |
| **相信 `texture_width`** | 声明 256 实际 1024 | 40 个模型的 PNG 比声明大 | 以 PNG 实际尺寸为准 |
| **用盒式 UV** | 图省事 | 语料 88.3% 是逐面 UV | 逐面 UV 才能让薄片正反都有正确贴图 |
| **对语料做世界坐标变换** | 想"算"出真实形状 | 见 §12.1 | 别做 |

### 12.1 【重要】这份语料的旋转不能直接重放

实测发现：对 `yujin` 的方块重放 `rotation`（绕其 `pivot`）会把块甩到半径 **30** 的位置；重放骨骼 `rotation` 会把两层壳压到半径 **2.7**（身体内部）。对 `bronya.outskirt` 重放方块旋转会把 0.1 厚的水平片转成竖直羽片——两种解读都"说得通"。

**结论：这批文件的 `origin` 已经是最终位置，`rotation` 字段是编辑器留下的元数据，不能当作"待应用的变换"。**

因此本文的所有形状结论都用**尺寸比例**（§1.3）和**名字/父子关系**，不用世界坐标。做造型时也同样：**按尺寸和名字抄，不要按"旋转后的形状"抄。**

核心分类器（照抄即可）：

```python
def shape_class(s):
    sx, sy, sz = [abs(v) for v in s]
    mn, mid, mx = sorted([sx, sy, sz])
    if mx <= 0.85: return "CHIP"
    if sy >= mx - 1e-9 and sy >= 1.6*max(sx, sz): return "STRIP_V"
    if sy <= mn + 1e-9 and sy <= 0.7 and max(sx, sz) >= 1.4: return "PLATE_H"
    if mn <= 0.35 and mid >= 1.0 and mx >= 1.4: return "SHEET"
    if mid <= 0.9 and mx >= 2.0: return "SHEET"
    return "BLOCK"
```
