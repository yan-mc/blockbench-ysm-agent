## 1. 十句最重要的结论

1. **工程成功 ≠ 美术达标**：插件从 v0.4.0 推到 v0.9.1、隔离渲染/参考图/分层全部落地；但丰川祥子 v12 仍"角被头发埋、手臂被侧发挡"，是未完成的验收。
2. **方法论转折点是"禁止用数量指标倒推造型"**：v6 为凑 903 块/94% 旋转反而画风割裂；v7 退回 484 块才成立。块数服从档位（1.3–1.6 单位 → 400–900 块）。
3. **眼睛教义一天改四次，最终版才是对的**：v1 四层薄片 → v7 纯贴图 → v9 两块薄板 → **v10/v11 纯色方块叠层（每眼 8–9 块、全部宽>高、深度遮挡、可眨眼）**。
4. **"头身比 4.87"是错误目标，害了 3 轮**：4.87 是**视觉头口径（含发/角）**；建模该用**头方块/骨骼口径 7.31**。skill 已写双口径，`docs/21b`/corpus-rules 已补口径说明。
5. **v0 的"祥子"是拿旧模板换色，不是建模**：被用户 T16 当场否定。**禁止模板换色交付**，每个部件必须能说清来自哪张参考图（已进 skill 铁律 14）。
6. **T1/T2 做得出来，但主建模链几乎没用**：T1 7.6s/9 部件、T2 22 层/156s 都实测过；13 轮里只有 R1/R2 用了 T1，T2 全程只 probe。原因：环境被主动清空 + skill 只有"可以用" + 任务书没把分层当 gate。
7. **isolate 是最高性价比的质检**：v1–v8 一次没用，v9 一用就暴露"脸只露 1/4、角被埋、手臂被吞"；它应该从第一轮就存在。
8. **静默失败是最大工程成本**：`resolution` 从未生效（浪费约 10 轮）、`delete` 简写静默失效、`set_uv` 丢 uv_size、`animation.create` 不标脏、离屏首帧必空。**"返回 ok"不等于生效**，必须回读/渲染验证。
9. **美术判断必须亲自看图**：脚本只能统计；用户两次纠正"不要用脚本一键处理"。每个建模轮至少一次把官方立绘与当前渲染并排看。
10. **参考语料会消失**：一次清理把 169 模型删掉后只能去 MC 库硬找；重要语料/参考图要先归档再谈清理。

## 4. 本轮（togawa-sakiko 首轮验收）的立绘拆分复检

- `bb_seg_probe`：T1 可用（自动下载 59.1MB），T2 未装（ComfyUI 不可达，约 7GB）。
- `bb_seg_lite` 跑了官方立绘 + 3 张裁切图：72 个部件 / 983 候选，但**拆分质量低**——掩膜被钢琴/沙发/基座/留声机等道具与背景占据，人物的裙/手套/腿/靴/胸饰 0 个被切出。
- 因此逐部件对照改用 **人工读 `crop_head/face/body/legs` + 拆分 bbox 辅助**；8 组 isolate 检查全部完成。
- 结论：**major 5**（双角仅约参考 1/3、双马尾每条仅 4 块薄板、靴无形体、裙层/衬裙边/拖尾缺失、腹前浅灰方框无对应物），minor 4，pass 0。
- 证据：`models/togawa-sakiko/SEG-CHECK.md` + `models/togawa-sakiko/artifacts/seg-check/`。

> 教训：**T1 不是万能的**——在"暗色人物 + 暗色大件道具 + 亮背景"的稠密插画上会失效。
> 拆分不可用时改人工判读，并把"拆分不可用"写进报告；T2 才是可靠的分层参考（但成本高，按档位决定）。

### 4.1 T2 完整安装 + 逐细节修理（2026-11-07 晚）

- **安装**：ComfyUI 0.44.0 portable（torch 2.14.1+cu130，4.626GB/71,678 文件）+ See-through 节点（324 文件）+ pip 依赖；权重 **12.513GB**（HF cache，一次性）；磁盘占用约 27GB。关键工程处理：2GB 安装包用系统 curl 单线程下载（插件内置 Node fetch 会长时间停滞/被双写破坏），解压用 bsdtar（91.7s），其余仍走 `bb_seg_install`。
- **首次分层**：官方立绘 832²/28 步 → **29 个语义层**（GenerateLayers 24 → PostProcess 29），**22 分 43 秒**（含权重下载）；`crop_head` 特写 → 23 层/3 分 11 秒；PSD 由 ag-psd 复刻（`bb_seg_run` 不产 PSD），psd-tools 校验层序正确。
- **T2 真正有用的地方**：语义归属（哪层是什么）、部件形状、**遮挡深度序**（front hair 0.17 < face 0.50 < headwear 0.68 < topwear 0.70 < back hair 0.94）。
- **T2 不可用的地方**：面积比例——原图 2176² 里人物占比小，`objects` 抢走 19.98%，`front hair` 仅 2,606 px、`face` 1,772 px，只能看形状不能算比例；部分 `-l` 层 bbox 不可靠（看裁切图本身）。
- **修理结果**：217 → **355 块**（+138）；SEG-CHECK 的 5 个 major 全部落地（角 7.00×7.76 单位/只、马尾 3 层垂到 y=17.2、裙组 79 块含 21 片落地拖尾、靴 15 块/只、胸衣改形）；`bb_validate` 0 error；导出 zip 489KB。
- **剩余差距**：头发仍"薄板/栅栏"感（最大项）、拖尾片间有缝、蕾丝密度 2 层、腿无小腿肚、头身比 6.21 偏 Q、无背面参考。
- **新工具坑**：`bb_seg_run` 不产 PSD（前端/ag-psd）；层数不固定 24（实测 29）；Blockbench 欧拉序是 **XYZ（R=Rx·Ry·Rz）**（按 ZYX 推会把角做成"齿轮"）；骨骼 `delete` 会**级联删除子骨骼与方块**。
- 证据：[`T2-INSTALL-REPORT.md`](../models/togawa-sakiko/T2-INSTALL-REPORT.md)、[`T2-REPAIR.md`](../models/togawa-sakiko/T2-REPAIR.md)、`models/togawa-sakiko/artifacts/t2-repair/before-after-sheet.png`。

## 5. 工具/流程坑（按危害）

| 类 | 代表 | 规避 |
|---|---|---|
| 静默失败 | `resolution` 不生效（UV clamp）、`delete` 简写、`set_uv` 丢 uv_size、`animation.create` 不标脏、`no_visible_change` 假阴性 | 每个写操作回读 `changed[]`/`bb_scene`/渲染验证 |
| 数据源不可信 | `bb_validate.stats` 骨骼数恒 77、`bb_session_start` summary 是 main+arm 合计 | 计数一律用 `bb_scene` 或读 `main.json` |
| 坐标空间 | `main.json` 与 bbmodel x 镜像；`update_cube` 不给 pivot 会漂 | 用 bbmodel 坐标 + 逐块校验；改 rot 块必给 pivot |
| 预算管理 | 700+ 块 inline ops 耗尽 edits | 大改用「Python 生成 main.json+PNG → close/open」，bb_* 只做校验/渲染 |
| 参考图 | wiki 直链 403/404；暗底图拆分失效 | 萌娘原图兜底；人工裁切判读 |
| 并发/环境 | 队友上限 8、DSH 重启、BAE 独占 dist | 用新 subagent；改 bridge 后杀 electron → 同步 dist → 重启 |
