## 一、Blockbench 能做什么

```
Blockbench
├─ Minecraft 衍生
│  ├─ Minecraft 原版模型与材质
│  ├─ Minecraft 模组
│  └─ Minecraft 动画
└─ 像素风模型
   ├─ 像素方块模型
   └─ 像素 lowpoly 模型
```

## 二、四种模型规格（决定能用在哪）

| 格式 | 特点 | 导出 |
|---|---|---|
| **基岩版模型** | 方块搭建，**对旋转角度和尺寸无要求**，同一项目内只能有一张使用中的贴图；最自由的方块建模格式。用于龙核、萌芽等服务器引擎，可用于模组（如 YSM、TACZ） | `geo.json`（与 java 模型不通用） |
| **java 模型** | 多用于原版模型/模组；大小限制 **3×3×3 方块**（即 48×48×48 px）；**同一方块只能有一个旋转轴**，不能三向旋转，角度只能为 **22.5° 的倍数**；同一模型只能有一张贴图 | `.json` |
| **Minecraft 皮肤** | 分辨率多为 16x / 32x | `.png` |
| **自由模型** | 无网格体时可视为多个基岩版项目的集合，可混放基岩/java/皮肤，贴图互不影响；有网格体时只能存为自由模型，**无法转成其他格式** | 内部格式 |

**YSM 用的是基岩版模型**（geckolib 核心，支持基岩 **1.12.0 模型** + **1.8.0 动画**）。

> 转换关系：基岩模型 ⇄ java 模型可以互转；自由模型可转基岩，反向不行。

## 三、良好的模型制作习惯

1. **建立项目文件索引规范**
   例：`2025/10月/椰椰像素模组/沙发01`
2. **关闭自动更新**：`文件 / 首选项 / 设置 / 应用`
3. **增量保存**
   - 新建模型后**立即保存**到预期文件夹
   - **每 15 分钟手动保存一次**
   - 确认保存路径是自己想要的，别保存完找不到
4. **在世界中心建模**
   - 模型**正面朝北**
   - **对称轴落在世界轴线上**（否则后续镜像、对称绘画全废）
5. **贴图前检查**：新建贴图时确保**没有隐藏的方块、没有锁定的方块**
6. **导出前检查**：确保没有方块被误关（大纲视图右侧的可见性开关）
7. **有意识地分组**：建模时就按语义分层，别事后补

## 四、单位与"混素"（texel 密度）

- 使用规范长宽高，尽量让小数位落在 `.25 / .5 / .75`，能被 5 整除更好
- **避免混素**：同一模型内纹素尺寸差距不要过大（像素点大小不一致）
  - **16x 项目**：1 格模型 = 1 纹理像素
  - **32x 项目**：0.5 格模型 = 1 纹理像素
  - 因此方块尺寸不要小于"1 像素对应的模型尺寸"

> 这条直接决定视觉是否"糊"。本项目 `sakiko-final` 用 128 贴图配 196 方块，
> 单像素压力偏大，是贴图应该升到 256 的另一个理由（见 `docs/09`）。

## 五、界面与功能（菜单栏）

### 文件
- **项目**：显示模型信息（名字、格式、UV 展开方式）
- **新建 / 最近**：新建或打开最近项目
- **新窗口**：再开一个 Blockbench（双屏时用）
- **保存项目 / 另存为**
- **转换文件**：基岩/java ⇄ 自由模型（有网格体时只能存自由模型）

### 编辑
- **查找/替换**：批量改方块名
- **变换 → 缩放**：缩放整组方块且**整体形状不变**（很好用）
  - 「点击选中中心」可让模型以几何中心为原点缩放
- **吸附**：调节按住 `Shift` / `Ctrl` 时移动、缩放、旋转的步进量

### 视图 / 工具 / UV / 帮助
- **枢轴工具**：Blockbench 的旋转以**方块枢轴点**为圆心；枢轴点位置决定旋转效果。
  每个方块有独立枢轴点，每个组也有统一枢轴点。
- **移动工具**：先把 A 的顶点 a 移到 B 的顶点 b（点 A → 点 A 顶点 → 点 B → 点 B 顶点）
- **旋转工具**：轴=第一个选中方块的枢轴点；方向由两个选中顶点确定；可在画面下方窗口开启**轴约束**
- **缩放工具**：同移动，但**方块怎么缩放都还是方块，无法变成平行四边形**

### 变换方向
- **自身**：按方块/组自己的方向
- **父级**：按上一级组的方向
- **全局**：按世界坐标轴
- **翻转**：沿某世界轴对称翻转选中方块/组

### 设置（首选项）
- **常规**：语言
- **界面**：图标大小、透视显示
- **预览**：光照亮度、抗锯齿、双面/单面显示、背景、比例小人
- **渲染距离**：用于减少 **z-fighting**，其他软件叫摄像机裁切距离
  - *z-fighting = 重面现象：两个面叠在一起时软件不知显示哪个，会红白闪烁出锯齿*
- **应用**：硬件加速（GPU 渲染）、关闭自动更新
- **导出**：obj 用三角面还是四边面
- **快捷键 / 主题**

## 六、大纲视图（Outliner）

- **集合（Group）**：Blockbench 独有概念，把一堆方块归类，**同时起骨骼作用**，可层层嵌套
- **方块**：基础建模单位，可通过**擦除、拼接**等技法实现更复杂表现，不局限于方块
- **自动 UV**：可开可关
- **特殊按钮**（列表右侧）
  - **锁定**：关闭后无法对该方块/组做任何操作（同其他软件的"冻结"）
  - **可见性**（小眼睛）：显示/隐藏
  - **阴影**（java 模型独有）：游戏中是否受原版光照影响

## 七、建模指南

- **移动视角**：左键旋转 / 右键平移 / 中键缩放（不改变视野）
- **显示模式**：材质 / 灰模等
- **阴影开关**：上色环节很重要
- **预览**：截屏 / 分屏 / 背景 / 比例参考小人
- **右键菜单**：空白处 = 预览功能；方块上 = 复制粘贴、调整 UV 展开方式、标记颜色
- **添加参考图**：直接把图拖进视口；双击进入调整模式；`Delete` 删除；可拖多张

## 八、基础造型理论（关键）

### 三种建模人

| 风格 | 做法 | 评价 |
|---|---|---|
| **概括** | 用尽量少的块数/面数概括外形，内部结构靠贴图补足。原版生物、模组模型多用此法 | 推荐 |
| **狠狠雕** | 用大量小方块堆细节 | 新手易犯：比例失调、接缝过多影响观感。**不适合 Blockbench**，无美术基础不建议尝试 |
| **体素** | 像 Minecraft 一样垒方块，一个方块对应一个像素点 | 传统表现方式（如 Teardown） |

### 方块数量参考值

| 对象 | 建议块数 |
|---|---|
| 家具 | 10–150 |
| 武器 | 10–150 |
| **人物** | **50–300** |
| 载具 | 150–400 |
| 机甲 | 50–500 |
| 怪物 | 100–600 |

> 取中间值通常得到"不太难、效果尚可"的结果。
> **单体超过 500 块**时，若不是故意做该风格，建议停下来重新概括。

**交叉验证**：语料 114 个模型实测方块中位 **306**（`docs/08`），与"人物 50–300（取中上）"吻合。

### 节约块数与面数
善用**面片 / 橡皮擦 / 拼块技巧**，用最少方块达到最好效果。

## 九、材质、纹理与 UV

### 三者的区别
- **材质（Material）**：贴图所构成的一份贴图组（PBR 工作流下）；不做 PBR 可忽略
- **纹理（Texture）**：在 Blockbench 里创建的那张 PNG。
  本质就是**一张彩色包装纸**——只是一张图片，没有特殊功能
  - `png` 含透明度（alpha），`jpg/jpeg` 只有 RGB 不含透明
- **UV**：告诉软件"怎么从包装纸上裁形状、贴到模型的哪个面"，
  本质是**把 3D 模型顶点与 2D 贴图位置一一对应**

### 文件格式差异

| 格式 | 包含内容 |
|---|---|
| `.bbmodel` | 纹理 + UV + 模型 + 动画，**全部打包在一个文件** |
| `.json`（导出） | 只有 UV + 模型；纹理需配 PNG；动画需配另一个动画 JSON |
| `.obj` | UV + 模型；需 `.mtl` 提供贴图路径 + PNG。完整一份 = obj + mtl + png |
| `.fbx` / `.gltf` | 包含全部模型信息（3D 软件常用） |

## 十、贴图绘制工具

| 工具 | 说明 |
|---|---|
| **画笔** | 可调大小、形状、软硬、透明度。**新手不建议改软硬和透明度** |
| **复制画笔** | 复制选中图案；`Ctrl` 点击取源，再点击粘贴。**可直接在 3D 视图操作**，无需处理纹理图。相对位置不变 |
| **油漆桶** | 一次性填大范围颜色。可在 3D 视图涂，也可在左上角纹理视图涂 |
| **橡皮擦** | 让对应像素变透明 —— **本质是删掉方块的一部分**，非常常用 |
| **拾色** | 可在模型、参考图、纹理上吸色，**甚至跨工程吸色**（开两个 bb 模型互相取色） |
| **绘制形状** | 按住鼠标绘制方形/圆形 |
| **选区工具** | 在纹理视图框选，可复制/粘贴/删除/移动 |
| **移动图层** | 搭配选区工具移动图案 |
| **镜像绘画** | 对称轴为世界坐标轴，画对称模型时用 |
| **锁定 alpha 通道** | 锁定后涂色不改变透明度（半透明区域涂完仍半透明） |
| **绘画网格** | 显示像素网格 |
| **渐变工具** | **不建议使用** |

**油漆桶模式**
- 面 / 元素 / 选中的元素
- 3D 视图涂 vs 纹理视图涂（后者会填满 UV 框外的透明区域）

## 十一、光影与色彩理论（上色核心）

### 明暗结构
光线方向决定五个区：
- **亮面**：光线直射
- **灰面**：斜射，比亮面暗、比暗面亮
- **暗面**：光线照不到
- **明暗交界线**：方体中暗部棱线很暗；球体中与光线相切的区域很暗
- **反光区**：光线反射到暗面，使其变亮
- **闭塞阴影**：完全没有光线进入的区域（桌脚与地板缝隙、两物体挤压处）

### 阴影规律
- 距离物体根部越近越深，越远越浅
- 按光源大小分**软阴影 / 硬阴影**：越靠根部越硬，越远越软

### 环境光遮蔽（AO）
模拟环境光在缝隙、褶皱、阴角处的遮挡，增强立体感。
- **阳角：颜色亮**
- **阴角：颜色暗**

### 自发光
有自发光的零件会影响附近颜色。例：车灯是亮黄色，附近颜色应向"变亮、变黄"靠。

### 色彩三要素

| 要素 | 含义 | 应用规则 |
|---|---|---|
| **色相** | 什么颜色 | 不同色相影响视觉明度（黄色天然比蓝色显亮） |
| **明度** | 亮/暗 | **朝上的面更亮，朝下的面更暗；朝南北较亮，朝东西较暗** |
| **饱和度** | 鲜艳/混浊 | **亮部饱和度更低，暗部饱和度更高；阴影饱和度较低** |

### 天光设定（重要）
单体模型默认放在**天光**下绘制：阳光是**亮黄色**，大气是**蓝色**，地面漫反射。
因此：
- **亮面偏暖，暗面偏冷，阴影偏冷**
- 朝上面更亮、朝下面更暗

### 色调
按色相（红/蓝色调）、明度（亮/灰/暗调）、饱和度（纯/灰色调）、冷暖（冷/暖调）分类。
作用：统一画面色彩，避免杂乱。

> **一句话**：色相名字无所谓，颜色在色环上无极相接，不要纠结"这算蓝还是绿"。

## 十二、YSM 官方规范（来自官方说明书）

### 目录结构（`config/yes_steve_model/`）

```
custom/ 或 auth/
└─ default/                 模型包文件夹（文件夹名 = 模型 ID）
   ├─ main.json             主模型（固定名，必须）
   ├─ arm.json              第一人称手臂（固定名，必须）
   ├─ main.animation.json   主动画
   ├─ extra.animation.json  轮盘动画
   ├─ happy_skin.png        贴图（名字可自定义，会成为游戏内显示名）
   └─ ...                   任意多张贴图
```

- **只有三样是必须的**：`main.json`、`arm.json`、任意一个 PNG
- 文件夹/贴图名只能用小写英文、数字、下划线
- 也可以整个打包成 zip（注意别把外层文件夹一起打进去）

### 组命名规范（官方）
1. **大写驼峰 + 形容词+名称**：`LeftArm`、`AllHead`
2. **简洁原则**：用 `All` 不用 `Whole`；用 `Eyes` 不用 `HeadEyes`（眼睛必然在 Head 里）
3. **无意义分组**用"父类+数字"：`Mouth1`、`Mouth2`、`Mouth3`
4. **特定组名不可改**（改了游戏功能失效）：

| 组名 | 说明 |
|---|---|
| `Head` | 游戏会**默认添加头部随视角摆动的动画**（不喜欢就把组改名） |
| `LeftHand` + `LeftHandLocator` | 左手手持物品定位组；**Locator 必须位于 `LeftHand` 里面**，由 Locator 的旋转点定位物品 |
| `RightHand` + `RightHandLocator` | 同上 |

### arm.json 制作（5 步）
1. 复制主模型文件
2. 把 `LeftArm`、`RightArm` 分组复制到根目录
3. 删除整个 `Root` 分组
4. 粘贴刚才复制的两个 Arm
5. 把它们的 X/Y/Z 旋转全部改为 0（内部分组不用改），改完手臂应垂直向下

- 在根目录建名为 `Background` 的组，第一人称时会渲染为背景

### 贴图
- PNG 格式；**不建议用半透明贴图**（会造成渲染错误）
- 支持多张贴图，游戏智能识别

### 动画文件
主动画（`main.animation.json`，可修改）：

| 名称 | 作用 | 循环 |
|---|---|---|
| `walk` | 普通行走 | 循环 |
| `run` | 疾跑 | 循环 |
| `climbing` | 活板门下 | 循环 |
| `sneaking` | 潜行不移动 | 循环 |
| `sneak` | 潜行并行走 | 循环 |
| `swim` / `swim_stand` | 游泳 / 水中站立 | 循环 |
| `attacked` | 被攻击 | 单次 |
| `jump` | 离地（跳跃和飞行都调用） | 循环 |
| `fly` | 鞘翅飞行 | 循环 |
| `boat` | 坐船 | 循环 |
| `use_righthand` / `use_lefthand` | 使用左右手 | 单次 |
| `sleep` / `ride` / `ride_pig` / `sit` | 睡觉/骑马/骑猪/坐下 | 循环 |
| `idle` | 无操作 | 循环 |

- **并行动画 `parallel0`–`parallel7`**：放 `main.animation.json`，与主动画互相独立、同时播放
  （尾巴摆动、耳朵摆动、眨眼）。**优先级高于主动画**，同骨骼冲突时并行覆盖主动画。
- **额外动画 `extra0`–`extra7`**：单独放 `extra.animation.json`，用**动画轮盘（Z 键）**播放。

| `ysm.armor_value` | 护甲值 | 0 ~ 20 |
| `ysm.hurt_time` | 受伤值（受伤时为正） | — |

### 两个经典技巧

**1. 显示/隐藏部件**：缩放 X/Y/Z 全设 0 即隐藏。
```
q.ysm_has_helmet ? 1 : 0
```

**2. 长发穿身问题**：抬头时头发不随头转，而是抵消回去；低头时随头转。
```
(ysm.head_pitch > 0) ? -ysm.head_pitch : 0
```
条件式语法：`判断条件 ? 成立时 : 不成立时`
- `ysm.head_pitch > 0` 抬头 → 取反抵消
- 否则返回 0 → 头发随头旋转
