# 24 · 复杂立绘 → 三视图/干净正视图 + 图像拆解：方案调研（2026-11-08）

> 背景：当拿不到标准人设图/三视图时，只能退而求其次用官方立绘（可信度高），但官方图通常带**复杂动作、背景道具、打光、遮挡**，直接 T1/T2 拆分和建模判断都很难。
> 本文是**调研报告**，不涉及代码改动。目标：把"立绘 → 可用于建模的干净多视图 + 部件拆解"的现有路线、工具、可靠性整理清楚，供后续决定接入方式。
> 结论先行：**没有单一工具能可靠地把"带动作带背景的立绘"变成真三视图**。可行的是"**生成式标准化（出多视图）→ 分层/部件拆解（带遮挡补全）→ 人工逐项复核**"的三段式，并把所有"推定部分"显式标记为假设。

---

## 0. 问题拆解：我们到底缺什么

| 缺的东西 | 官方立绘的问题 | 需要的能力 |
|---|---|---|
| **标准视角**（正/侧/背，等比例） | 是 3/4 动态构图，不是正交视图 | 转面/姿态标准化 → 多视图 |
| **干净主体** | 钢琴、沙发、道具、地面、粒子 | 主体分割 + 去背景/去道具 |
| **中性光照** | 强氛围光、逆光、彩色环境光 | 重打光 / 平涂化 / 阴影归一 |
| **部件语义** | 头发遮脸、手挡胸、裙层叠、道具遮挡 | 语义分层 + 遮挡补全（amodal / inpainting） |
| **结构假设** | 背面/内侧根本看不到 | 3D 重建或生成式"合理推断"，并标记为假设 |

我们的 YSM 流水线目前：`bb_ref_*`（官方基准/深搜/对照表）→ T1 SAM2 / T2 See-through → 人工裁切 → spec → 建模。痛点集中在**第 1、4 项**。

---

## 1. 三条技术路线总览

| 路线 | 做法 | 强项 | 弱项 | 代表 |
|---|---|---|---|---|
| **A. 2D 生成式标准化** | 用图像编辑/生成模型（Nano Banana、GPT-Image、Qwen-Image-Edit、Seedream、Flux Kontext 等）以原立绘为 reference，逐张生成正/侧/背 + 表情 + 服装/道具 | 快、风格统一好、能"补出"看不到的部分 | **是生成不是还原**：会改设计、左右镜像、背面是幻觉；需要逐张人工核对 | ai-chan-sheets、CharacterCardStudio、Nano Banana 三视图模板、Scenario |
| **B. 3D 重建后渲染** | 单图/多视图 → 3D 网格（TripoSR / Hunyuan3D-2.x / CharacterGen / Meshy）→ 摆 A/T-pose → 渲染正交三视图 | 视角/比例真正 3D 一致；可导出多视图与部件 | 单图有姿态/遮挡歧义；背面仍是推断；风格/细节损失；角色脸容易崩 | CharacterGen、TripoSR、Hunyuan3D-2/2mv、Meshy |
| **C. 拆解/补全** | 语义分层（See-through / LayerDiffusion）+ 部件分割（SAM2/SAM3）+ 遮挡补全（inpainting/amodal） | 直接给"部件 + 遮挡后完整形状 + 深度序" | 分层是"看起来合理"的补全，不是事实；对复杂遮挡/道具仍会失败 | See-through、LayerDiffusion、SAM3、amodal completion |

实际落地建议是 **A/B 先做"视角标准化"，C 做"部件拆解"，最后人工复核**；三者互补，不要指望单工具全自动。

## 2. 路线 A：2D 生成式"三视图/设定板"

### 2.1 最简单的做法：图像编辑模型 + 提示词模板

- **Nano Banana / Nano Banana Pro（Google）**：目前社区最常用的"角色三视图/设定板"生成器。典型提示词结构：`以参考图为身份依据，保持脸型/发型/服装/配色；横向三视图：严格正面、90° 侧面、严格背面，等高等比例，头顶与脚底基线对应，中性姿态，纯白背景`。教程与模板：[NanoBanana2 三视图教程](https://nanobanana2.xin/zh-cn/blog/nanobanana2-character-three-view-tutorial/)、[58 组角色设定图提示词合集](https://www.uisdc.com/character-sheet-prompts)（其中 03 白底四视图、47 综合角色设定总表最常用）。
- **Scenario** 也给出了三种 turnaround 工作流：Edit with Prompts / Pixverse 360° / 用 ControlNet 训练角色模型：[Scenario: Generate Character Turnarounds](https://www.scenario.com/blog/generate-character-turnarounds-scenario)。
- **国内商业工具**：Krene 支持"标准三视图生成 + 元素拆解标注"（Nano Banana/即梦双模型）[百度百科：Krene](https://baike.baidu.com/item/Krene/67894654)；献丑 AI 画布「角色设计」可一键派生正面锚点、三视图、表情表、服装拆解、道具图等 12 项资产 [阿里云开发者社区](https://developer.aliyun.com/article/1740784)。

**优点**：几分钟出图，风格贴近原图；**风险**：同一角色多张之间的"一致性"靠 reference 图+提示词，仍会漂移；**背面是模型脑补**；左右手/左右眼、文字徽记很容易错。

### 2.2 工程化流水线：把"设定图"拆成 22 张独立素材再拼板

GitHub 项目 **ai-chan-sheets** 是目前看到最接近"可复用产线"的开源方案（[repo](https://github.com/lmy414/ai-chan-sheets)）：

- 输入：**一张原始立绘**（通常只有正面）；
- 输出：横版完整设定图，四区：**01 三视图（正/左/背）、02 表情 8 种、03 服装 4 件（脱下摆放的单品）、04 道具与饰品 7 项**；
- 流程：制作清单（22 条任务）→ 每条任务独立写提示词（"保留什么、修改什么、本张只画什么"）→ 逐条调用图像模型（开源记录用 `gpt-image-2.5-sunburst`；也有用内置 `image_gen`）→ **逐张目检**（身份走形/左右镜像/标识文字）→ 按原生像素 1:1 拼接（不缩放不裁切）→ **独立校验脚本逐字节比对 22/22、零重叠零越界零缩放**；
- 关键点：**原图只有正面的角色，侧面/背面是"依据可见结构推定补全"**（例如被遮挡的裙片连接、外披内侧、鞋跟），并在文档中明确标注为推定；已有侧背面的以已有视图为依据；
- 产出还有"原图切片"：四区各一张 1:1 原像素 PNG，可直接当描线底图/细节参考。

> 这个项目的价值不只在图，而在**流程设计**：把"设定板"拆成独立任务 + 独立校验 + 1:1 拼接，避免一张大图里元素互相污染、比例错乱。

### 2.3 ComfyUI 侧的角色卡/三视图节点

- **ComfyUI-CharacterCardStudio**（[repo](https://github.com/JGRFW/ComfyUI-CharacterCardStudio)）：面向 Qwen-Image 2.1 的一键角色卡生成，支持"一张参考图 → 多视图/表情/环境细节 → 按卡版自动切片排版"，内置 8 套角色卡版（4–14 格，含三视图/设定集）。
- **Yolain ComfyUI Workflows** 的 `3-1-1 角色三视图与特写`：基于 ControlNet + IPAdapter 的经典三视图工作流（[repo](https://github.com/yolain/ComfyUI-Yolain-Workflows)），适合已有 SD/ComfyUI 环境直接套。
- **ComfyUI_CharacterPose**（[repo](https://github.com/Spit8/_ComfyUI_CharacterPose)）：把 2D sprite 的姿势（idle/T-pose）转成另一姿势并保持画风——属于"2D 姿态标准化"而非三视图，但对"把坐姿立绘改成站姿"很有用（Flux.2 Klein + Mixamo OpenPose 库）。

### 2.4 关键限制（必须写进流程）

1. **生成 ≠ 还原**：背面/内侧/被遮挡处是"合理幻觉"，不是官方设定；要作为 `spec.gaps` 或"推定"标记。
2. **一致性**：多张生成必须逐张与官方图对比；脸、左右、配色、纹样、文字要人工核对（ai-chan-sheets 的 22 张也要逐张目检，不合格重生成）。
3. **左右镜像**最容易出错（跟"哪只手拿剑/发饰在哪侧"有关）。
4. **文字/徽记/细纹样**经常被改写；YSM 建模可以后补贴图，但判定"这是不是同一个设计"时要小心。

## 3. 路线 B：姿态标准化 + 3D 重建 → 渲染正交视图

### 3.1 把"任意姿势"标准化到 A/T-pose

- **CharacterGen**（arXiv 2402.17214，[abs](https://arxiv.org/abs/2402.17214)）：核心就是"单张任意姿势图 → 图像条件多视图扩散做 **pose canonicalization（姿态规范化）** → transformer 稀疏视图重建 3D → 纹理反投影"。这是"立绘动作复杂"问题最直接的学术方案；但它生成的是**风格化 3D 网格**，脸/服装细节会损失，适合"结构/三视图"参考，不适合直接当高保真贴图来源。
- **Meshy 的 custom pose**（[功能页](https://www.meshy.ai/zh-Hant/features/custom-pose)）：上传任意姿势参考图 → 生成前直接选 T-pose/A-pose/自定义姿势 → 导出 FBX/GLB。商用 API/网页即可，适合快速出"中性姿态的多视图"。
- **PoseMaster**（CVPR 2026，[pdf](https://openaccess.thecvf.com/content/CVPR2026/papers/Yan_PoseMaster_A_Unified_3D_Native_Framework_for_Stylized_Pose_Generation_CVPR_2026_paper.pdf)）等新工作把"姿势化"放到 3D native 框架里，思路同源。

### 3.2 单图/多视图 3D 重建模型

| 工具/模型 | 输入 | 说明 | 链接 |
|---|---|---|---|
| **TripoSR** | 单图 | Stability AI，快；结构粗、细节弱 | 通过 [abstract3d](https://pypi.org/project/abstract3d/0.3.0/) 封装可调 |
| **Hunyuan3D-2 / 2mv / 2.1** | 单图/多视图 | 目前开源里几何最强之一；2mv 可吃多视图约束几何；注意 Tencent 社区许可（不含 EU/UK/韩国） | 同上 |
| **CharacterGen** | 单图（任意姿势） | 先 A-pose 多视图再重建；适合二次元角色 | [abs](https://arxiv.org/abs/2402.17214) |
| **Meshy** | 单图/多图 | 商业，姿势控制好，可导出 GLB | [custom pose](https://www.meshy.ai/zh-Hant/features/custom-pose) |
| **SAM 3D** | 单图 | Meta SAM 3D，面向物体/人物重建，2025-11 发布 | [Meta 公告](https://about.fb.com/br/news/2025/11/nossos-novos-modelos-sam-facilitam-a-deteccao-de-objetos-e-a-criacao-de-reconstrucoes-3d/) |

拿到网格后：摆 A/T-pose → 用正交相机渲染 front/left/back/right → 得到"真 3D 一致"的三视图；也可以把网格按部件分割后做"部件爆炸图"。

### 3.3 部件级 3D 生成/分割（做"拆解"的 3D 路线）

- **PartCrafter**（arXiv 2506.05573，[ar5iv](https://ar5iv.labs.arxiv.org/html/2506.05573v1)）：单图直接联合生成多个语义部件网格（不是先分割再重建）。
- **OmniPart**（arXiv 2507.06165，[ar5iv](https://ar5iv.labs.arxiv.org/html/2507.06165)）：两阶段——先给部件 bbox，再在 TRELLIS 体素表达上做部件感知生成；支持文本部件 schema。
- **SAMPart3D**（arXiv 2411.07184，[abs](http://arxiv.org/abs/2411.07184)）：无需文本 prompt 的 3D 部件分割，粒度可控；适合已有网格拆部件。
- 这些是"从 2D 部件到 3D 部件"的前沿，工程上还偏重；对我们的 YSM 体素建模，**3D 输出主要拿来看结构/比例，而不是直接转换**。

### 3.4 限制

- 单图 → 3D 的背面是模型先验，**不是官方设定**；
- 二次元脸/发丝/花纹容易糊，颜色也偏；不适合直接当贴图；
- 复杂服装/长裙/大饰品在重建里经常合并或断裂；
- 推理成本：本地 Hunyuan3D-2.1 需要不错显卡；云端 Meshy 按次计费。

## 4. 预处理：先把"干净主体"搞出来

### 4.1 去背景 / 主体分离

- SAM2/SAM3（SAM3 支持**文本 prompt**，如 `hair/headwear/face/eyes/...` 直接分割部件）、U2Net/rembg、BiRefNet 等；我们已有 T1 SAM2 + T2 See-through，可直接复用。
- SAM3 的 20 个 body-part 标签（hair, headwear, face, eyes, eyewear, ears, earwear, nose, mouth, neck…）在 See-through 的推理脚本里就有示例（[HF space docs](https://huggingface.co/spaces/24yearsold/see-through-demo)），适合"按语义部件出 RGBA"。

### 4.2 去动作/道具（把不想要的东西抹掉）

- 手动 mask + inpainting（ComfyUI inpaint / LaMa / SD inpaint）；
- **Amodal completion**：专门"补全被遮挡物体"的研究——CVPR 2024 *Amodal Completion via Progressive Mixed Context Diffusion*（[pdf](https://openaccess.thecvf.com/content/CVPR2024/papers/Xu_Amodal_Completion_via_Progressive_Mixed_Context_Diffusion_CVPR_2024_paper.pdf)）、CVPR 2025 *Open-World Amodal Appearance Completion*（[pdf](https://openaccess.thecvf.com/content/CVPR2025/papers/Ao_Open-World_Amodal_Appearance_Completion_CVPR_2025_paper.pdf)）。对"手挡住胸饰/裙片"这种场景，比普通 inpaint 更合理，但仍是"补全假设"。

### 4.3 光照/材质归一（把"氛围光"打平）

- **IC-Light（lllyasviel）**：给主体重新打光，保留身份/服装，把背景替换成中性光（教程示例：[plakat relight](https://raw.githubusercontent.com/vulogov/plakat/e66f3bda2f93d5fc07f7afa28d6235b436109d6d/Documentation/Tutorials/RELIGHT_TUTORIAL.md)）。
- **animetic_light**（HF）：专门针对**动漫图**的背景生成+重打光 LoRA（[README](https://huggingface.co/ippanorc/animetic_light/blob/main/README.md)），比照片向 IC-Light 更贴近二次元。
- 平涂化/线稿化：Anime2Sketch、lineart/cel-shading 模型；把复杂渐变压成"可读的固有色"，便于拆解和取色。
- 去阴影/去高光后可再交给 T2 分层，层图会更干净。

## 5. 图像拆解：两条完全不同的"拆解"

### 5.1 语义分层（2.5D 分层 PSD）——"把角色拆成带深度的层"

- **See-through**（arXiv 2602.03749，[abs](https://arxiv.org/abs/2602.03749)；[GitHub](https://github.com/shitagaki-lab/see-through)；[HF demo](https://huggingface.co/spaces/24yearsold/see-through-demo)）：单张立绘 → 完全补全的语义层（头发/脸/眼/衣服/配饰…）+ 推断的绘制顺序 + 深度 → 分层 PSD。
  - 技术：SDXL 的 **LayerDiff 3D** 生成带透明度层 + 微调 **Marigold** 深度 + 后处理分层；训练数据是从 **Live2D** 模型自动提取的（Live2D 的 Drawable 天然分层、有遮挡关系），版权原因数据不公开但权重可用。
  - 中文 blog：*把一张立绘拆成带深度的分层 PSD*（[HF blog](https://huggingface.co/spaces/24yearsold/see-through-demo/blob/main/docs/blog_zh_seethrough.md)）明确指出："头发、脸、眼睛、衣服、配饰，每一层都是完整修复过的，被遮挡的部分也补好了"；前发/后发能分开。
  - 我们已装 T2（ComfyUI + See-through），实测 24→29 层，就是这条路。
- **LayerDiffusion / LayerDiffuse**（lllyasviel，[repo](https://github.com/lllyasviel/sd-forge-layerdiffuse)）：透明图层生成/图层分解的另一支，适合"生成带 alpha 的前景/背景层"。
- 我们需要的正是这个：**"每个部件完整、带透明通道、带遮挡补全"**，因为建模要的是"部件形状"而不是"可见碎片"。

### 5.2 全展开设定板（"把所有东西摊开到一张图上，还会脑补"）

这就是用户印象里的那类图。它本质上是"**生成式设定板**"，不是严格拆解：

1. **Nano Banana Pro "像素级拆解" 提示词**（社区爆款，示例：[GitHub issue #385](https://github.com/mqyqingfeng/Blog/issues/385)）：
   - 目标："全景式角色深度概念分解图"；
   - 中心：角色全身立绘（视觉锚点）；
   - 环绕：**服装分层（单品、脱下外套的内层、内着）**、3–4 个表情特写、材质特写、核心道具、**"生活切片"**（包里物品、美妆、私人物件），并用手绘箭头连线到对应部位；
   - 背景：米黄/羊皮纸/浅灰设计稿风，模拟手写注释；
   - 执行逻辑明确写着"**脑补并设计二级深度元素**"（内衣风格、包里有什么）——所以必然会"假设不存在的东西"，这正是用户记忆中的效果。
2. **ai-chan-sheets**（上节）是它的"工程化、可校验"版本：不是一张大图，而是 22 张独立素材 + 1:1 拼板 + 逐字节校验；其中"服装设计 4 项（脱下摆放的单品）"、"道具与饰品 7 项（被手挡住/过小的配件放大）"就是"把东西摊开"。
3. **uisdc 58 组提示词** 的 47 号"综合角色设定总表"、03 号"白底四视图"也是同一类思路（[链接](https://www.uisdc.com/character-sheet-prompts)）。
4. **商业工具**：Krene 的"元素拆解与表情设计"、献丑 AI 的"服装拆解/道具图/配色卡"（[Krene](https://baike.baidu.com/item/Krene/67894654)、[献丑](https://developer.aliyun.com/article/1740784)）。

> 这类图对建模的价值：**给出"部件清单 + 可能的层次/穿法"**，非常适合做 checklist；但不能当"三视图尺寸依据"——它本身透视不严格、比例不统一、背面是编的。使用时要：让人工逐项标"可信/推断/错误"，把推断项写进 `spec.gaps`。

### 5.3 遮挡补全/背面推断

- See-through 的核心卖点就是"被遮挡的部分也补好"+深度序；
- 3D 重建（路线 B）从多视图反推背面，属于"几何先验补全"；
- Amodal completion（§4.2）是 2D 的"补全被遮挡物体"；
- 生成式设定板（§5.2）是"语义先验补全"，最自由也最不可靠。

## 6. 对我们的 YSM 流水线，怎么用（建议）

### 6.1 分级策略

| 情况 | 建议 |
|---|---|
| 能拿到官方**三视图/设定集** | 直接用，`bb_ref_collect` 对照表 + T1/T2；不要生成 |
| 只有**官方立绘**（复杂动作/背景） | 先做 §4 预处理（去背景/重打光）→ 再选 A（2D 三视图模板/ai-chan-sheets 风格）或 B（3D 重建 → 渲染正交视图）产出"干净三视图候选" → 用 T2 拆解 → **人工逐项复核** |
| 立绘有多个角度/多张官图 | 多视图一起喂 T2/3D 重建（Hunyuan3D-2mv / CharacterGen 的 multi-view），比单图可靠得多 |
| 只需要部件清单/比例 | 直接 T2 分层 + SAM3 文本分割零件 + ai-chan-sheets 式"摊开板"做 checklist，不必追求精确三视图 |
| 背面完全没信息 | 明确写 `spec.gaps`：背面为对称/生成推断；不要假装有依据 |

### 6.2 推荐组合（工程上最稳）

1. **预处理**：SAM2/3 去背景 → IC-Light/animetic_light 重打光 → 可选平涂化；
2. **视角标准化**：优先 **B（3D 重建 + A/T-pose 渲染）** 得到真三视图；若 3D 质量太差，再用 **A（Nano Banana/GPT-Image/Qwen-Image-Edit 三视图模板 + 逐张目检）** 兜底；
3. **拆解**：T2 See-through（29 层 + 遮挡补全 + 深度）为主；配合 SAM3 文本部件分割做"指定部件 RGBA"；
4. **假设清单**：把 A/B 生成的"背面/内侧/被挡部件"全部标记为推定，进 `spec.gaps`；
5. **人工复核**：逐张对照官方图，检查左右镜像、配色、纹样、文字、比例。

## 7. 风险清单（用之前先看）

1. **幻觉**：生成式三视图/设定板会"发明"背面、内衣、道具；只能当假设。
2. **一致性漂移**：同一角色多张之间脸/发/服装会变；必须 reference 图 + 逐张复核。
3. **左右镜像**：发饰/武器/单侧配饰最容易反；要和官方图逐项对。
4. **文字/徽记**：logo、编号、花纹会被改写；建模贴图需另找参考或重画。
5. **版权**：官方立绘/第三方模型参考只能本地研究，不随仓库分发（我们已有 gitignore 规则）。
6. **3D 重建的风格损失**：二次元脸/发丝/蕾丝会糊；只用结构与比例。
7. **"拆解板"不是三视图**：透视不统一、比例不可量；只能做部件清单，不能当尺寸依据。
8. **T2 也不是全能**：官方立绘实测 `objects` 抢走 19.98%、裙/手套等层可能切空；需要人工裁切兜底（`docs/23` 与 `SEG-CHECK` 有记录）。

## 9. 结论（给下一步决策）

1. **不要指望"一个工具把复杂立绘变成可靠三视图"**；正确姿势是"预处理 → A/B 视角标准化 → C 拆解 → 人工复核"。
2. 对我们现有仓库，**最高性价比的增量**是：① SAM3 文本部件分割（补 T2 的不足）；② IC-Light/animetic_light 重打光（让 T2 层更干净）；③ 借鉴 ai-chan-sheets 的"独立素材 + 1:1 拼板 + 校验"流程，把"三视图/拆解板"做成可复核的资产，而不是一张不可信的大图。
3. **任何生成/补全的背面与遮挡部分都必须标记为"推定"**，写进 `spec.gaps`；这是保证"不像就承认"的底线。
4. 如果后续要做，建议先做**离线原型**：拿一张祥子官方立绘（复杂坐姿+钢琴背景）跑一遍"去背景 → 重打光 → 2D 三视图模板 / 3D 重建 → T2 分层"，对比"直接 T2"的差距，再决定是否接入插件工具链。
