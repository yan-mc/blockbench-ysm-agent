# 18 · 官方基准优先 + 大面积深度搜索

> 两条硬规则：
> 1. **先取官方基准，再搜图** —— 基准用来校验后面所有候选图；
> 2. **搜索要深要广** —— 搜索本身极便宜，实测 902 个候选只要 2 秒，没有理由只搜几十张。

---

## 1. 为什么必须先有基准

图搜结果天然混杂：同人图、别的角色、AI 图、表情包。

**实测事故**：全新用户验收那次，15 张候选里混进了一张**完全不同的角色**
（鹿島神：紫瞳、深蓝短波波、水手服），只有当执行者真的逐格看图才排除掉。
如果它直接按"搜索结果第一张"建模，发色/瞳色/发型会全错。

有了官方基准后，判断从"看起来像不像"变成"和基准对得上对不上"：

| 维度 | 基准给的信息 | 用它怎么筛 |
|---|---|---|
| 发色/瞳色 | 百科外观段落 + 官方立绘 | 颜色对不上的直接丢 |
| 服装 | 设定段落的服装描述 | 同名不同服装（校服 vs 演出服）要分清 |
| 比例 | 官方立绘全身像 | 校准模板"腿偏长/裙偏短"这类偏差 |
| 外文名 | 罗马音 | booru 图站只认罗马音标签 |

---

## 2. `bb_ref_canon`（第一步必做）

一次调用拿到三样东西：

```jsonc
{
  "facts": [{ "source": "moegirl", "title": "丰川祥子",
              "extract": "（已按外观相关段落裁剪，约 1800 字）",
              "full_chars": 11723 }],
  "name_variants": ["丰川祥子", "Ave Mujica", "Eiga Sakiko"],
  "images": [{ "title": "File:Eiga Sakiko.png", "width": 2000, "height": 3000 }],
  "downloaded": [...],           // 已存到 refs/<角色>/canon/
  "attachment": { ... }          // 官方图对照表
}
```

### 2.1 数据来源

只用**公开 MediaWiki API**，不抓页面 HTML：

| 源 | API | 说明 |
|---|---|---|
| 萌娘百科 | `zh.moegirl.org.cn/api.php` | 中文二次元角色覆盖最好 |
| 维基百科 | `zh.wikipedia.org/w/api.php` | 兜底 |

### 2.2 踩到的坑

**`prop=imageinfo` 对匿名调用被拒**：

```
titles=File:xxx&prop=imageinfo  →  {"error":{"code":"action-notallowed"}}
```

但 **`generator=images` 是允许的**，一次就能拿到直链 + 尺寸。所以取图走：

```
action=query&generator=images&gimlimit=30&titles=<角色>&prop=imageinfo&iiprop=url%7Csize%7Cmime
```

**官方图要按名字筛**：条目里挂着大量无关文件（乐队 logo、其他成员的图、按钮图标）。
做法：用抽出来的 `name_variants` 做**文件名命中打分**，再按面积排序。
实测效果：从 22 张里准确捞出 `Eiga_Sakiko.png`（2000×3000 官方电影人设），
而不是乐队 logo。

**正文要裁剪**：全文 11723 字，直接塞给模型等于灌剧情。按段落打分：

- 优先：标题或正文含 `外貌/外观/人设/服装/制服/发型/发色/瞳色/身高`
- 排除：`经历/剧情/历代形象/关系/萌战/战绩/评价/轶事`
- 预算 1800 字，按原文顺序输出保持连贯

## 3. 深度搜索 `depth:"deep"`

### 3.1 放大机制

| 维度 | fast | deep |
|---|---|---|
| 查询词 | 6 条 | **23 条**（中/日/英 × 设定集/三视图/立绘/背面/侧面/服装/特写） |
| Bing 语区 | zh-CN | **zh-CN + ja-JP + en-US** |
| Bing 分页 | 1 页 | **3 页** |
| 360 分页 | 1 页 | **2 页** |
| 源 | 3 | **4**（+ yande.re booru） |

### 3.2 实测对比（丰川祥子）

| | fast | deep | 倍数 |
|---|---|---|---|
| 任务数 | 18 | **276** | 15× |
| 候选总数 | 96 | **902** | **9.4×** |
| 耗时 | 1.05s | **2.0s** | 1.9× |
| 各源 | bing 70 / so360 9 / moegirl 17 | bing **643** / so360 **244** / moegirl 15 | |

**结论：搜索成本几乎可以忽略，没有理由不深搜。**

### 3.3 新源：yande.re（booru）

- 优势：高质量原画、带精确 `width/height/score`、可按尺寸和评分筛
- 限制：标签必须是**罗马音**，且只用 `rating:s`（安全级）
- 实测：`togawa_sakiko` → 30 条 / 0.76s
- 没有罗马音时**明确报错**（`缺罗马音标签`），不静默跳过

## 4. 正确使用顺序

```
bb_ref_canon({character})                         ← 先拿基准（文字 + 官方图 + 罗马音）
   ↓ 看官方图，读 facts，确认发色/瞳色/服装
bb_ref_search({character, depth:"deep",
               romaji:<name_variants>})           ← 大面积搜（900+ 候选）
   ↓
bb_ref_collect({max_images:24})                   ← 下载 + 去重 + 编号对照表
   ↓ 逐格看图，对照 canon 基准：颜色/发型/服装对不上的剔除
bb_spec_save({spec})                              ← 把判读写进 spec 的 references
```

`bb_ref_search` 会自动复用上一次 `bb_ref_canon` 的 `name_variants` 作为 romaji，
所以通常不用手动传；换了角色或重载过插件就要重跑 `bb_ref_canon`。
