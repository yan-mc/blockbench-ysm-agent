# 13 · 分层能力（P3）：See-through 探测与安装

> 目标：给 AI「把立绘拆成部件」的能力，用于**分模块对照检查**建模结果。
> 产品决策：**T1 是标准档默认必做**（成本约 5–15 秒、模型 59MB）；**T2 是可选增强**（精细档推荐，需 ~7GB + 首次权重）。使用前先探测环境；非 N 卡明确不支持 T2。

---

## 1. 为什么必须分级

See-through 是 SDXL 级的扩散管线（LayerDiff 3D + Marigold 深度），真实门槛：

| 项 | 要求 | 来源 |
|---|---|---|
| GPU | **NVIDIA，Turing 及以后**（RTX 20xx+ / GTX 16xx） | NF4 量化需要 Turing 的指令 |
| 显存 | 512→约 5GB，768→约 5.5GB，**1024→约 7GB**，1280→约 9GB | 社区实测 |
| 磁盘 | ComfyUI + 依赖 + 权重约 **7GB** | 本文估算 |
| OS | 内置安装器只覆盖 **Windows** | 便携版只发 Windows |

插件要分发给别人，**不能假设所有人都有 N 卡**。所以定三级能力：

| 级别 | 依赖 | 能力 | 遮挡补全 |
|---|---|---|---|
| **T0** | 无 | 模型直接看立绘判断部件 | ❌ |
| **T1** | SAM2 ONNX（约 50MB，CPU 可跑） | 可见部件掩膜 | ❌（靠对称推断） |
| **T2** | ComfyUI + See-through（约 7GB） | **See-through 原始 24 层**（body 13 + head 11）+ 深度序 + PSD；插件按语义合并输出 **22 层**（见 [docs/16](16-T2完整分层调用.md)） | ✅ |

T1 是标准流程的默认步骤（见 `docs/17` §6）；T0 是降级兜底——环境不支持时可跳过 T1/T2，但**必须在报告写明原因**。

---

## 2. `bb_seg_probe`

只探测、不安装。返回：

```jsonc
{
  "platform": "win32",
  "gpus": [{ "name": "...", "vramGB": 12, "driver": "621.14", "legacy": false }],
  "disk": { "target": "~/.dsh-seethrough", "freeGB": 400 },
  "comfy": { "configured": true, "reachable": false },
  "tiers": {
    "t0": { "ok": true },
    "t1": { "ok": true },
    "t2": { "ok": true, "recommendedResolution": 1024, "estimateGB": 7, "reasons": [] }
  },
  "recommendedTier": "t2",
  "plan": { "canInstall": true, "steps": [ ... ] }
}
```

### 判定规则（可单测的纯函数 `computeTiers`）

| 条件 | 结果 |
|---|---|
| 无 `nvidia-smi` | T2 不可用，建议降到 T0 |
| 显卡属 Pascal 或更早（GTX 10xx/9xx/MX） | T2 不可用（NF4 不支持） |
| 显存 < 6GB | T2 不可用 |
| 剩余磁盘 < 12GB | T2 不可用 |
| 非 Windows | T2 不可用（安装器不覆盖） |
| 显存 ≥ 11GB | 推荐 1024 |
| 显存 ≥ 7GB | 推荐 768 |
| 其它 | 推荐 512 |

**不支持的组合会写进 `tiers.t2.reasons`**，而不是静默降级——用户要能看懂为什么不行。

## 3. 安装计划

`planInstall` 输出 7 步，每步带体积估算：

| 步骤 | 内容 | 体积 |
|---|---|---|
| `check` | 环境复核 | 0 |
| `download-comfy` | 下载 ComfyUI Windows 便携版（官方 releases 直链） | 1.8GB |
| `extract` | 解压到安装目录（自带 python_embeded，**不用单独装 Python**） | 0 |
| `install-node` | clone `ComfyUI-See-through` 到 `custom_nodes/` | 0.1GB |
| `install-deps` | `python_embeded\python.exe -m pip install -r requirements.txt`（diffusers/accelerate 等） | 2.0GB |
| `register` | 写入插件配置 `comfyUrl` / `segInstallDir` | 0 |
| `first-run` | **首次跑分层时**自动从 HuggingFace 拉权重 | 3.0GB |

关键设计：**权重不在安装时下载**，而是在第一次真正跑分层时由节点自动拉。
安装只占时间的是 ComfyUI 本体与 pip 依赖。

## 4. 实现状态（0.9.1）

| 项 | 状态 |
|---|---|
| 能力探测（`bb_seg_probe` + `computeTiers`） | ✅ 已实现，10 项单元测试 |
| 安装计划（`planInstall`） | ✅ 已实现 |
| T1 轻量分割（`bb_seg_lite`，SAM2.1 ONNX） | ✅ 已实现；首次自动下载 SAM2 约 59MB 到 `~/.dsh-blockbench-agent/sam2` |
| T2 安装执行器（`bb_seg_install`：下载/解压/pip） | ✅ 已实现；ComfyUI 便携版 + 依赖约 7GB 到 `~/.dsh-seethrough` |
| T2 完整分层调用（`bb_seg_run`，ComfyUI See-through） | ✅ 已实现并真实跑通（详见 [docs/16](16-T2完整分层调用.md)） |

> **分层按档位执行**（见 `docs/17` §6）：标准档 T1 必做、精细档 T1+T2；环境不支持时允许降级，但必须在报告说明原因。T0 是永久兜底，不是默认路线。
> T2 首次跑分层时还会由节点自动拉取权重（Marigold + LayerDiff 全套约 12.5GB），要有耐心。

**为什么先只做探测**：安装是 7GB 级、十几分钟的一次性动作，且强依赖本机环境。
在没有确认目标机器之前把它自动化，收益低风险高。探测能立刻回答"这台机器行不行"，
这是决定要不要投入的前提。

## 5. 后续接入点

分层结果接进 P2 的 spec：

- `references.layers[]`：每层对应一个部件，作为 `parts` 的独立依据
- 遮挡关系 → 直接决定骨骼层级（前发 vs 后发、袖子 vs 身体）
- 深度序 → 决定哪些面可以省掉

spec 结构不需要改动，只是 `references` 更丰富、`parts` 更有依据。
