# 21c · 头发与面部：169 个现代 YSM 语料的实测规格

> 数据源：`material/refmodels/ysm_decoded/` 169 个已解码 YSM 工程（`{name}/main.json`，
> bedrock 1.12 格式）。全部结论由 Python 直接读几何 + PIL 读贴图算出，
> 脚本在 `blockbench/work/hairface/`（`canon3.py / measure.py / spatial.py / bangs*.py /
> cover.py / botprofile.py / org.py / face.py / eyestack.py / shape2.py / tex.py / ladder_all.py`），
> 中间结果在 `blockbench/work/hairface/out/*.json`，可复算。
>
> **本文所有"单位"都是 MC 像素单位（1 单位 = 1 像素 = 1/16 格），且已按 7×7×7 的标准头归一化。**
> 归一化方法见 §0。

## 0. 先说口径：三个会让你算错的坑

这一节是全文最重要的部分。**如果不做这三件事，你会得到互相矛盾的数**——
上一轮任务里那句"hi3_elysia 有 871 个发布方块（占 33%）"就是踩了其中两个坑。

### 0.1 坑一：`ysmGlow*` 是复制出来的自发光层

82 / 169 个模型带 `ysmGlow` 前缀的骨骼，全语料共 **10643** 个这样的方块。
它们是**同一套几何的第二份拷贝**（整体沿 z 平移 +20 左右，用来做描边/发光），
不是新造型。例如 `gs_sh_yg`：

```
hair        26 块 (parent=headdd)
longhair    24 块
ysmGlowhair2     26 块 (parent=ysmGlowheaddd, pivot z=+19.69)   ← 平移副本
  ysmGlowlonghair2  24 块
```

`bronya_reason4.2` 的 glow 副本有 **865 块**，`爱莉希雅` **1483 块**。

### 0.2 坑二：整骨架副本（`X` 与 `X2` 同时存在）

3 个模型（`bronya_reason4.2`、`kamen_rider_tycoon`、`kamen_rider_tycoon_v2`）
把整套骨骼复制了一份，名字加后缀 `2`，位置抬高约 9.6（`Head` y=36.35 → `Head2` y=45.95）。
`bronya` 有 549 根骨骼 / 4947 块，其中**一半是副本**。

**所有"每模型"数字都必须先除以 `dup`（1 或 2）。** 本文的 `bronya` 数字均为**单份**。

### 0.3 坑三：`ClothHair*` 是挂在头发上的**饰品**，不是头发

`hi3_elysia` 的 `ClothHairBackLeftFlowerPart`(95) / `LingDangPart`(90) / `WoodPart`(81)
及右侧镜像，共 **560 块**，全部是花/铃铛/木簪——
它们的骨骼父级是 `BackLeftHair2` / `LeftSideHair2`（跟着头发甩），但几何是饰品。

### 0.4 口径对照表（同一个模型，三种数法差 2.8 倍）

| 口径 | 中位 | p75 | 最大 | hi3_elysia | 说明 |
|---|---|---|---|---|---|
| **A. 名字含 `hair` 的骨骼的直接方块** | 61 | 115 | **871** | 871（占全模型 33%） | 上一轮用的口径；会**同时**漏掉非 hair 命名的发骨、**多算** Glow 副本与 ClothHair 饰品 |
| **B. 结构发（子树归并、去饰品、去 Glow、除骨架副本）** | **114** | **185** | **386** | 311（12%） | **本文口径**，用于所有几何统计 |
| **C. 发饰（`ClothHair*`/花/缎带/铃/冠）** | 38 | 73 | 2139 | 805 | 单独统计 |

> `hi3_elysia` 的 871 = **311 结构发 + 560 发饰**。
> 它其实是"发饰冠军"，不是"头发冠军"——真正的头发冠军是 `bronya_reason4.2`（386/份）。

### 0.5 归一化：88% 的模型是标准尺度，2 个不是

方法：取头部骨骼（`head/headd` 系）里**体积最大的那个方块**的中位边长作为"头尺度 ref"，
`k = 7 / ref`。结果：

- `k` 中位 **1.000**，p10 **1.000**，p90 **1.077** —— **绝大多数模型直接用 1 单位 = 1 像素**
- 只有 2 个例外：`hi3_elysia` `k=0.343`（≈2.9 倍大，`ysm_height_scale: 0.26` 也印证）、
  `_goblin` `k=0.652`
- 19 个模型只有 `AllHead` 这种 3×3×3 标记块，按标准 7 头处理

**所以：跨模型比较厚度是合法的**，只有 `hi3_elysia` 必须换算。
它那个"厚度 2~7"的 `BackLeftHair2`，换算后是 **0.69 ~ 2.40，中位 0.69**。

## 1. 头发总预算

| 指标（单份，已归一化） | p25 | **中位** | p75 | p90 | max |
|---|---|---|---|---|---|
| 结构发方块数 | 80 | **114** | 185 | 231 | **386**（bronya） |
| 发骨骼数（含 0 块的容器骨） | 7 | **14** | 28 | 64 | 125 |
| 有方块的发骨（"发束骨"） | 6 | **12** | 24 | 55 | 107（tiamat） |
| 发占全模型比例 | 12% | **17.5%** | 26.7% | 34.9% | 60.5% |

**头发是模型的第二大件**：中位 17.5%，仅次于躯干+服装。
到 p90 就是 35% —— 也就是说"头发做得好"约等于"模型完成度的一半"。

分布（结构发块数）：

```
<30        1
30-60      9
60-120    60   ████████████████████████
120-250   73   █████████████████████████████
250-500   16
500+       0   ← 没有任何模型的结构发超过 500
```

> **实用结论：结构发超过 250 块就开始不值了。** 语料 p90 = 231，
> 再往上加的数量应该给发饰（§7）或表情（§10），而不是发丝。

## 2. 发束的组织方式

### 2.1 两种骨架粒度，泾渭分明

按「每根发束骨平均挂几块」统计（`hair / 有方块的发骨`）：

| cubes/骨 | 占比 | 特征 | 代表 |
|---|---|---|---|
| <3 | 11.4% | **样条骨**：1 块/骨，骨多块少 | `tiamat`（107 骨 / 236 块 / 59 根单块骨） |
| 3-6 | 16.5% | 样条骨（略粗） | `fgo_tiamat_b`（99 骨 / 265 块 / 62 根单块骨） |
| 6-10 | 17.1% | 混合 | `rs03`（25 骨 / 253 块） |
| 10-20 | 38.6% | **块状发片**：一根骨挂十几块 | `al_agnes`（24 骨 / 239 块） |
| 20+ | 16.5% | **整块大板**：一根骨挂几十块 | `v_suzuhara_lulu`（6 骨 / 215 块 = 35.8/骨） |

两个极端：

- **`jizi__2c90d16c1e70`**：6 根发骨扛 233 块 —— `hair` 一根骨 **150 块**、`headwear` 36、`hair4` 27。
  这是"一个骨一根大发束"的极致，代价是**头发完全不能飘**（只有 6 个旋转点）。
- **`tiamat__3e37c3c1dc80`**：107 根发骨扛 236 块，59 根是单块骨。
  这是"每一小撮都能单独动"的极致，代价是骨骼面板糊成一片。

**量化分界**：158 个模型里
- **31 个（20%）是样条骨派**：≥8 根单块发骨，且单块骨占比 ≥50%
- **94 个（59%）是纯块状派**：**一根单块骨都没有**

### 2.2 分段：一根发束由几段骨骼组成

对每条"发束链"（从端点到根）统计骨骼数：

| 链深（骨数） | 链数 | 占比 |
|---|---|---|
| 1 | 14 | 0.8% |
| **2** | 383 | **22.7%** |
| **3** | 388 | **23.0%** |
| **4** | 278 | **16.5%** |
| **5** | 202 | **12.0%** |
| 6 | 100 | 5.9% |
| 7 | 93 | 5.5% |
| 8 | 75 | 4.4% |
| 9-12 | 130 | 7.7% |
| >12 | 23 | 1.4% |

**中位 = 3 段，46% 落在 2-3 段，74% 在 2-5 段。**
6 段以上只占 **25%**，主要是双马尾/螺旋卷/长辫（其中 >12 段仅 1.4%）。

每根发束链的方块数：中位 **16.2**，p25 9.8，p75 27.1，p90 38.0。
（这条很关键：**一根发束 10-25 块是标准量**，不是 3 块也不是 100 块。）

### 2.3 命名：三种硬习惯

**(a) 方位 + 编号链**（主流，约 60% 的模型）

```
Hair ─┬─ FrontHair ─┬─ FrontMiddleHair
      │             ├─ FrontLeftHair
      │             └─ FrontRightHair
      ├─ SideHair  ─┬─ LeftSideHair1 / LeftSideHair2
      │             └─ RightSideHair1 / RightSideHair2
      └─ BackHair  ─┬─ BackMiddelHair
                    ├─ BackLeftHair  ─┬─ BackLeftHair1
                    │                 └─ BackLeftHair2 ─ BackLeftHair3
                    └─ BackRightHair ─┬─ BackRightHair1
                                      └─ BackRightHair2 ─ BackRightHair3
```

`hi3_elysia` 就是这么组织的：**14 根发束骨 / 311 块**，最大单束 `BackLeftHair2` 49 块。

**(b) 语义 + 编号**：`LongHair1..12`、`HairPart1..4`、`MaWei_A${n}`、`HairB_3`。
带 `x/y` 后缀的变体很常见（`LeftLongHair5x2`、`Right_BackHairK5y3`）——
这是作者手工复制之后批量改名的产物。

**(c) 完全无语义**：`bone92`（74 块）、`bone48`（17 块）、`ts`（21 块）、`S2`（60 块）。
`ba_asuma_toki` 最大的发束就叫 `bone92`，`doggo` 最大的叫 `S2`。
**28% 的模型有 ≥1 根无意义命名的发骨**（因为是从别的软件导入/复制来的）。

### 2.4 左右对称：**不做对称**

- 95 / 158 个模型有 `Left/Right` 命名
- 但**完全左右配对（≥80% 的骨都有对侧同名骨）的只有 8 个**
- 对称度中位 **0.37**（即只有 37% 的发骨有明确对侧）

原因很实际：作者先做一侧，另一侧**镜像之后手工改长短**，所以名字对不上、数量也不同。
例：`miku_2` 有 `RightLongHair11` 但 `LeftLongHair11` 只有 5 块；
`hsr_jingliu` 的 `Right_hair` 18 块 vs `Left_hair` 18 块（这个是对的）。

> **配方上：做左右对称骨架，但末端 1/3 的方块长度给 ±10~20% 的随机差。**
> 完全对称的头发看起来像假发。

### 2.5 发束收尖：61% 会收

对 808 条 ≥3 段的链，比较「端点段宽度 / 根部段宽度」：

| 指标 | 中位 | p25 | p75 |
|---|---|---|---|
| 端点宽 / 根部宽 | **0.59** | 0.35 | 1.00 |
| 端点长 / 根部长 | 0.75 | 0.50 | 1.04 |

- **61% 的链收尖（比值 <0.9）**
- **50% 收到 0.6 以下**（明显收尖）
- 39% 不收（大板发、齐发尾）

## 3. 发片尺寸：一条硬到不可思议的约定 —— **厚度 = 1.00**

### 3.1 厚度分布（22013 个发方块，归一化）

| 厚度区间 | 数量 | 占比 |
|---|---|---|
| 0.00-0.25 | 829 | 3.8% |
| 0.25-0.50 | 1035 | 4.7% |
| 0.50-0.75 | 2029 | 9.2% |
| 0.75-1.00 | 2518 | 11.4% |
| **1.00-1.25** | **11986** | **54.4%** |
| 1.25-1.50 | 991 | 4.5% |
| 1.50-1.75 | 457 | 2.1% |
| 1.75-2.00 | 281 | 1.3% |
| 2.00-2.25 | 1436 | 6.5% |
| 2.25-3.00 | 197 | 0.9% |
| 3.00-4.00 | 254 | 1.2% |

**分位数：中位 1.00 / p25 0.90 / p75 1.05 / p90 1.71 / p99 3.00**

- **66.2% 的发方块厚度落在 0.75-1.25；75.4% 落在 0.50-1.25**
- **49.2% 落在 1.00 ± 0.05** —— 一半的发方块厚度就是精确的 1.00
- **每个模型自己的中位厚度：p25=1.00、中位=1.00、p75=1.00** —— 几乎所有模型的发片就是 1 单位厚
- 第二峰在 **2.0-2.25（6.5%）**：这是"正面看是板、侧面看是 2 单位厚"的大发片（`hi3` 的 BackHair2 换算后 0.69，`v_suzuhara_lulu` 的整块发）

> 一句话：**发片厚度不是"1~1.5"，是 1.00。**
> 想做厚发就**并排三片 1.0**，不要做一片 3.0。

### 3.2 长度与宽度

| | p25 | 中位 | p75 | p90 | p99 |
|---|---|---|---|---|---|
| 长度（最长边） | 2.00 | **2.93** | 4.00 | 6.00 | 9.00 |
| 宽度（中间边） | 1.00 | **1.15** | 2.00 | 2.98 | — |
| 长/厚 比 | 2.0 | **2.9** | 4.0 | 6.0 | 9.0 |

**典型发片 = 1.0(厚) × 1.5~2.0(宽) × 3~4(长)** —— 这是"竖长条"，不是"斜片"。

### 3.3 朝向：62% 竖、22% 横、16% 纵深

| 长轴方向 | 方块数 | 占比 |
|---|---|---|
| **y（竖直）** | 13615 | **61.9%** |
| x（左右） | 4860 | 22.1% |
| z（前后） | 3599 | 16.4% |

薄轴方向：**x 53.1%**（片朝左右 — 侧发/披发）、z 29.9%（片朝前后 — 刘海/鬓角）、y 17.2%（横放的板）。

### 3.4 旋转：92% 的发方块都带旋转

每模型「带旋转的发方块比例」：中位 **0.92**，p25 0.81，p75 0.99，p90 1.00。

**"头发不旋转"在现代语料里不存在。** 连最偷懒的模型也有 80% 的发片转了角度。
这正是"折线拟合曲线"的实现（docs/19 §3.1 已述），本节只补量：
相邻片之间的角度差典型是 **3~7°**（`v_suzuhara_lulu` 的 `RightSideHair` 是 -6.7°×3 然后 -1.7°×2），
配合 1 单位厚度 + 交叠遮盖折角。

## 12. 脸型修形：26% 的模型把"头"切成镜像斜片

### 12.1 统计（165 个有头骨的模型）

| 指标 | 值 |
|---|---|
| 头骨里有 ≥1 个旋转方块 | **43 / 165 = 26%** |

| 头骨 100% 是旋转方块 | 9 / 165 = 5% |
| 头骨方块数中位 | 1（p75 2，最大 50） |
| **有旋转时，镜像配对率** | **中位 1.00**（p25 0.74）；30 个模型 ≥0.90 |
| 旋转主轴 | **x 19 / z 18 / y 6** |
| 斜片厚度中位 | 0.80（p25 0.50，p75 1.00） |
| 斜片长度中位 | 2.00 |

`docs/20` 说的"37% 多方块头 / 30% 头部含旋转"与这里 26% 一致（口径宽窄差）。

### 12.2 核心发现：**修形不是"削下巴"，是把整个头劈成镜像斜片**

有旋转的 43 个模型里，**30 个的旋转片是严格镜像成对的（mirror_frac ≥ 0.90）**。
也就是说做法是：

```
把头从中间劈开 → 左右两片各向外/向内转 10°~40° → 形成一个上宽下窄（或上窄下宽）的锥台
```

### 12.3 三个可直接抄的例子

#### 例 1：`lenna2.0.0__f19b1d3c82fe` —— 头劈成 3 片，±15°

```
Head (3 块，全部旋转)
  [3.45, 6.98, 7.29]  rot ( 0.0,  0.0,  15.0)   ← 右半头
  [3.45, 6.98, 7.29]  rot ( 0.0,  0.0, -15.0)   ← 左半头（镜像）
  [3.47, 6.98, 3.58]  rot ( 0.0,  0.0, -10.0)   ← 后脑补片
```

**一个 7×7×7 的头 → 两片 3.45 宽半头各转 ∓15°**，正面看收窄、侧面看有圆弧。
`gi_noelle_6.6` 用的是同一招（`[2.5, 5.0, 7.0]` rot `(0.2, 0, ±15)`）。

#### 例 2：`changchun__ed75c545ce9a` —— 下巴用 3 条斜板拟合圆弧

```
Head
  [0.94, 0.46, 7.94]  rot (0, 0, -65.0)   ← 最外侧，几乎平躺
  [1.15, 0.82, 7.94]  rot (0, 0, -27.5)   ← 中间
  [1.45, 0.78, 7.94]  rot (0, 0, -10.0)   ← 最内侧
```

**三片薄板（0.46-0.82 高）绕 z 轴 −65° / −27.5° / −10° 递进，拼出一条下颌弧线。**
这是"折线拟合"用在脸上的标准写法，比一整块 7×7 的下巴干净得多。

#### 例 3：`bronya_reason4.2` —— 两块 0.4 厚的"颧骨片"外扩

```
Head
  [6.4, 6.3, 6.1]  rot 无              ← 主 skull
  [1.4, 2.8, 0.4]  rot (-5.0, -39.7,  7.8)   ← 右颊
```

**只有 0.4 厚、2.8 高的小片，绕 y 轴 ∓39.7°** ——花 2 个方块把方脸颊变成有颧骨的弧面。

## 14. 头发贴图：色阶处理法

### 14.1 面积规划

| 项 | 目标 |
|---|---|
| 头发占已用贴图 | **10%**（p75 16%） |
| 头发占画布 | 3%（512 图 ≈ 80×80 px，1024 图 ≈ 180×180） |
| 每片发片的 UV 颗粒度 | 1 单位厚 → 1-2 px 宽的侧面；4 单位长 → 4-8 px |

**256 贴图就够画完 150 块结构发**（108/169 个模型用 256）。
想上渐变（流派 B）才需要 1024+。

### 14.2 流派 A：4 阶离散（推荐新手，81% 的模型）

```
阶 1  暗部   base × 0.65   ← 内侧、发根、被遮挡处   15-20% 面积
阶 2  主色   base          ← 主体                    50-60% 面积
阶 3  亮部   base × 1.25   ← 朝光面、发丝高点        20-25% 面积
阶 4  高光   base → 白     ← 1-2 px 的点/短线        2-5% 面积

可选 +1 阶：冷色反光（在暗部里加一点紫/蓝，如爱莉希雅的 #8C74C4）
```

**关键：阶与阶之间是硬边，不渐变。** 一条 1px 宽的深色缝沿着发流方向画。

`爱莉希雅` 的实测色阶（8 色，请直接参考这个比例）：

| 色 | 亮度 | 占比 |
|---|---|---|
| `#D4649C` 主色 | 128 | 30% |
| `#BC447C` 暗部 | 98 | 22% |
| `#FCFCFC` 高光白 | 252 | 17% |
| `#E494BC` 亮部 | 168 | 14% |
| `#ECECEC` 次高光 | 236 | 5% |
| `#BCBCCC` 冷高光 | 189 | 4% |
| `#8C74C4` 冷反光 | 127 | 2% |
| `#F4CCE4` 边缘光 | 214 | 2% |

### 14.3 流派 B：连续明度带（高级，19%）

```
底色：占 70-75% 面积，单一颜色
明度带：从底色向暗部延伸 19-40 级，每级差 1（8bit 亮度）
       每级至少 1px 宽 → 至少需要 40px 高的带
方向：顺着发流，越靠近发尾越暗
```

`hi3_elysia` 实测：

```
底色 #F494C4  72% (lum 172)
明度带 lum 155→173，19 级连续，每级 3000-7000 px
```

**注意：底色占 72% 意味着"渐变只发生在 28% 的面积上"。**
不要整片渐变——那会糊成一团。

### 14.4 发丝线（stripe）的密度

从 `hi3_elysia` 的 120 级亮度看，它的发丝线密度约每 2-4 px 一条（1280 贴图下）。
换算到 256 贴图就是每 1 px 一条——**即 256 图做不了细发丝，只能做 2-3 px 宽的色块**。
（这条是按亮度级数/贴图宽度推算的，不是直接量出来的网格间距。）

> **想画发丝线 → 贴图 ≥512。这条是硬门槛。**

### 14.5 UV 排版（省像素的关键）

- 发片是**瘦长条**（1×2×4），UV 展开后是 `1×4` + `2×4` + `1×2` 三类小矩形
- 把这些小矩形**按长度排成一列**（同一长度的放同一行），共享相邻边界
- 一片 4 长的发片只用 `1×4 × 2 + 2×4 × 2 + 1×2 × 2 = 8+16+4 = 28` 像素
- 150 片 × 28 px = 4200 px² ≈ 65×65 的方块 —— 这就是"256 贴图够用"的原因

### 14.6 透明与描边

- 发片**不用透明**（发像素里 alpha>200 的占比：**中位 1.000**，129 个模型里只有 1 个低于 0.5）。
  发梢用几何收尖，不用 alpha 抠
- 需要外描边时用 `ysmGlow*` 复制层（84 个模型这么做），不要画在贴图上
